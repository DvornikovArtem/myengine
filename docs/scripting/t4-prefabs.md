# T4: создание объектов из prefab-шаблонов

## Что сделано

Prefab — описание объекта в `assets/prefabs/<name>.prefab.json`. Компоненты используют тот же формат, что и сцена, включая `Script` и его `props`.

`PrefabLibrary` теперь загружает и кэширует шаблоны, создает копии, возвращает список имен, дает доступ к JSON для будущего редактора и сохраняет изменения. `world.spawn` подключен к Python через частный `ScriptApi`: публичные заголовки движка не зависят от Python / pybind11.

```python
import myengine as me

# В OnStart / OnUpdate / другом методе поведения:
coin = me.world.spawn("coin", me.Vec3(2, 1, 3))
coin.transform.rotation = me.Vec3(0, 45, 0)

# Без позиции берется Transform.position корня из файла:
another_coin = me.world.spawn("coin")
```

Спавн происходит сразу на главном потоке: объект и компоненты доступны после возврата `spawn`. Его поведения создаются и получают `OnStart` на следующем шаге ScriptSystem. Существующие поведения и ссылки на другие объекты не сбрасываются: загрузка prefab не публикует `SceneLoadedEvent`.

## Как создается копия

1. Загружаем JSON (повторный спавн использует кэш без чтения диска).
2. Проверяем структуру и компоненты во временном мире: положительные локальные ID, отсутствие дубликатов, один корень, существующие родители, отсутствие циклов.
3. Создаем новые ID и таблицу `локальный ID → новый ID`.
4. Загружаем все компоненты через `DeserializeEntity`, затем восстанавливаем родительские связи через `SetParent`. Поле `children` не копируется со старыми ID: оно восстанавливается по `parent`.
5. Если передана позиция, меняем только `Transform.position` корня; локальные позиции детей остаются прежними. При отсутствии Transform создаем его.
6. Возвращаем `Entity` корня. Копии не разделяют `props` или компоненты друг с другом и с шаблоном.

Неверный JSON, ID, иерархия, тип данных компонента, отсутствующий файл или небезопасное имя не оставляют в мире частично созданные сущности. C++ возвращает `kInvalidEntity` и сохраняет причину в `GetLastError`; Python получает `RuntimeError`, который обычный `SafeCall` обрабатывает как ошибку поведения. Нечисловая позиция (NaN / бесконечность) из Python дает `ValueError`.

Имена задаются без пути и расширения: `"coin"`, а не `"../coin"` или `"coin.prefab.json"`. Загрузка и сохранение ограничены настроенным каталогом; ссылки на файл вне него отклоняются.

## Кэш, сохранение и жизненный цикл

Используется `FileWatcher` Артема: проверка времени изменения и чтение измененных файлов выполняются в Streaming job, а сброс кэша — на главном потоке через `Poll`. WatchDirectory принимает `.json`; callback дополнительно проверяет суффикс `.prefab.json` и каталог.

При изменении файла следующие копии используют новые данные; существующие копии не меняются. Удаление файла сбрасывает его кэш, возвращенный после исправления файл снова загружается. Ошибочный новый файл не порождает объекты из старого кэша после доставки изменения. В Windows обновляются также записи, загруженные под другим регистром имени (`coin` / `COIN`).

Поправлен один граничный случай `FileWatcher`: явный `RequestFullRescan` работает и на самом первом сканировании. Иначе изменение между первой загрузкой шаблона и установкой начального состояния вотчера могло быть пропущено. Скан без явного запроса по-прежнему только устанавливает исходное состояние.

`GetPrefabJson` возвращает указатель на запись кэша для правки `props`. Его нельзя хранить между кадрами: внешний файл может измениться, и `Poll` удалит запись. `SavePrefab` сначала проверяет JSON, пишет во временный соседний файл и заменяет оригинал только после успешной записи. Неудача не обрезает существующий файл. В [T8](t8-prefab-editor.md) редактор хранит отдельный черновик и передаёт его в `SavePrefab(name, draft)`; после сохранения или явного `ReloadPrefab` указатели кэша также нужно получить заново.

Application выбирает исходный `assets/prefabs`, а если он отсутствует — копию рядом с exe. Перед остановкой job system вызывает `PrefabLibrary::Shutdown`, который дожидается фонового сканирования. `Poll` вызывается из ScriptSystem и в Edit, и в Play.

## Подготовленные шаблоны

- `coin`: золотая сфера, trigger-коллайдер, `coin.Coin` с `spin_speed` / `score_value`; дочерний объект `CoinGlow` проверяет иерархию.
- `chaser`: ящик с Rigidbody и box-коллайдером; `chaser.Chaser` с полями скорости, штрафа и имени цели.
- `firework`: небольшой ящик с физикой; `firework.Firework` с временем жизни.
- `gold.material.json`: по формату существующих материалов, золотой tint, имеющиеся shader и texture.

Игровые модули `coin.py`, `chaser.py`, `firework.py` относятся к отдельной [задаче T6](t6-gameplay.md): там реализованы подбор монет, погоня и самоуничтожение. T4 отвечает за создание сущностей и компонентов из шаблонов. Панель Prefabs добавлена отдельно в [T8](t8-prefab-editor.md). Исходные сцены не меняются.

## Проверка в PowerShell

Команды вводить по одной; перед сборкой закрыть запущенный движок.

```powershell
Set-Location "C:\Users\ivanm\source\repos\myengine"
```

```powershell
cmake -S . -B build -DMYENGINE_BUILD_TESTS=ON
```

```powershell
cmake --build build --config Debug --target myengine_prefab_tests myengine_script_api_tests
```

```powershell
& ".\build\tests\Debug\myengine_prefab_tests.exe"
```

```powershell
& ".\build\tests\Debug\myengine_script_api_tests.exe"
```

Для RelWithDebInfo заменить `Debug` в команде сборки и путях запуска на `RelWithDebInfo`.

`prefab_library` проверяет независимые копии, новые ID, трехуровневую иерархию с корнем не первым в файле, позицию, `props`, ошибочные данные, изменение/удаление/восстановление файлов, сохранение и отказ записи в read-only файл. Проверяет также реальные три шаблона и пути ресурсов материала gold. `script_api` дополнительно проверяет `world.spawn` из OnUpdate, отложенный старт поведения, работу `props`, отсутствие сброса старых ссылок и удаление поддерева prefab.

Тесты работают с временными копиями в каталоге с кириллицей; реальные assets читаются, но не переписываются. При ошибке путь к сохраненному логу выводится в терминал.
