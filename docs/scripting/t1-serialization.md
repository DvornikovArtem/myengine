# T1: данные скриптов и загрузка сцены

## Что готово

- `ScriptComponent` хранит только данные сцены: `module`, `className`, `props`. Объектов Python в нём нет; ими будет владеть `ScriptSystem` в T3.
- `SerializeEntity` и `DeserializeEntity` используют прежний формат компонентов, плюс ключ `Script`. Старые сцены без скриптов по-прежнему загружаются.
- `DeserializeEntity` заполняет уже созданную сущность, не использует сохранённый `id` и не устанавливает родителя. Связи `Hierarchy` восстанавливает вызывающий код после создания всех сущностей. Это позволяет T4 переназначить локальные id prefab-а.
- Полная сцена сначала разбирается во временный `World`. Только после успеха заменяются сущности и компоненты; зарегистрированные системы остаются в живом мире. Ошибка в данных не уничтожает предыдущую сцену.
- `scene::SceneLoadedEvent` объявлен в `myengine/scene/SceneEvents.h`, содержит `World* world`. Публикуется после успешной загрузки файла, восстановления снимка Play и пересоздания встроенной демо-сцены. Подписка `ScriptSystem` и `ResetInstances` остаются задачей T3.
- `--scene <path>` выбирает файл для загрузки, ручного сохранения и сохранения при выходе. Пути разбираются как UTF-16, включая пробелы и кириллицу. Относительный путь ищется от текущего каталога, затем от корня исходников и каталога exe. Без аргумента сохраняется прежний выбор `benchmark.json`.
- Если явно выбранная сцена отсутствует или повреждена, запуск завершается с ошибкой в логе; файл не заменяется встроенной демо-сценой.
- Исправлен `World::SetParent`: существующий `HierarchyComponent` больше не пересоздаётся, поэтому не теряются соседние дети и вложенные связи.

## Формат Script

```json
"Script": {
  "scripts": [
    {
      "module": "coin",
      "class": "Coin",
      "props": { "spin_speed": 120.0, "score_value": 1 }
    }
  ]
}
```

Если `props` отсутствует, загружается пустой объект. Значения сохраняются без применения к Python: проверка полей класса и вызовы поведения будут в T3. Несколько скриптов на одной сущности сохраняют свой порядок.

`assets/scenes/scripting_demo.json` содержит камеру, управляемый ящик, пол, сущности `GameManager`, `CoinSpawner`, `EnemySpawner` и тестовую монету с `props`. Модули указаны по плану механики; сами Python-файлы ещё предстоит написать в T6. На этапе T1 эта сцена проверяет данные, а не готовую игровую механику.

## Проверка в PowerShell

Команды выполняются из корня репозитория. Для второй конфигурации заменить `Debug` на `RelWithDebInfo`.

```powershell
.\setup.bat
cmake -S . -B build -DMYENGINE_BUILD_TESTS=ON
cmake --build build --config Debug --target myengine myengine_scene_serialization myengine_job_stress myengine_scripting_smoke myengine_controls_tests
ctest --test-dir build -C Debug --output-on-failure
& ".\build\tests\Debug\myengine_scripting_smoke.exe"
```

`scene_serialization` проверяет компоненты, несколько скриптов, `props`, старую сцену, иерархию, восстановление снимка, события, ошибки загрузки и сохранение зарегистрированных систем.

`control_systems` проверяет движение персонажа с места по мировым осям при разных поворотах камеры и частотах кадров, вертикальное перемещение камеры и сброс ввода при потере фокуса.

`myengine_scripting_smoke` — отдельная интеграционная проверка с DX12-окном (поэтому не входит в CTest). Она запускает приложение на временной копии сцены, выполняет 120 кадров, выходит штатно и проверяет, что изменения `props` во время Play не попали в сохранённую сцену. Исходные сцены не перезаписываются.

Лог этой проверки находится рядом с тестовым exe:

```powershell
Get-Content ".\build\tests\Debug\logs\myengine.log" | Select-String "Python|ScriptRuntime|SceneSerializer"
```

В нём должны быть проверка `Vec3(2, 3, 4)`, изолированный `sys.path`, загрузка/сохранение временной сцены и `ScriptRuntime: shut down`.

Запуск самого движка с новой сценой:

```powershell
& ".\build\app\Debug\myengine.exe" --scene "assets/scenes/scripting_demo.json"
```

При выходе файл выбранной сцены будет сохранён. Как и раньше, если приложение закрыто в Play, сначала восстанавливается снимок начала Play.

В Play без зажатой ПКМ персонаж управляется независимо от камеры: W/S — по мировой оси Z, A/D — по X, Space — прыжок. С зажатой ПКМ управляется камера; Q опускает её, E поднимает по мировой оси Y.

В сборке остаются существовавшие до T1 предупреждения стороннего ImGuizmo и отсутствующих PDB для DirectXTK/DirectXTex; изменения T1 не добавляют новых предупреждений.
