# T6: механика «Сбор монет под охраной»

## В чём задача

T0–T5 и T7 подготовили инструменты: Python внутри движка, доступ к сущностям, жизненный цикл, prefab, hot reload и инспектор. T6 использует их для маленькой игры: собрать нужное количество монет за время раунда, избегая врагов.

Все правила, счёт, таймеры, волны и реакции на события написаны на Python. C++ по-прежнему отвечает за ввод, физику, рендер и безопасное исполнение скриптов. Управление игроком использует существующий `PlayerController`; оно не переписано и не зависит от направления камеры.

Используются настоящие prefab из T4: `coin`, `chaser`, `firework`. В `chaser.prefab.json` добавлены поля `detection_radius` и `catch_radius`; остальные прежние значения сохранены. Игровые настройки лежат в `props` сцены и шаблонов, а не только в коде.

## Как устроен раунд

В готовой сцене цель — 10 очков за 60 секунд. Сначала появляются 6 монет. Каждая даёт 1 очко; после подбора новая монета появляется с интервалом 1.5 секунды, пока не достигнут лимит. Монеты размещаются вокруг спавнера по воспроизводимой схеме, внутри пола.

Первый враг появляется через 4 секунды. Каждые 10 секунд приходит новая волна: 1, затем 2, затем 3 новых врага и так далее, но одновременно не больше 8. Скорость врага — 3; скорость игрока берётся из существующего `PlayerController`.

Враг ищет `Controlled_1` и записывает горизонтальную скорость в Rigidbody. Гравитация и столкновения остаются у физики. Если игрок близко (`catch_radius`) или произошёл контакт, враг отправляет менеджеру `hit_player`. Менеджер снимает очко, возвращает игрока на старт и обнуляет его скорость. Общий cooldown 1.5 секунды не позволяет нескольким врагам сразу списать очки многократно. Падение ниже `fall_height` тоже возвращает игрока со штрафом.

При достижении цели менеджер переходит в `won`, останавливает горизонтальное движение врагов и создаёт 20 физических ящиков-частиц из `firework`. Их начальные скорости направлены в разные стороны и вверх. Скрипт `Firework` удаляет каждый через 2 секунды. При окончании времени или удалении игрока раунд переходит в `lost`. В завершённом раунде очки не начисляются, новые монеты и волны не создаются.

R начинает новый раунд без перезапуска движка: счёт, таймер, cooldown и волны сбрасываются; старые объекты спавнеров и салют удаляются, игрок возвращается на старт. Новые поведения prefab начинают работать на следующем шаге скриптов, как предусмотрено T3.

R сбрасывает игровой раунд, а не загружает весь файл сцены. Вручную размещённые объекты старой `scripting_demo.json`, например `CoinPreview`, не восстанавливаются после подбора по R. Для возврата **всей** сцены используется Stop → Play. В новой сцене T6 все монеты создаёт спавнер, поэтому каждый рестарт имеет одинаковый состав раунда.

## Почему ссылки и reload безопасны

Спавнеры хранят `Entity`-handles и проверяют `alive`, прежде чем использовать их. Удаление монеты удаляет также дочерний `CoinGlow`; старый handle становится мёртвым. Повторные события не дают повторные очки: монета сразу ставит `collected`, а само удаление выполняется в конце шага.

У каждого спавнера свой префикс имён, содержащий ID владельца. Очистка удаляет только его объекты. При L1 reload новый спавнер сначала находит свои старые корни, затем очищает и создаёт их заново: бесхозные копии не накапливаются. При L2 сохраняются список handles, таймеры и номер волны.

При обращении к менеджеру его класс импортируется внутри метода, чтобы после reload не использовать старый Python-класс. В L2 менеджер сохраняет счёт, оставшееся время и состояние раунда; `OnReload` обновляет HUD. В L1 состояния начинают работать заново.

## Как запустить в PowerShell

Перед сборкой закрыть работающий движок. Каждую команду вводить отдельно; установленный Python не нужен.

```powershell
cmake --build "C:\Users\ivanm\source\repos\myengine\build" --config RelWithDebInfo --target myengine
```

```powershell
Set-Location "C:\Users\ivanm\source\repos\myengine\build\app\RelWithDebInfo"
```

```powershell
.\myengine.exe --scene "C:\Users\ivanm\source\repos\myengine\assets\scenes\coin_guard_demo.json"
```

Движок сейчас запускается в Play. В viewport должны быть игрок-ящик, пол и золотые монеты; HUD показывает счёт и время. Если переключён Edit — нажать Play. Управление: WASD — игрок, Space — прыжок, R — новый раунд. Навигация камеры остаётся прежней, включая Q/E по вертикали.

Для смены баланса нажать Stop, выбрать `GameManager`, `CoinSpawner` или `EnemySpawner` в иерархии и изменить Script-поля в инспекторе, затем Play. Например, поставить `target_score=3` или увеличить `round_duration`. Параметры самой монеты и врага находятся в их prefab; редактор шаблонов относится к T8, здесь их JSON можно редактировать вручную. Изменения prefab применяются к следующим копиям.

Для демонстрации изменения **правила** в Play можно заменить в `coin.py`:

```python
me.send(self.manager_name, "add_score", self.score_value)
```

на:

```python
me.send(self.manager_name, "add_score", self.score_value * 2)
```

Сохранить файл, дождаться вотчера или нажать Reload scripts / F5. В L2 счёт и таймер не сбросятся, а следующие монеты будут давать двойные очки. После демонстрации вернуть исходную строку.

## Автотесты

[GameplayTests.cpp](../../tests/scripting/GameplayTests.cpp) запускает настоящий встроенный Python, ScriptSystem, PrefabLibrary и физику. Проверки игровых правил находятся в [gameplay_checks.py](../../tests/scripting/gameplay_checks.py). Скрипты и prefab копируются во временный каталог с кириллицей; изменения правила для reload выполняются только в копии, не в исходных assets.

Проверяются поля из `props`, отложенный старт, вращение, подбор через настоящую физику, игнорирование чужих и повторных событий, удаление дочернего glow, безопасный respawn, рост и лимит волн, движение врага, поимка по расстоянию/контакту, cooldown, падение и пропавший игрок, победа/поражение, время жизни салюта, 20 рестартов без накопления сущностей, L1/L2 reload с изменением правила и 5 циклов Play/Stop.

Используется временная копия сцены; для короткой проверки цель снижена до одного очка, первая волна включена сразу. Оконный тест не включён в headless CTest.
