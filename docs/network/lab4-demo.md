# ЛР4 «Сеть»: сценарий показа

Архитектура описана в `docs/network/architecture.md`. Здесь — что запускать и что нажимать на приёмке. Каждый шаг привязан к пункту ТЗ.

## Запуск

Сервер и два клиента запускаются на одной машине, в трёх окнах. Команды даны для пакета `RocketArena.exe`; в сборке из репозитория то же самое — `build\app\RelWithDebInfo\myengine.exe --game …`.

```
RocketArena.exe --rl-host 47777 --rl-mode 2 --net-sim latency=40,jitter=10,loss=5          :: окно 1 — сервер (хост) и его игрок
RocketArena.exe --rl-join 127.0.0.1:47777 --net-sim latency=40,jitter=10,loss=5             :: окно 2 — клиент
RocketArena.exe --rl-join 127.0.0.1:47777                                                   :: окно 3 — второй клиент (допфича)
```

- `--net-sim` — эмуляция сети на отправке этого окна: задержка, джиттер и потери в процентах (ещё есть `dup=` — дубли). Ключ можно не задавать.
- Хост открывает лобби, кнопка **Start match** начинает матч, пустые места занимают боты.
- Лог каждого окна: `%LOCALAPPDATA%\RocketArena\logs\myengine.log` (в сборке из репозитория — `build\app\RelWithDebInfo\logs\myengine.log`).

## Клавиши (в окне матча)

| Клавиша | Что делает |
| --- | --- |
| **F2** | сетевая панель: RTT, трафик в обе стороны, повторы, потери снимков, RPC, плохие сообщения |
| **1–4** | RPC `QuickChat`: фраза уходит серверу; после его `OK` она появляется в ленте у всех игроков |
| **F6** | RPC несуществующего метода 999 → `UNKNOWN METHOD` |
| **F7** | `QuickChat` с фразой 200 → `BAD ARGUMENTS` |
| **F8** (клиент) | RPC `StartMatch`: гостю нельзя → `NOT ALLOWED` |
| **F9** (клиент) | шлёт серверу 4 битых сообщения: неизвестный тип и три обрезанных. Сервер считает их, пишет в лог и продолжает игру |

Результат каждого вызова появляется строкой `RPC <метод> #<номер>: <статус> … - <причина>` и держится 8 с.

## Живой критерий ТЗ, по шагам

1. **Подключить клиент к серверу.** Окно 2 попадает в лобби хоста, хост жмёт Start match.
2. **Управлять сущностями.** Обе машины ездят, мяч общий.
   - Сервер владеет матчем, клиент шлёт только ввод.
   - Своя машина клиента отзывается сразу — это предсказание. Поправки сервера видны в панели F2 (`rollbacks`).
3. **Вызвать RPC и увидеть результат.** В окне 2 нажать `2`.
   - В окне 2 появляется строка `RPC QuickChat #1: OK in 90 ms - 'What a save!' sent to every player`.
   - В ленте обоих окон — `<игрок>: What a save!`.
4. **Недопустимый вызов — контролируемый отказ.** В окне 2:
   - `F6` → `UNKNOWN METHOD`;
   - `F7` → `BAD ARGUMENTS - there is no phrase 200`;
   - `F8` → `NOT ALLOWED - only the host starts the match`;
   - две фразы подряд → `TOO FAST`.

   Матч продолжается. В логе сервера на каждый вызов есть строка `net rpc: … from peer N: …`.
5. **Некорректные сообщения.** В окне 2 нажать `F9`.
   - На панели сервера (F2): `bad messages: unknown 1 broken 3`, ниже последняя причина.
   - В логе сервера: `net host: unknown message type 238 …` и `a broken Input / RpcCall / CarSelect …`.
6. **Штатное отключение и повторное подключение.**
   - Окно 2: `Esc` → Leave match. Сервер отдаёт слот боту, на его панели `guests 0`.
   - Окно 2: Play → Join (IP `127.0.0.1:47777`). Клиент входит в идущий матч на место бота: получает состояние матча кусками и догоняет.
7. **Потеря связи и повторное подключение.**
   - Окно 2 закрыть через Диспетчер задач («Снять задачу»), без прощального пакета.
   - Через 5 с сервер сам отдаёт слот боту, «призрака» нет.
   - Запустить окно 2 командой из раздела «Запуск» — клиент снова в матче.
8. **Сервер продолжает работать, состояние согласовано.** У всех окон одинаковые счёт и часы. Хэши состояний сверяются в каждом снимке: `hash mismatches` в тестах равно 0.

## Счётчики (Измеримость)

Панель F2:

- `RTT` и трафик `up / down kB/s (packets/s)` за последнюю секунду;
- всего пакетов и байт, `resent` — повторы надёжных сообщений в процентах;
- `dropped` — чужие датаграммы;
- у клиента — `snapshots lost` в процентах. Это потери ненадёжного потока, при `loss=5` около 5 %;
- `RPC calls / ok / refused / timeouts / waiting`;
- `bad messages`;
- у сервера — `connections` и `guests`.

## Стабильность

| Проверка | Как показать |
| --- | --- |
| Повторы сценария | шаги 3–7 несколько раз подряд |
| Ошибочный ввод | F6–F9; неверный адрес `--rl-join 127.0.0.1:1` |
| Недоступный сервис | `--rl-join` без запущенного сервера → через 10 с «No answer from the host.» и возврат в меню |
| Повторный вход в сцену | Leave match → Play → Host или Join, несколько раз |
| Длительная сессия | матч 5 минут. Счётчики `waiting 0`, а `connections` равно числу гостей |
| Корректный выход | закрыть окна. Сервер и клиенты завершаются без падения, в логе нет ошибок |

## Допфичи (п. 5 ТЗ)

| Допфича | Баллы | Как показать |
| --- | --- | --- |
| client-side prediction с server reconciliation | 3 | `--net-sim latency=100` у обоих окон. Своя машина отзывается без задержки; на панели растут `rollbacks`, а `hard corrections` равно 0 |
| второй и последующие клиенты | 1 | окно 3. Каждый видит машины и фразы другого. Выход и возврат одного не мешает остальным |
| версионирование протокола с отказом | 2 | `RocketArena.exe --rl-join 127.0.0.1:47777 --net-protocol 4`. На экране «The host has another version of the game…», в логе сервера `its protocol is 4, ours is 5` |
| эмуляция сетевых условий | 2 | `--net-sim latency=…,jitter=…,loss=…`. При потерях RPC доходит повтором, а без сервера кончается `TIMEOUT` через 3 с. Панель показывает RTT, потери и частоту отправки и получения |

Лимит допфич — 6 баллов. Если какую-то не засчитают, есть запасная.
