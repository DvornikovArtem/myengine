# Сеть: архитектура ЛР4 (вариант Б)

ЛР4 «Подсистема на выбор». Выбран **вариант Б. Сеть**. Сетевой код уже работал в онлайне Rocket League (`docs/game/rl-online.md`, раздел 7).
В ЛР4 он стал подсистемой движка: транспорт вынесен из библиотеки игры в `engine/`, добавлены RPC с ответом, диагностика плохих
сообщений и счётчики трафика. Сценарий показа — в `docs/network/lab4-demo.md`.

## 1. Граница подсистемы

```
игра (engine/src/ecs/systems/RlGameSystem.cpp, game/rl/src/RlNetHost.cpp, RlNetClient.cpp)
        │  INetTransport, RpcServer / RpcClient, NetBadMessages, NetTransportStats, SetNetLogSink
        ▼
myengine_net  (engine/include/myengine/net, engine/src/net)  — своя библиотека, без DX12, ImGui и ECS
        │  IDatagramLink
        ▼
UdpLink (winsock) | LoopbackLink (тесты) | SimLink (задержка, джиттер, потери, дубли)
```

- **`myengine_net`** — отдельная статическая библиотека движка (`engine/CMakeLists.txt`). Её линкует библиотека игры `myengine_rl`, а через неё и `myengine_engine`. Отдельной она сделана, чтобы библиотека игры могла пользоваться сетью без остального движка (рендера, ECS).
- **Middleware нет.** UDP-сокеты Windows (winsock) — единственное, что берётся у системы. Рукопожатие, надёжная доставка, RPC и сериализация написаны нами. Steam-транспорт (`game/rl/src/net/steam`, собирается только с SDK) — вторая реализация того же `INetTransport`.
- Игровой код не трогает сокеты и байты пакетов. Хост и клиент Rocket League знают только `INetTransport` (послать сообщение, получить события). Новые RPC-методы игра регистрирует в `RpcServer`.
- Старые заголовки `game/rl/include/rl/net/Net*.h` оставлены как переходники: код игры по-прежнему пишет `rl::net::…`, имена приходят из `myengine::net`.

| Файл | Что в нём |
| --- | --- |
| `NetTransport.h` | `INetTransport`: `Listen`, `Connect`, `Send(reliable)`, `Poll(now) → события`, `Disconnect`, `Close`, `RoundTripSeconds`, `Stats`; `NetSimParams` (`--net-sim`) |
| `NetLink.h/.cpp` | датаграммы: `UdpLink`, `LoopbackHub`/`LoopbackLink`, `SimLink` |
| `NetReliable.h/.cpp` | транспорт поверх датаграмм: рукопожатие с токеном, надёжные упорядоченные сообщения (номер, ack-маска, повтор по RTO), keepalive, RTT, таймаут 5 с, счётчики |
| `NetRpc.h/.cpp` | `RpcServer` (методы по номеру, проверка, ответ), `RpcClient` (номера запросов, таймаут 3 с, закрытие), `ByteWriter`/`ByteReader` |
| `NetLog.h/.cpp` | `SetNetLogSink` (движок направляет его в `myengine.log`), `NetBadMessages` (счёт и лог неизвестных и битых сообщений) |

## 2. Владение данными и авторитетность

- **Сервер (хост) — владелец матча.** `RlNetHost` владеет `RlMatch`, шагает 120 Гц и рассылает снимки 60 Гц: тик, машины, мяч, площадки буста, счёт, часы, статистика, хэш состояния и использованные вводы.
- **Клиент владеет только своим вводом.** Он шлёт ввод (`Input`), а не состояние. Своя копия матча у клиента — предсказание: при расхождении с сервером клиент откатывается к его снимку и пересчитывает (`docs/game/rl-online.md` 7.5).
- **Чьё что.** Транспорт (`unique_ptr<INetTransport>`) принадлежит `RlGameSystem`. Хост и клиент держат на него ссылку и создаются после него, а удаляются раньше (`StopOnline`).
- **RPC.** Хост проверяет права вызывающего и аргументы. Клиент узнаёт результат только из ответа хоста.

## 3. Жизненный цикл

| Этап | Где | Что происходит |
| --- | --- | --- |
| Инициализация | `Application::Initialize` | `SetNetLogSink` направляет диагностику сети в лог движка |
| Создание | `RlGameSystem::StartNetwork` / `StartOnline` | `MakeUdpTransport(--net-sim)`, затем `RlNetHost::Listen` или `RlNetClient::Connect` |
| Обновление | каждый кадр `NetStep` | `Update(now)`: `Poll` транспорта, разбор сообщений, тики матча, снимки; `NetFrame`: клавиши, результаты RPC, скорость трафика |
| Подключение | `NetReliable` | Connect → Accept с токеном → `Join` (версия, хэши настроек и машин) → `Welcome` или `Reject` с причиной |
| Штатный выход | `RlNetClient::Close` / `LeaveMatch` | `Disconnect` (три пакета bye), хост отдаёт слот боту (`SlotMask`) |
| Потеря связи | `NetReliable::Poll` | 5 с без пакетов → `Disconnected(Timeout)`; у клиента все ждущие RPC завершаются `Closed`, у хоста слот уходит боту |
| Повторный вход | `RlNetHost::OnJoin` → `LateJoin` | новый клиент получает слот бота и состояние матча кусками (`StateChunk`), догоняет и играет |
| Завершение | `StopMatchState` → `StopOnline` | хост и клиент удаляются раньше транспорта, затем `transport->Close()` |
| Выход из приложения | `Application::Shutdown` | `SetNetLogSink({})` до удаления логгера |

## 4. Сообщения

Каждое сообщение — первый байт типа (`rl::RlMsg`) и поля в little endian фиксированной ширины. Позиции, скорости и вводы квантованы (`RlNetProtocol.cpp`), сырых дампов структур нет. Декодер читает через проверку границ и отвергает сообщение, если оно короче, длиннее или с полем вне диапазона.

| Тип | Направление | Доставка | Содержимое |
| --- | --- | --- | --- |
| `Join` = 1 | клиент → хост | надёжная | версия протокола, хэши настроек и машин, машина, имя |
| `Welcome` / `Reject` = 2 / 3 | хост → клиент | надёжная | слот, режим, сид, маска людей / причина отказа |
| `Input` = 4 | клиент → хост | ненадёжная | вводы последних ≤ 8 тиков (5 байт на тик) |
| `Snapshot` = 5 | хост → клиенты | ненадёжная | тик, мир (квантованный), площадки, хэш, использованные вводы |
| `Event` = 6 | хост → клиенты | надёжная | старт, смена слотов, гол, сейв, демолиш, конец, **QuickChat** |
| `StateChunk`, `InputRequest`, `InputHistory` = 7–9 | | надёжная | вход в идущий матч |
| `Names`, `CarSelect` = 10, 11 | | надёжная | лобби |
| **`RpcCall`** = 12 | клиент → хост | надёжная | `[номер запроса u32][метод u16][длина аргументов u16][аргументы]` |
| **`RpcReply`** = 13 | хост → клиент | надёжная | `[номер запроса u32][метод u16][статус u8][длина текста u8][текст]` |

Версия протокола `kNetProtocolVersion = 5`: в ней добавились `RpcCall`, `RpcReply` и событие `QuickChat`. Клиент другой версии получает `Reject(Version)`, а хост пишет в лог обе версии.

## 5. RPC

Методы хоста (`rl::RlRpcMethod`):

| Метод | Аргументы | Проверки хоста | Результат |
| --- | --- | --- | --- |
| `QuickChat` = 1 | `u8` номер фразы | ровно 1 байт, номер < 8, у вызывающего есть слот, не чаще 1 раза в секунду | `OK`, событие `QuickChat` всем (лента HUD у каждого игрока) |
| `StartMatch` = 2 | нет | только игрок хоста, матч ещё не начат | гостю — `NOT ALLOWED` |

Статусы `RpcStatus`: `OK`, `UNKNOWN METHOD`, `BAD ARGUMENTS`, `NOT ALLOWED`, `TOO FAST`. На клиенте к ним добавляются ещё два: `TIMEOUT` — ответа нет 3 с; `CONNECTION CLOSED` — соединение кончилось раньше ответа или его не было. Каждый вызов даёт ровно один результат, молча вызов не теряется. Вызовы идут надёжным каналом, поэтому при потерях `--net-sim loss=…` доходят повтором. Игрок хоста вызывает те же методы без сети: байты вызова передаются серверу напрямую, проверки те же.

## 6. Диагностика

- **Неизвестный тип сообщения** и **сообщение, которое не разобралось**, считаются в `NetBadMessages` (`unknown`, `malformed`) и пишутся в лог: первые 5 каждого вида, дальше каждое сотое. Хост продолжает работать, состояние не трогается.
- **Неверный RPC** получает ответ с причиной и строку в логе (`net rpc: #999 #4 from peer 2: UNKNOWN METHOD - …`).
- **Сервис недоступен**: если хост не отвечает, через 10 с подключение кончается `Disconnected(Timeout)` с понятной ошибкой на экране. Если версия, настройки или машины другие, приходит `Reject` с причиной.
- **Транспорт** отбрасывает чужие датаграммы: без магического байта, от неизвестного адреса, со старым токеном. Они считаются в `droppedPackets`.

## 7. Счётчики

| Счётчик | Где | Показ |
| --- | --- | --- |
| RTT | `INetTransport::RoundTripSeconds` | панель F2, пинг в HUD |
| пакеты и байты в обе стороны, в секунду и всего | `NetTransportStats` | панель F2 |
| повторы надёжных сообщений, % | `NetTransportStats::retransmits` | панель F2 |
| потерянные снимки, % | `RlNetStats::snapshotsMissed` | панель F2 (клиент) |
| RPC: вызовы, OK, отказы, таймауты, ждущие | `RpcCounters` | панель F2 |
| неизвестные и битые сообщения, последняя причина | `NetBadMessages` | панель F2, лог |
| соединения, гости | `NetTransportStats::peers`, `ClientCount` | панель F2 |

## 8. Тесты

`myengine_rl_net_tests` (`ctest -R rl_net`). К сценариям G5 добавились:

- `TestRpc` — отказ гостю в `StartMatch`; `QuickChat` доходит до всех; `TOO FAST`, `UNKNOWN METHOD`, `BAD ARGUMENTS` (номер вне диапазона и лишний байт); вызов игрока хоста; итоговые счётчики.
- `TestRpcTimeoutAndClose` — хост молчит: `TIMEOUT` через 3 с, потеря связи даёт `CONNECTION CLOSED`, без соединения вызов отклоняется сразу. Хост убирает пропавшего клиента, «призрака» не остаётся.
- `TestBrokenMessages` — неизвестный тип и три обрезанных сообщения посчитаны и залогированы, матч идёт дальше.
- `TestTransportCounters` — пакеты, байты, повторы при 10 % потерь, потеря снимков около 10 %, отброшенная чужая датаграмма.
- `TestProtocolVersion` — клиент версии 4 получает отказ с причиной.
