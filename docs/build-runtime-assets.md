# B1: копирование рантайм-ассетов при сборке

## Зачем это нужно

Каждому exe нужны рядом `assets/`, `config/` и рантайм Python (`python314.dll`, `python314.zip` из `external/runtime`). Раньше каждая исполняемая цель вешала на себя POST_BUILD-команды `cmake -E copy_directory` в папку своего exe. Все тестовые цели лежат в одной папке `build/tests/<Config>`, поэтому при параллельной сборке несколько целей одновременно копировали одни и те же файлы. Из-за этого сборка иногда падала на `copy_directory` без единой ошибки компилятора.

Теперь копирование выполняется один раз за сборку на папку вывода и заканчивается до линковки любой цели этой папки.

## Что сделано

| Что | Где | За что отвечает |
|---|---|---|
| `myengine_copy_runtime_assets(<цель>)` | [cmake/CopyRuntimeAssets.cmake](../cmake/CopyRuntimeAssets.cmake) | Создаёт custom-цель копирования для папки вывода цели и добавляет цели зависимость на неё |
| Скрипт копирования | [cmake/CopyRuntimeAssetsRun.cmake](../cmake/CopyRuntimeAssetsRun.cmake) | Запускается как `cmake -P` во время сборки и копирует файлы через `file(COPY)` |
| Вызовы функции | [app/CMakeLists.txt](../app/CMakeLists.txt), [tests/CMakeLists.txt](../tests/CMakeLists.txt) | Подключают копирование к `myengine` и к каждой тестовой цели |

## Как это устроено

1. Функция принимает цель и решает, что копировать:
   - `assets/` и `config/` копируются, если `MYENGINE_COPY_RUNTIME_ASSETS=ON`. При `OFF` выводится сообщение в лог CMake, и эти папки не копируются.
   - содержимое `external/runtime` копируется, если папка существует. Флаг `MYENGINE_COPY_RUNTIME_ASSETS` на него не влияет: рантайм Python копируется всегда, как и раньше.
   - если копировать нечего, функция выходит без создания цели.
2. На каждую папку вывода создаётся одна custom-цель `myengine_copy_runtime_<папка>`. Имя строится из пути папки сборки (`CMAKE_CURRENT_BINARY_DIR` относительно `CMAKE_BINARY_DIR`) и значения `RUNTIME_OUTPUT_DIRECTORY` цели, если оно задано. Все символы, кроме букв и цифр, заменяются на `_`. Если цель с таким именем уже есть, вторая не создаётся.
3. Команда цели запускает `cmake -P cmake/CopyRuntimeAssetsRun.cmake` с параметрами `DST_DIR` (`$<TARGET_FILE_DIR:цель>`), `SOURCE_DIR`, `COPY_ASSETS`, `COPY_RUNTIME`.
4. Каждая цель папки получает `add_dependencies(<цель> <цель копирования>)`. Поэтому копирование идёт один раз за сборку и раньше линковки любой из целей, и параллельные копии одних и тех же файлов исключены.
5. Custom-цель без выходных файлов выполняется при каждой сборке зависимых от неё целей. Лишней работы это не создаёт, потому что `file(COPY)` пропускает файл, у которого копия в папке назначения имеет то же время изменения.

Следствия:

- Пересборка без изменений стоит порядка 0,1 с. Замер: `assets` 47 МБ (141 файл) плюс runtime 11 МБ.
- Заменённый или новый файл в `assets/` попадает в папку сборки при каждой сборке цели. Раньше это происходило только при перелинковке.
- `python314.dll`, которую держит запущенный процесс, без изменений не перезаписывается.

## Требования к будущим целям

- Чтобы новая цель получила ассеты, достаточно вызвать `myengine_copy_runtime_assets(<цель>)` после её создания.
- Все цели одной CMake-папки должны иметь одну папку вывода. Если цель задаёт `RUNTIME_OUTPUT_DIRECTORY` до вызова функции, для каждого значения создаётся своя custom-цель.

## Ограничения

- Файлы, удалённые из `assets/`, из папки сборки не удаляются (как и раньше).

## Проверка

Автоматических тестов для этой задачи нет: гонка проявляется только при параллельной сборке. Ручная проверка:

1. Удалить `build/tests/Debug/assets` и пересобрать тестовые цели параллельно, не больше 4 задач: `cmake --build build --config Debug --parallel 4`. Сборка не должна падать на копировании. Повторить несколько раз подряд.
2. Проверить, что в `build/tests/Debug` и `build/app/Debug` есть `assets`, `config`, `python314.dll`, `python314.zip`.
3. Повторить сборку без изменений: шаг копирования должен занимать порядка 0,1 с.
4. Изменить файл в `assets/` и собрать любую цель: файл должен обновиться в папке сборки.
5. Сконфигурировать с `-DMYENGINE_COPY_RUNTIME_ASSETS=OFF`: `assets` и `config` не копируются, рантайм Python копируется.
