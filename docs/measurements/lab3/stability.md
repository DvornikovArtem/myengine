# ЛР 3: сценарии стабильности

Протокол проверки 14 сценариев из раздела 4 [architecture.md](../../render/architecture.md): что ломаем в шейдере, материале или на выходе, что должен делать движок и чем это подтверждено. ## Как проверяется результат в автотесте

Общие принципы, одинаковые для сценариев `render_stability`:

- Цвет центрального пикселя говорит, какая версия шейдера рисует. Кадр рисуется в render target 32x32, пиксель читается из центра. Версии шейдера в тесте дают разный цвет.
- На каждую отвергнутую перезагрузку в логе ровно одно сообщение `Shader error:`, и в нём имя файла.
- Счётчики статистики адаптера (`programs`, `pipelineStates`, `rootSignatures`, `retiredObjects`) после серии не растут, а `retiredObjects` (объекты, которые ждут GPU) возвращается к 0.
- После `Shutdown` в устройстве нет живых объектов.

## Что нашли при подготовке

| Находка | Что с ней |
| --- | --- |
| Одна и та же ошибка файла сообщалась дважды: при компиляции стадии VS и при компиляции стадии PS | Исправлено в `ShaderReflector`: сообщение одно, поле `stage` хранит обе стадии. Тест `shader_reflection` поправлен |
| У ошибки «необъявленное имя» компилятор добавляет второе сообщение (`function must return a value`), поэтому строк `Shader error:` может быть две | Не дубль: первая строка с файлом, строкой и колонкой - причина, вторая - следствие. Для синтаксической ошибки сообщение одно |
| Сообщения про entry, профиль, конфликт слотов и вход VS называют файл, но не строку | Строки нет в источнике сообщения. Файл и имя entry/профиля/ресурса в тексте есть |
| Белая текстура создаётся при первом обращении | Внутри прохода render target этого делать нельзя. В тесте её создают заранее; в движке её берут до кадра |
| Цвет пикселя читается из центра картинки 32x32 | Мелочь прогона: если менять размер или геометрию в тесте, центр должен остаться внутри меша |

## Ручной прогон

### Подготовка

1. Закрыть работающий движок, собрать нужную конфигурацию. Для Debug запуск с отладочным слоем:

   ```text
   myengine.exe --dx12-debug
   ```

   Для RelWithDebInfo запуск без флага; при желании тоже с `--dx12-debug`, если установлен слой Graphics Tools.
2. Открыть любую простую сцену (например `benchmark.json` или ту, что открыта по умолчанию), в которой есть сфера с материалом `gold`. Открыть панели `Output Log` (меню окон), Material Editor и Content Browser. Счётчики видны в двух местах. В панели Statistics, группа «Shaders»: строки `Programs`, `Pipeline states`, `Root signatures`, `Reloads` (в виде «N ok / M failed»). И в окне `Help -> Developer -> Shader Layouts`, строка вида `programs N | PSO N | root signatures N | waiting for the GPU N | reloads N ok / N failed`; только там есть `waiting for the GPU`.
3. Рядом открыть редактор HLSL с файлом [textured_lit.hlsl](../../../assets/shaders/textured_lit.hlsl). Файлы шейдеров и материалов опрашиваются раз в 500 мс, после сохранения нужно подождать около секунды.
4. После проверки вернуть файлы:

   ```text
   git checkout assets/shaders/textured_lit.hlsl assets/materials/gold.material.json
   ```

В колонке «Отметка» записать «прошло» или «нет» и комментарий.

### Сценарий 3: серия перезагрузок

1. Записать числа из группы «Shaders» в Statistics (`Programs`, `Pipeline states`, `Root signatures`, `Reloads`) и `waiting for the GPU` из `Shader Layouts`.

### Сценарий 14: корректный выход

Запускать движок из PowerShell, чтобы видеть вывод консоли и код выхода (`$LASTEXITCODE`). Закрывать окно крестиком. Во всех случаях окно закрывается без зависания (дольше нескольких секунд ждать не нужно), в консоли и логе нет сообщений отладочного слоя вида `Live ...` и `OBJECT_SUMMARY` про живые объекты. Сообщение движка `DX12 live objects after shutdown: none (the device only)` говорит, что всё в порядке; `DX12 live objects after shutdown: N (a leak of the adapter)` - утечка.

## Что не покрыто автоматически и почему

| Что | Почему не покрыто |
| --- | --- |
| Реальное окно и swap chain | Тест работает в скрытом окне с render target. Рисование в окно, ресайз и Present вживую остаются ручными |
| Превью в панелях и миниатюры Content Browser | Это ImGui. Автоматически проверен только путь, которым они рисуют (проход в render target с перезагрузкой внутри), но не сами панели |
| Баннеры, секции и виджеты Material Editor | Рисование ImGui не проверяется автоматически; модель панели без GPU проверяет `material_editor_model` |
| Группа «Shaders» в панели Statistics | Это ImGui. Автоматически проверены сами числа адаптера (`render_stability`), но не то, что панель их показывает. Числа в панели сверяются вручную в сценариях 3 и 13 |
| Длинная сессия с Диспетчером задач | 10 минут с живым редактором слишком долго для CTest. Автоматически - ускоренная версия на 60 циклов, она следит за счётчиками адаптера и частными байтами процесса |
| Память GPU | Тест не читает память GPU, счётчики адаптера и проверка живых объектов её не заменяют. Смотреть в Диспетчере задач |
| Закрытие окна пользователем | Тест вызывает `Shutdown` в нужных состояниях, но не закрывает окно мышью, не проходит через цикл сообщений окна и Play/Edit редактора |
| Машины без аппаратного адаптера | Без устройства или рабочего стола тест завершается кодом 77 (`Skipped`) и ничего не проверяет |
