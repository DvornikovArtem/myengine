# Лр1. Замеры до job system

Это наш `baseline`, снятый до появления `job system`. Все цифры получены из трейсов в `traces/`.

## Условия

| Параметр | Значение |
|---|---|
| **Конфигурация сборки** | RelWithDebInfo (`TRACY_ENABLE` включён только в ней) |
| **Tracy** | 0.14.1, клиент из сабмодуля, `tracy-capture -f -s 25` |
| **VSync** | выключен (`MYENGINE_VSYNC` не задана) |
| **Сцена** | `assets/scenes/benchmark.json`, 1036 сущностей, из них 1025 с `Rigidbody` |
| **Окно** | `1280x720` |
| **Прогонов** | 3, по 25с каждый, ввод во время записи не трогался |
| **Бинарный кэш** | `*.myemesh` и `*.myetex` удалялись перед каждым прогоном (холодная загрузка) |

Окно анализа физики `5-20с`. Мы сделали так, потому что в первые секунды тела падают и нагрузка нестабильна. Перцентили считаются линейной интерполяцией по всем вызовам зоны в окне.

## Какие проблемы есть

- Загрузка идёт через `std::async`: нет лимита параллелизма, приоритетов и единого шатдауна. В трейсе видно три разных потока пула;
- `PumpAsyncLoads` финализирует всё готовое за один кадр, лимита на кадр нет;
- Аплоад на GPU синхронный: `ExecuteCommandListAndWait` -> `WaitForGpu`;
- Выход с незавершёнными задачами блокируется в деструкторе `std::future`, отмены нет;
- `LoadTexture`, `LoadShader` и `LoadMaterial` вызывают `ScheduleMeshLoad`, из-за чего текстуры, шейдеры и материалы дополнительно уходят на парсинг как меши и падают с `Unsupported mesh format`.

## Структура папки

- `traces/artem/before_1..3.tracy` - трейсы Артёма, каждый содержит и загрузку (первая секунда), и физику;
- `traces/artem/csv/before_1..3_step.csv` - выгрузка зоны `Physics::Step` из трейсов Артёма;
- `traces/ivan/before_1..3.tracy` - трейсы Ивана;
- `traces/ivan/csv/before_1..3_step.csv` - выгрузка зоны `Physics::Step` из трейсов Ивана (`tracy-csvexport -u -f`).

Важно то, что фильтр `-f` у `tracy-csvexport` работает по подстроке. Для зоны `Frame` в выгрузку попадают также `RenderFrame`, `BeginFrame` и `EndFrame`, поэтому строки нужно фильтровать по точному совпадению колонки `name`.
