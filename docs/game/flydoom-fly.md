# Муха играет в DOOM (N1, FlyDoom)

Режим **Fly plays**: DOOM управляет не человек, а мозг мухи — 164 789 нейронов коннектома MaleCNS v1.0 в модели LIF (`game/flybrain`, [flybrain.md](../flybrain/flybrain.md)). Кадр игры попадает в «глаза» (фоторецепторы R1–R6), мозг считает 28,57 мс своего времени на каждый такт DOOM, частоты нисходящих нейронов превращаются в команду игрока. Игра ждёт мозг.

**Это не настоящая муха и не обученная муха.** Это сеть точечных LIF-нейронов с картой связей реальной мухи, подкормленная током. Что она умеет честно: реагировать на картинку (поворачивать к более яркой стороне) и ходить; чего не умеет: видеть врагов, уклоняться, учиться (подробно в конце).

## Как запустить

```powershell
powershell -ExecutionPolicy Bypass -File tools\flybrain\fetch_malecns.ps1 -SourceDir D:\flydoom-n0\raw   # один раз: assets\flybrain\malecns_v1.fbrain (154 МБ, не в git)
build\app\RelWithDebInfo\FlyDoom.exe --fly            # муха играет сразу
build\app\RelWithDebInfo\FlyDoom.exe                  # меню: Human plays, Fly plays, Fly learns, Human vs Fly, Fly vs Fly, Swarm
build\app\RelWithDebInfo\FlyDoom.exe --fly-mode fly-learn --fly-fast   # муха учится с нуля не упираться в стены, как можно быстрее (N4)
build\app\RelWithDebInfo\FlyDoom.exe --fly-mode human-vs-fly   # сразу дуэль: вы против мухи (D1b)
build\app\RelWithDebInfo\FlyDoom.exe --fly-mode fly-vs-fly     # два мозга друг против друга, вы смотрите (D1b)
```

Если файл коннектома лежит там, где его ищет игра, меню в начале спрашивает, кто играет; без файла игра как раньше (играет человек). Ключи (общие для `FlyDoom.exe` и `myengine.exe --game doom`):

| Ключ | Что |
| --- | --- |
| `--fly [doomfly\|bio]` | муха играет сразу; набор управления (по умолчанию `doomfly`, см. ниже) |
| `--fbrain <файл>` | где `.fbrain` (иначе `assets/flybrain/` рядом с exe, затем в исходниках) |
| `--fly-mode <id>` | сразу режим без меню: `fly`, `fly-learn` (N3b), `human-vs-fly`, `fly-vs-fly` (D1b) |
| `--fly-fast` | «Fly learns» идёт как можно быстрее (Speed MAX в меню): тик за тиком, сколько успевает мозг; на экране фактическая скорость (N4) |
| `--fly-untrained` | Fly plays, Human vs Fly, Fly vs Fly без обученной мухи (`assets/flybrain/fly_trained.bin`), как до N4 (в меню — Fly brain: FROM SCRATCH) |
| `--fly-forget` | оставлен для старых командных строк: с N4 «Fly learns» всегда начинает с нуля |
| `--fly-seed N` | зерно мозга (по умолчанию 1; сейчас влияет только на пуассоновский вход, которого игра не использует: ход игры от него не зависит) |
| `--fly-reward` | «награда»: ток в PAM при убийстве монстра или подборе предмета (по умолчанию выключено) |

Клавиатура и мышь при игре мухи не управляют игроком (только меню DOOM: Esc, Enter, стрелки). Игра сама начинает новую игру на титульном экране (Esc → New Game → Enter по умолчаниям) и листает экраны между уровнями (Enter).

## Схема

```
кадр DOOM 320x200 ──► глаза ──► мозг (28,57 мс) ──► нейроны ──► управление ──► TicCmd ──► один такт DOOM
(без панели статуса)   FlyEyes   FlyBrain            DNp20, DNpe017   FlyControls   ITicCmdSource   DoomGame::StepTic
        ▲                  ток в 1386 R1–R6, 12 мВ в L1/L2/L3/L5                                          │
        └──────────────────────────────────────────────────────────────────────────────────────────────────┘
урон ──► ток 4 мВ на 200 мс в PPL101 (дофамин)         смерть, смена уровня, «раскачка» ──► мозг пересоздаётся
```

Файлы: `game/doomfly` (`FlyEyes`, `FlyControls`, `FlyPlayer`, `FlyModes`), `engine/include/myengine/game/DoomController.h` (интерфейс контроллера игры), `assets/flybrain/controls_*.json` (данные), `tests/doomfly/DoomFlyTests.cpp` (тест `doom_fly`).

### Глаза (`FlyEyes`)

- **Какие рецепторы.** `R1-R6` коннектома MaleCNS (только вычитанные, `status == Traced`): **498 слева и 888 справа** (из ≈ 5300 у реальной мухи: левый глаз в датасете собран хуже). В DOOMFLY их 3335 из 3377: там берут и невычитанные, в нашем `.fbrain` их нет.
- **Куда смотрит рецептор.** У фоторецептора нет колонки (`assignedOlHex1/2` есть у L1–Mi1, не у R). Как у DOOMFLY, он берёт колонку клеток ламины, которые он кормит (самая частая колонка среди его целей L1/L2/L3, вес — число контактов): так нашлись колонки для 1386 из 1394 рецепторов (3 и 5 без колонки). Покрыто колонок: **182 из 875 слева, 380 из 892 справа** (остальные без вычитанного рецептора).
- **Ориентация решётки колонок** определена по данным, а не выдумана. Подгонка 3D-положения клеток L1–L3 и Mi1 под колонку (N1, пробник удалён; оси датасета: `y` дорсально→вентрально, `z` спереди→назад, `x` латерально; середина мозга `x ≈ 48 000`): для Mi1 `y = 59000 − 900·hx − 1070·hy` (R² 0,96), для L1–L3 `R² 0,95–1,00`; решётка у обоих глаз подписана одинаково (зеркально). Для плоскости `hx = hex2 − hex1/2`, `hy = 0,866·hex1`: **вверх** = `0,6·hx + 0,8·hy`, **вперёд** = `−0,8·hx + 0,6·hy` (в медулле, у Mi1, горизонтальная ось обращена: её «задняя» сторона видит передний мир — хиазма между ламиной и медуллой; ламина и рецепторы идут как в глазу). Наибольшая неопределённость — горизонтальная ось (R² 0,66–0,92), вертикальная надёжна.
- **Куда в кадре.** Левый глаз видит левые 60 % кадра с передним краем на 60 %, правый — правые 60 % с передним краем на 40 %: 20 % посередине видят оба. По вертикали — 3D-вид без панели статуса (верхние 84 % кадра, 168 из 200 строк). Центр: `left_x` ∈ [0,002; 0,527], `right_x` ∈ [0,420; 0,998] (тест).
- **Что чувствует.** Яркость — Rec. 709 по линейным цветам, среднее по квадрату 3×3 пикселя. Ток рецептора — насыщающийся отклик как у DOOMFLY: `drive = 30·L/(0,02 + L)` мВ (половина насыщения при `L = 0,02`). Низкочастотный фильтр τ = 10 мс (применяется в 4 подшага тика по 7,1 мс). **Тонический ток 12 мВ в L1, L2, L3, L5** (7114 клеток): без него ламина молчит (гистамин рецепторов тормозит её).
- **Движение и лупинг (D1a).** Кроме яркости в мозг идёт то, что меняется: для каждой колонки яркость сравнивается с её медленным средним (τ 100 мс): `c = (L − L_медл)/(L_медл + 0,05)`, −1…1. Рост (`c > 0`) даёт ток `12·c` мВ в **ON-клетки** колонки (Mi1, Mi4, Mi9), падение (`c < 0`) — ток `12·|c|` мВ в **OFF-клетки** (Tm1, Tm2, Tm4, Tm9); это все клетки колонок, у которых в `.fbrain` есть колонка (у Tm3 и T4/T5 её нет). Колонок 875 + 892 — **все** колонки обоих глаз, не только те, где есть вычитанный рецептор. Оттуда сигнал идёт по схеме мухи (T4/T5, LC4, LPLC2, гигантское волокно). Усиление 12 мВ — граница: при 6 мВ мозг не отвечает ничем, при 10 и выше сильное изменение картинки (резкая смена света, растущий объект) перебрасывает центральный мозг в собственное устойчивое состояние (см. «Лупинг»). Параметры — `EyesConfig::motionOnGainMv`, `motionOffGainMv`, `motionOnTypes`, `motionOffTypes`.

### Управление (`FlyControls`, данные в `assets/flybrain/controls_*.json`)

Канал — взвешенная сумма средних частот групп нейронов (за `smoothingMs` = 100 мс): тип и сторона. `turn` и `forward` — `gain·(сумма − offset − мёртвая зона)` с ограничением; `fire` — спайки группы за окно или частота выше порога; `use` — по таймеру у двери.

Два набора, переключаются при запуске (`--fly doomfly|bio`, пункты 2 и 3 меню):

| Набор | Поворот | Вперёд | Огонь | Что с ними на самом деле |
| --- | --- | --- | --- | --- |
| **DOOMFLY** (`controls_doomfly.json`, по умолчанию) | DNp20 R − DNp20 L − 11 Гц, мёртвая зона 2 Гц, 0,12°/такт на Гц, ±6° | DNpe017, 1 ед./Гц, ≤ 50 | DNpe017 ≥ 24 Гц | отвечают на картинку; нейроны те же, что в публичной демке DOOMFLY (MIT), авторы называют это инженерным назначением, не биологией; пороги и коэффициенты наши |
| **Bio** (`controls_bio.json`) | (DNa02 R − L) + 0,5·(DNa01 R − L), 0,06°/Гц | DNp09 − MDN | MN9, любой спайк за 100 мс | **молчат при любой картинке**: муха стоит на месте (честно показано, не «починено») |

Единицы DOOM: `forwardMove` в единицах DOOM (25 — шаг, 50 — бег), поворот `deg·65536/360` (положительный `DNp20 R − L` — вправо). «Использовать» — одно нажатие каждые 35 тактов, пока игрок давит вперёд и не двигается (меньше 6 единиц за 12 тактов): у двери. На экранах, которые ждут клавишу (титул, интермиссия, финал), контроллер жмёт Esc/Enter сам.

**Рефлекс «отвернуть от стены»** (`unstick` в наборе DOOMFLY, не из мозга): картинка стены не рулит (яркая, ровная), и без него муха встаёт у первой стены навсегда (первый прогон: с 700-го по 3150-й такт позиция не менялась). Если игрок давит вперёд и не двигается 50 тактов (кнопка «use» к тому времени уже пробовалась), на 18 тактов включается поворот на 5° за такт (сторона чередуется) и ход назад 10 единиц, потом управление возвращается мозгу. Это такой же внешний рефлекс, как «use» у двери; в данных (`afterTics: 0` выключает).

**Смещение −11 Гц.** При ровной картинке `DNp20 R − L` не ноль, а ≈ +10…+12 Гц (справа вычитанных рецепторов 888, слева 498), поэтому без поправки муха всегда подворачивала бы вправо. Поправка `offsetHz` измерена на ровном сером кадре (N1: 10,5 Гц серый, 11,5 тёмный, 12,0 яркий) и лежит в данных.

### Мозг на GPU (D1a)

`FlyPlayerConfig::backend` (`--flybrain auto|cpu|gpu`, по умолчанию `auto`) и `renderDevice`: `Auto` ставит мозг на видеокарту (compute-шейдеры N0b), если есть DX12 с double и самопроверка проходит, иначе на CPU. В игре мозг живёт **на устройстве рендера** (`Application::RenderDevice()`): так вид мозга (V1) читает кольцо спайков без копии на CPU; в панели строка «brain on the GPU (render device)». После каждых 28,57 мс вызывается `FlyBrain::Synchronize()`: GPU только записывает окна, без ожидания читались бы «те спайки, которые уже вернулись», и ход игры зависел бы от случая; с ожиданием игра **детерминирована и тот же ход, что на CPU** (хэш команд E1M1 совпал бит в бит на обоих бэкендах). Скорость в игре: **мозг 2,7–3,1× реального времени, игра 1,0×** (темп 35 тактов в секунду держит `FlyPlayer`, GPU «ждёт часы»); на CPU 0,6–0,9×. Пересоздание мозга (сброс) не уничтожает старый мозг на потоке мозга: кольцо спайков, отданное виду (`FlyPlayer::BrainFeed()`), живёт до следующего `Pump` главного потока.

### Время: игра ждёт мозг (`FlyPlayer::Pump`)

Тик DOOM (1/35 с) = 28,57 мс мозга (285 или 286 шагов по 0,1 мс; дробная часть переносится). Мозг считает на отдельном потоке (нейроны окна — задачи job system), главный поток рисует кадры окна, пока он думает. Такт игры запускается, когда мозг дочитал свои 28,57 мс; раньше 1/35 секунды стенного времени после предыдущего такта он не стартует (мозг не быстрее реального времени). Если мозг медленнее — игровое время идёт медленнее, окно рисуется как раньше. В панели: `brain speed` — модельное время / стенное время мозга за такт (1,0 — реальное время), `game` — тактов в секунду / 35; «the game waits for the brain», пока такт ещё считается. `FlyPlayer::StepBlocking` выполняет то же самое на вызывающем потоке без темпа (тесты, обучение быстрее реального времени).

Определено порядком: кадр N → вход мозга → результат → команда такта N → такт → кадр N+1. Результат одинаков при любом числе потоков и любой скорости, это детерминированно: тот же ход игры при том же `.fbrain`, WAD и зерне (проверяет тест, два процесса).

### Подкрепление, сброс, раскачка

- **Урон** (здоровье игрока упало) → ток 4 мВ на 200 мс в PPL101 (bodyId 11327, 11900; как у DOOMFLY). 4 мВ меньше порога (7 мВ): сам по себе ток не рождает спайков, он сдвигает потенциал под приходящий вход. В панели полоска «dopamine PPL101».
- **Награда** (`--fly-reward`): ток 4 мВ на 200 мс во все PAM при убийстве или подборе предмета; по умолчанию выключена, влияние на поведение не измерялось.
- **Пластичность KC→MBON** — только в режиме **«Fly learns»** (`FlyPlayerConfig::learning`, N3b; [flybrain.md, «Муха учится в игре»](../flybrain/flybrain.md#муха-учится-в-игре-n3b)). Там урон — ток 15 мВ во все PPL1 (выше порога), дофамин — модулятор, локальные нейроны антеннальной доли молчат, а смена света колонок идёт прямо в зрительные входы клеток Кеньона (`flybrain::KcVision`, **наш мост вместо оптической доли**). Выученное переходит из жизни в жизнь и между запусками (`fly_memory.bin`, `--fly-forget` стирает). Управление — `controls_learn.json`: DOOMFLY + MBON32/MBON20 в повороте (**MBON → поворот — наш вес**), смещение и усиления откалиброваны под этот мозг. В панели: группа LEARNING (спайки KC, средний вес KC→MBON) и та же подпись про мост. Остальные режимы работают как раньше: быстрый дофамин, антеннальная доля включена, без пластичности.
- **Обученная муха и «долбится в стену»** (N4, [flybrain.md, «Обученная муха»](../flybrain/flybrain.md#обученная-муха-n4)). Упор — муха жмёт вперёд и почти не движется (`FlyStatus::wallTics`, `wallHits`). Стену выучивает **наш слой WallSense, не коннектом**: память картинок 8 × 6 с метками «через 0,5 с был упор», своя на каждую карту. Увидев знакомое место перед стеной, муха останавливается и поворачивает от половины картинки со стеной. Fly plays, Human vs Fly и Fly vs Fly грузят обученную память (`fly_trained.bin`, 18 карт эпизода 1 shareware DOOM и Freedoom) и доучиваются в сессии. Fly learns учится с нуля: и слой, и KC→MBON; за упор — тот же ток в PPL1, что за урон. Поверх картинки — фактическая скорость, «% времени у стены» за каждые 15 с и время жизней; в панели — группа WALLSENSE с подписью «наш слой (память картинок), не коннектом» и вес KC→MBON с подписью «синапсы учатся, но на стену не влияют».
- **Сброс мозга** (пересоздание `FlyBrain`: покой, потенциалы нули, глаза и тонический ток ставятся заново): смерть игрока, смена уровня, и **«эпилептическая» раскачка**: активность **центрального мозга** (нейроны `cb_intrinsic`, 32 160 штук) выше 600 тыс. спайков/с дольше 300 мс. Весь мозг для этого не годится: его шум идёт от оптической доли (покой и яркая картинка — 270–410 тыс. спайков/с, а в центральном мозге при этом **0**). Центральный мозг молчит, пока картинка не меняется резко; при раскачке током 25 мВ в ламину он даёт ≈ 1,08 млн спайков/с и остаётся там (замер ниже). Счётчики `resets` и `runaway` в панели и в журнале (строка `fly:` раз в 10 секунд игры).

### Панель мозга (временная)

Справа от картинки (26 % ширины): режим, скорость мозга и игры, частоты нейронов, которые читает управление (полоски до 60 Гц), поворот (двусторонняя полоска), вперёд, огонь/«use», дофамин PPL101, спайки мозга в секунду, такты, `resets`/`runaway`/`hurt`, и внизу квадрат «brain view» — **место для красивого 3D-облака (V0, coder-3, `BrainView`)**; пока в нём растр последних спайков по номеру нейрона (≈ 2048 штук за такт). Функция для вида: `FlyPlayer::Snapshot()` отдаёт копию `BrainSnapshot` (шаг и последние спайки) последнего такта; `FlyPlayer::GetConnectome()` — позиции нейронов; потоки безопасны (копия сделана на потоке игры).

## Два игрока в одной игре: Human vs Fly и Fly vs Fly (D1b)

Оба режима — **дезматч на двоих в одном процессе** (`-deathmatch -nomonsters -players 2 -warp 1 1`, E1M1; монстров нет, у карты четыре дезматч-старта). Игрок 0 — игрок консоли (в Human vs Fly им играете вы клавиатурой и мышью, в Fly vs Fly — первый мозг), игрок 1 — мозг. Что для этого сделано:

- **`-players N` в doomgeneric** (`d_loop.c`, пометка `myengine`; N = 1…4, по умолчанию 1): `D_StartNetGame` сообщает DOOM, что в игре N игроков, `BuildNewTic` держит игроков 1…N−1 «в игре» с пустой командой, `SinglePlayerClear` их не выкидывает. Сеть не включается (`netgame` остаётся ложью), поэтому меню Esc по-прежнему ставит игру на паузу. Команды игроков 1…N−1 выдаёт `DG_TicCmdHook` → `ITicCmdSource`, как для одного мозга.
- **Вид через глаза любого игрока.** `DoomGame::RenderEyes(player, view)` и `RenderView(player, view)` для не-консольного игрока: дополнительный проход `R_RenderPlayerView(&players[n])` с подменой `displayplayer` в тот же `I_VideoBuffer`, перевод палитры (PLAYPAL, гамма игры) в 0x00RRGGBB; ряды строки состояния чёрные. Проход идёт между тактами на потоке игры, следующий `D_Display` перерисует картинку консоли. Результат тестируется: вид игрока 1 отличается от вида игрока 0.
- **Счёт.** `PlayerState::frags` и `deaths` (DOOM-овские `frags[]`: убийства минус самоубийства). `DoomGame::RestartLevel()` загружает уровень заново (`ga_loadlevel`, из уровня и из межэкранной заставки): все игроки рождаются заново, фраги обнуляются; «новая игра» не годится, она выкидывает игроков 1…3.
- **`FlyPlayer` для нескольких игроков:** `FlyPlayerConfig::playerIndex` (чей это мозг), `ownView` (даже игрок консоли смотрит через дополнительный проход: оба мозга видят одинаково, без строки состояния), `drivesScreens` (только один мозг листает титульный экран и межэкранные заставки). `Pump` разобран на `Begin` (время и отправка кадра мозгу), `Poll` (результат мозга: команда готова) и `EndTic` (после такта): так один хозяин ведёт несколько мозгов, **такт игры идёт, когда ответили все мозги**. Мёртвый игрок жмёт «use» (иначе в дезматче не возродиться).
- **Контроллер `DuelController` (`FlyModes.cpp`)** ведёт раунд: до 10 фрагов, или 3 минуты (побеждает тот, у кого больше фрагов; поровну — ничья), или выход с уровня (кто-то нажал «use» у выходного выключателя: DOOM показывает заставку, потом тот же уровень начинается заново); 3 секунды показывается итог раунда, потом `RestartLevel`. Счёт раундов и фрагов — в панели справа, там же панель каждого мозга (при двух — друг под другом). Для проверок: `MYENGINE_DUEL_ROUND_TICS=<такты>` укорачивает раунд.
- **Окно** (`DoomGameFlow`): контроллер может сказать `HumanPlays()` (клавиатура и мышь работают в игре, а не только в меню) и отдать `Secondary()` — вторую картинку; окно кладёт её справа от картинки игры и подписывает («YOU» / «THE EYES OF THE FLY»; «FLY 1» / «FLY 2»). Во втором режиме слева картинка игрока 0 со строкой состояния, справа вид игрока 1 глазами его мозга.

Цена: два мозга — вдвое больше работы. На GPU (ноутбук, RTX 3050) два мозга шли в игре со скоростью **1,2–2,8×** реального времени (игра 1,00× — мозг ждёт часов; в тесте `duel` без часов: 0,97×); на CPU два мозга не уложатся в реальное время.

**Что видно честно:** мухи не видят друг друга (см. «Что муха умеет и не умеет»): они бродят по уровню и стреляют в стены, фрагов нет (в прогонах 0 : 0, раунды заканчиваются по времени или у выхода; здоровье у мух иногда падало (от выстрелов другой мухи или от кислоты на карте, причину не разбирал), убийств ни разу). Режим — не соревнование мозгов, а демонстрация механики (два мозга, два вида, счёт, раунды); смысл появится, когда у мозга появится способ различать врага (V1/N2: рой).

То есть игра идёт в 1,2–1,7 раза медленнее реального времени, как у DOOMFLY (у них 0,21–0,66× на M1 Pro); ускорение — задача N0b (мозг на GPU), интерфейс `FlyBrain` тот же.

**Поведение за 90 секунд игры** (E1M1 с титульного экрана, DOOMFLY-набор): муха сама открывает меню и начинает игру, первые 20 секунд идёт вперёд и стреляет в стены (расстреляла все 50 патронов стартового набора: «огонь» включается яркостью картинки, не целью), потом кружит в стартовой комнате в пределах 400×100 единиц, порой упираясь в стену и отворачиваясь рефлексом; здоровье 100 %, монстров не встретила, `resets 2` (старт мозга и вход в уровень), `hurt 1`, `runaway 0`. ## Лупинг: что делает мозг, когда объект приближается (D1a)

Проверено на GPU (`tests/doomfly/DoomFlyTests.cpp`, сценарий `loom`; та же картина на CPU: спайки совпадают). Расширяющийся светлый круг (радиус 3 → 70 пикселей за 28 тактов, три цикла) на тёмном фоне, 84 такта, потом объект исчезает:

| Объект | LC4 (пик, Гц) | DNp01 (пик, Гц) | DNa02 L (пик, Гц) | Поворот, °/такт (среднее / минимум) | Тактов огня | Сбросов мозга |
| --- | --- | --- | --- | --- | --- | --- |
| справа | 0,4 (R) | 0 | **40** | **−1,24 / −6,0** (от объекта: влево) | 2 | 3 |
| в центре | 1,5 (R) | 0 | **40** | −1,27 / −6,0 | 4 | 3 |
| слева | 0,4 (R) | 0 | 0 | −0,19 / −2,3 (шум) | 0 | 0 |
| тот же круг, но стоит | 0 | 0 | 0 | −0,51 / −2,3 (шум) | 0 | 0 |

Что это значит, без украшений:
- **Путь «лупинг → LC4/LPLC2 → гигантское волокно DNp01» в этой модели почти молчит**: LC4 справа отвечает единицами герц, LPLC2 — нулём, DNp01 на таких стимулах стреляет редко (в других замерах до 20 Гц на яркий растущий круг справа при усилении 40 мВ, но тогда мозг в раскачке).
- **Зато сильное изменение картинки (справа или спереди) перебрасывает центральный мозг в собственное устойчивое состояние (≈ 1 млн спайков/с, держится после исчезновения объекта)** — это та же «раскачка», что даёт ток в ламину, и защита от неё сбрасывает мозг через ≈ 11 тактов. Выход состояния: DNa02 противоположной стороны (L при объекте справа) стреляет 40 Гц, поворот `DNa02 R − L` отрицательный: **муха резко поворачивает от объекта (до −6°/такт) и один-два такта стреляет** (гигантское волокно, а в DOOMFLY-наборе ещё DNp20/DNpe017). Это настоящий выход мозга, не рефлекс вне его; но «видит приближение» — слишком сильно сказано: он отвечает на сильную смену света на правой стороне и в центре.
- **Слева нет ничего.** Левая оптическая доля в MaleCNS собрана хуже (498 вычитанных рецепторов против 888, LC4 слева 112 нейронов против 90, но отклика нет), то же видела N2 в вырезанной схеме роя. Объект слева муха не замечает совсем.
- Стоящий объект (даже большой) ничего не вызывает: центральный мозг молчит (0 спайков/с), поворота нет, огня нет.
- Порог по усилению (12 мВ в колонки): при 6 мВ ничего, при 10 мВ уже есть устойчивое состояние. Градуального ответа (чем быстрее приближение, тем сильнее реакция) нет — это переключатель.

Поэтому в наборе DOOMFLY к повороту добавлены `DNa02 R − L` с весом 2 (для ухода от объекта) и огонь по спайку DNp01 (`fire.spikeTerms`); LC4 и LPLC2 показываются в панели (`show`) для наблюдения, на управление они не влияют.

## Что муха умеет и не умеет

Умеет:
- поворачивать к более яркой стороне картинки и идти вперёд, быстрее по ярким коридорам (DNpe017 растёт с яркостью);
- стрелять в ярких местах (DNpe017 ≥ 24 Гц), «давить» на дверь, когда упёрлась;
- переживать урон (ток в PPL101), смерть и смену уровня (сброс мозга), раскачку (сброс мозга).

Не умеет (честно):
- **врагов видит только отчасти** (D1a): резкое изменение картинки справа и спереди (враг, который выскакивает или растёт) бросает мозг в устойчивое состояние, муха резко поворачивает прочь и стреляет; слева ничего; медленное приближение и стоящий враг ничего не дают; градуального ответа нет (см. «Лупинг»). Монстр в 20 % кадра без резкой смены света отклика не даёт;
- **уклоняется** только поворотом прочь (DNa02) при таком срабатывании, не бегом и не рывком (набор Bio, где «побег» по биологии, молчит);
- **мозгом не учится** вне «Fly learns»: там синапсы KC→MBON учатся (N3b), но заметно поведение не меняют, и на стены не влияют (N4); подкрепление в остальных режимах — только ток в PPL101; DOOMFLY сам пишет «live experimental training, not demonstrated learned survival». То, что муха меньше стоит у стен, — наш слой WallSense, не коннектом;
- управляется не биологически назначенными нейронами (DNp20, DNpe017: «не биология», по словам авторов DOOMFLY), потому что назначенные биологией (DNa02, DNp09, MDN) в такой постановке молчат;
- «зависимость от тонического тока»: как и у DOOMFLY, управление активно и с чёрным кадром (DNpe017 9 Гц → медленно ползёт вперёд); без тока в ламину молчит всё;
- ходит в стены и стреляет в них (яркая стена — сильный вход): сам мозг по картинке не отличает стену от прохода, только «светлее / темнее». С N4 обученная муха (наш слой WallSense) у стен проводит в 3–3,7 раза меньше времени, но она помнит места карт, а не «стену вообще».

## Рой мух-врагов (D1c)

Режим **Swarm**: играет **человек** (клавиатура и мышь как обычно), а на него волнами нападают 8–32 мухи. У каждой мухи свой маленький мозг ([`FlySwarmBrain`](../flybrain/flybrain.md), N2): схема в 1 660 нейронов, вырезанная из MaleCNS вокруг пути «лупинг → поворот, ход, бросок»; все мухи считаются одним батчем.

### Как запустить

```powershell
build\app\RelWithDebInfo\FlyDoom.exe --fly-mode swarm
```

Нужен `assets/flybrain/swarm_circuit.fbrain` (1 МБ, делает `myengine_flybrain_circuit.exe` из `malecns_v1.fbrain`, не в git; он производный от данных CC BY 4.0). `--fly-mode swarm` включает режим сразу (иначе он в меню FlyDoom). Аргументы DOOM режима (`doomfly::SwarmDoomArgs()`): `-warp 1 1` (сразу E1M1; свой `-warp` в `--doom-args` главнее), `-nomonsters` убирает обычных монстров DOOM, `-flyswarm` подкладывает DOOM спрайты и жужжание мухи (см. ниже: без него `doom::swarm` ничего не делает).

На экране (поверх картинки, без панели справа): `SWARM  WAVE n  FLIES живых / в волне  KILLED всего`, строка мозга (`brain gpu 0.4 ms per tic, turn, escape`), плашка «WAVE n», «WAVE n CLEARED, next in N», при смерти «THE SWARM GOT YOU» (USE начинает уровень заново: волны с первой). Звук мухи (`DSFLYBZ`) идёт через звук DOOM в `AudioSystem` вместе с остальными эффектами (громкость и сторона по расстоянию и углу).

### Что есть муха в DOOM

Муха — это **Lost Soul** (летающий монстр без гравитации), которым управляет хозяин (`game/doom/include/doom/DoomSwarm.h`, `src/DoomSwarm.c`): состояние мухи не кончается (`tics = -1`), ИИ DOOM не работает, перед каждым тактом хозяин задаёт угол, импульс и кадр спрайта. Остальное делает сам DOOM: стены, выстрелы игрока (муха `MF_SHOOTABLE`, оружие работает как против монстра; пистолет делает 5–15, у мухи здоровье 5: любое попадание убивает), смерть в кадрах смерти Lost Soul, подсчёт убийств (`MF_COUNTKILL`: `players[].killcount` растёт сам). Мухи не твёрдые (`MF_SOLID` снят), чтобы не слипаться, но игрока обтекают как стену.

Что подменено и зачем (все правки doomgeneric помечены `myengine`, список — [`third_party/doomgeneric/README-myengine.md`](../../game/doom/third_party/doomgeneric/README-myengine.md)):
- **Спрайты и жужжание — свои, рисуются кодом** (`game/doom/src/DoomSwarmAssets.cpp`, лицензия наша, файлов нет): рисунок мухи спереди 56×48 (красные глаза, прозрачные крылья «в шашечку» как у DOOM, полоски на брюшке) в палитре WAD (ближайший цвет `PLAYPAL`), 11 кадров Lost Soul: `A, B` — крылья вверх и вниз, `C, D, E` те же, `F`…`K` — смерть (брызги, раздавленная муха на полу); жужжание — пила 205 Гц с дрожью 7 Гц и огибающей 36 Гц крыльев, 0,3 с, 11025 Гц, формат DMX.
- **Лампы вставляются в память, `-file` не используется:** DOOM отказывается от `-file` с shareware («You cannot -file with the shareware version»), а у shareware `doom1.wad` нет спрайтов Lost Soul. `DG_AfterIwad` (хук в `D_DoomMain` после загрузки WAD, до `R_Init`) переименовывает уже имеющиеся `SKUL…` в `XKUL…` (скан спрайтов их не найдёт) и вставляет наши лампы в таблицу перед `S_END` (`W_InsertMemoryLumps`, память-файл вместо дискового); звук добавляется в конец, ему отведён `sfx_flybz`.
- **Состояния Lost Soul под роем:** `S_SKULL_DIE6` не кончается (иначе DOOM удаляет моб и у хозяина остаётся указатель в никуда); `painchance`, `seestate`, `missilestate` обнулены: муха, которую ранили и не убили (кулаком 2–20 против 5 здоровья), не должна проснуться как Lost Soul и лететь в атаку со звуком `dssklatk`, которого в shareware нет (так игра и упала в первом живом прогоне: «W_GetNumForName: dssklatk not found!»; в тесте `doom_fly_swarm` теперь ранение без смерти проверяется).

### Что мозг, что рефлекс

| Что | Чем решается |
| --- | --- |
| что видит муха | игра: лупинг слева и справа (угловая сторона, где игрок) и яркость 0,3 (ниже порога, спайков не даёт) |
| поворот в стороны от лупинга (DNa02, DNa01) | **мозг**: `turn` ± 14° за такт к направлению погони |
| быстрее или медленнее (DNp09, MDN) | **мозг**: скорость ± 35 % |
| бросок прочь от игрока (гигантское волокно DNp01) | **мозг**: каждый новый спайк волокна запускает бросок (7 тактов по 21 ед., раз в 24 такта, в сторону от линии оружия) |
| погоня за игроком, облёт стен (`P_NewChaseDir` DOOM), высота полёта, укус при касании (1–2 урона раз в 24 такта), разлёт друг от друга, жужжание | **рефлекс игры**, не мозг |

Что видит муха: игрок **набегает** на неё (скорость игрока в её сторону, сильнее вблизи) и **дуло оружия** смотрит на неё (стреляет по линии на неё; муха «замечает вспышку» с вероятностью 8 % за такт). Мухе, которая нападает, лупинг от собственного приближения **не** даётся: муха знает своё движение. Поэтому стоящий и не стреляющий игрок для роя не лупинг (мухи кусают), а игрок, который бежит на муху или целится в неё, заставляет её уворачиваться: бросок и поворот. Это не «биология охоты», а «биология бегства» поверх игрового рефлекса охоты, и так сказано честно.

### Правила

| Что | Значение |
| --- | --- |
| волна n | `8 + 4 (n − 1)` мух, не больше выбранного размера роя (8…32); следующая через 3 с после того, как поле чисто; скорость `10,5 + 0,35 (n − 1)` ед. за такт (игрок идёт 8, бежит 16), не больше 14 |
| рождение | в 380…950 ед. от игрока и **там, где игрок видит место** (`P_CheckSight`); если комнаты тесные — ближе (140…420) и без условия видимости |
| потерялась | муха, 7 с не видевшая игрока, возвращается в место, откуда игрок её видит (стены DOOM — не лабиринт, который она решает) |
| укус | в пределах 44 ед. и по высоте −24…+46; урон 1–2 (1 на самых лёгких уровнях), раз в 24 такта |
| смерть игрока | мухи висят на месте; USE начинает уровень заново (DOOM пересоздаёт мобы, рой — с первой волны) |
| труп | лежит 5 с и убирается; его место в мозге берёт следующая волна |

### Что измерено

Мозг роя на вырезанной схеме (сценарий `brain` теста, 12 мух, 314 мс, лупинг от 0 до 1; те же числа, что у N2): без лупинга ни одного спайка; **любой** лупинг, даже 0,1, запускает гигантское волокно (67–129 спайков за 300 мс): это почти «всё или ничего», поэтому игра даёт лупинг только на самом деле набегающему игроку и целящемуся оружию. Поворот: лупинг слева — вправо, уверенно (`turn` +0,53…+0,82); лупинг справа — влево, но слабо (−0,01…−0,22): асимметрия графа (N2), здесь не исправляется (бросок и его случайный разворот ±65° увод делают на обе стороны).

Игра (сценарий `game`, E1M1, shareware `doom1.wad`, 8–16 мух, мозг на CPU):

| Что | Результат |
| --- | --- |
| первая волна | на 34-м такте (1 с), 8 мух за 539 ед. от игрока в среднем; через 160 тактов в среднем в 140 ед.; стоящий игрок получил 31 укус и потерял 47 здоровья |
| игрок наводится на ближайшую видимую муху и стреляет | волна 1 чиста на 398-м такте (8 убито, 63 такта огня, DOOM сам насчитал 8 убийств игрока), волна 2 (12 мух) на 503-м, волна 3 (16) на 892-м, 20 убито, 26 бросков |
| мозг на такт | 16 мух, в игре: 0,8–1,6 мс из 28,6 (CPU, job system); 32 мухи, игрок стоит: **3,6 мс на CPU, 0,34 мс на GPU** (мозг почти молчит, пока нет лупинга; худший случай, все 32 мухи под лупингом, измерил N2: CPU 1,1×, GPU 3,8× реального времени) |

Живой прогон (скрытый рабочий стол, `FlyDoom.exe --fly-mode swarm`, игрок — скриптовая клавиатура: огонь и повороты; кадры — `.team/tasks/d1-evidence/swarm-t*.png`, лист `swarm-contact.png`, спрайты — `swarm-sprites.png`): мухи подлетают, крылья «в шашечку» вблизи на полэкрана, на полу красно-зелёные лужицы, волна 1 чиста к 20-й секунде (патроны кончились, дальше кулак), «WAVE 1 CLEARED», волна 2 из 12 мух. Мозг шёл на GPU (0,4 мс на такт).

### Тест `doom_fly_swarm`

`ctest --test-dir build -C RelWithDebInfo -R doom_fly_swarm` (4 с; сценарии в дочерних процессах, как у `doom_fly`; мозг и игра пропускаются без `swarm_circuit.fbrain`, игра — без WAD):

| Сценарий | Что проверяет |
| --- | --- |
| `sprites` | 11 кадров рисуются (≥ 120 пикселей), крылья вверх и вниз различаются, последний кадр лежит на полу; `SWARM_SHEET=<файл.ppm>` пишет лист кадров |
| `brain` | без лупинга ни одного спайка; с лупингом гигантское волокно прыгает (> 20 спайков); лупинг слева поворачивает вправо; больше лупинга — не меньше спайков |
| `game` | E1M1 без монстров DOOM и с роем: первая волна в первые 80 тактов, 8 мух; они подлетают (расстояние вдвое меньше за 160 тактов); кусают, здоровье падает; игрок, наводящийся и стреляющий, убивает волну (DOOM считает те же убийства); волна 2 из 12 после чистого поля и волна 3 из 16 (слоты мозга для трупов используются снова); мухи прыгают; **раненая и живая муха не просыпается как Lost Soul** |

Параметры сценария `game` для измерений: `--flies 32 --wave 7 --backend gpu|cpu|auto --tics N`.

### Чего нет

- Мухи не решают лабиринт: погоня по прямой, когда игрок виден, иначе жадный обход стен `P_NewChaseDir` и возврат в видимое место через 7 с.
- Мозг мух не получает «звук» и «запах»: вход — лупинг и яркость.
- Одно ограничение мозга: на GPU выходы отстают на такт.
- Меню режима и регистрация в `FlyDoomModes` — coder-1 (D1b): `doomfly::MakeSwarmController(options, flies, backend, seed, error)`, `doomfly::SwarmDoomArgs()`, `doomfly::SwarmAvailable(options, reason)`.
