# Повтор гола и кинематографичные камеры (G7e)

Отдельный модуль без Jolt и без рендера (`game/rl`), который `RlGameSystem` подключает несколькими вызовами: кольцо записи последних 10 секунд матча, повтор гола с замедлением и тремя камерами, облёт стадиона перед первым кик-оффом, камера на взрыв гола, камера итогов матча. Звук и эффекты повтора — `RlFeedback` в режиме повтора ([rl-feedback.md](rl-feedback.md)), надпись REPLAY и подсказка Skip — UI-кит ([rl-ui.md](rl-ui.md)). `RlGameSystem`, `RlMatch`, `RlNet*` модуль не меняет.

| Файл | Что |
| --- | --- |
| `game/rl/include/rl/RlReplay.h`, `src/RlReplay.cpp` | `RlReplayBuffer` (кольцо), `RlReplayPlayer` (клип, профиль скорости, три плана), `RlReplayConfig`, `RlReplayInfo` |
| `game/rl/include/rl/RlCinematic.h`, `src/RlCinematic.cpp` | `RlDirector` (что показывать каждый кадр), камеры `RlFlyoverView`, `RlGoalCelebrationView`, `RlResultsView`, `RlLookAt`, `RlBlendViews` |

| `tests/rl/RlReplayTests.cpp` | тест `rl_replay` |

## Как это работает

**Запись.** `RlReplayBuffer` хранит весь `RlWorldState` каждого тика (машины, мяч, пады, счёт; 1112 байт): кольцо на 1200 тиков (10 с) — 1.3 МБ, запись тика — одна копия (0.00004–0.0002 мс). Тот же номер тика ещё раз (откат сети пересимулирует его) стирает тик и всё после него и пишет новый; тик не подряд (разрыв) начинает кольцо заново. Поэтому в кольце всегда лежит та линия времени, которая у матча сейчас.

**Клип.** `RlReplayPlayer::Start` копирует из кольца 5 с до гола и 0.9 с после (кольцо может перезаписаться, пока клип играет; копия ~0.8 МБ, раз за гол). Скорость: 1× до последних 1.25 с перед голом, дальше 0.5×, переход гладкий за 0.25 с. Повтор длится **около 8 с реального времени** (709 тиков: 3.75 с на 1× и около 4.3 с в замедлении). Проигрыватель отдаёт два соседних тика и долю между ними (`Previous()`, `Current()`, `Alpha()`): их рисуют так же, как живые `before`, `now`, `alpha`, и список тиков, пройденных за кадр (`CrossedTicks()`), для `RlFeedback`.

**Три плана** (`RlReplayShotKind`, смена два раза, резкий монтаж): сначала **Ball** (за мячом по направлению его полёта, выше, подтянута к стенам и потолку по `ArenaSegmentFree`), затем **Author** (камера машины, забившей гол: настоящий `RlCameraUpdate` с ball cam; только если автор известен, его машина не уничтожена и не дальше 45 м от мяча), в замедлении **Goal** (из сетки ворот за линией, смотрит на мяч). Если автора нет (мяч в ворота без касаний), второго плана нет.

**Режиссёр** `RlDirector` ведёт последовательность и каждый кадр отвечает, что показывать:

| Момент | Что на экране | Заморозка матча |
| --- | --- | --- |
| Старт матча (`Reset`) | облёт стадиона 2.4 с (короче отсчёта 3 с): от ворот оранжевых вокруг арены к воротам синих, сглаживается в камеру игры за 0.4 с; пропускается кнопкой | нет |
| Гол | камера на взрыв 1.8 с (напротив ворот, подъезжает и поднимается), мир живой | нет |
| Затем | повтор ~8 с | **да, офлайн** (матч ждёт, потом идёт с того же места) |
| После повтора или пропуска | камера игры (плавный переход 0.4 с) | нет |
| Конец матча | камера итогов: облёт машин победившей команды, пока идёт экран результатов | — |

Гол, найденный ещё раз после отката (на несколько тиков позже), второй гол не даёт. Повтор не стартует, если в кольце меньше двух секунд до гола.

## Подключение к `RlGameSystem` (точные места)

Имена по `RlGameSystem.cpp` ветки `game-rl-online`; G1-flow переставляет код, смысл мест тот же.

**1. Создание.** Поле `std::unique_ptr<rl::RlDirector> director;`, рядом с `match` (после загрузки `tuning`): `director = std::make_unique<rl::RlDirector>(tuning);`. При перечитывании `rl_tuning.json` — `director->SetTuning(tuning)`.

**2. Новый матч.** В `StartMatch(World&)` после создания `match` (и там, где включается `BeginMatchVisuals` онлайн): `director->SetCanFreeze(online.role == RlOnlineOptions::Role::None); director->Reset();`. В `ToMenu`: `director.reset()` не нужен, достаточно `Reset()` при следующем старте.

**3. Каждый тик.** Сразу после `match->Step(inputs.data())` в цикле фиксированных тиков: `director->OnTick(match->World());`. Онлайн — один раз в наблюдателях хоста и клиента, рядом с `feedback->OnTick`: `netHost->SetTickObserver([this](uint32_t, const rl::RlMatch& m) { director->OnTick(m.World()); ... });` (наблюдатель зовётся и для пересимулированных тиков: кольцо перепишется, гол не удвоится).

**4. Заморозка (офлайн).** Поле `bool frozen = false;`. В цикле тиков: `while (accumulator >= rl::kTickDt) { accumulator -= rl::kTickDt; if (frozen) { continue; } ... match->Step(...); director->OnTick(...); }`, а после `director->Frame` — `frozen = shot.freezeLive; if (frozen) accumulator = 0.0f;` (чтобы после повтора не догонять накопленное время). Онлайн `freezeLive` всегда `false`.

**5. Каждый кадр, в `ApplyToScene`.** После того как вычислены `before`, `now`, `alpha` (у клиента `clientWorld` дважды и `alpha = 0`):

```cpp
const bool skip = justPressed.car.jump;   // Jump / A / Space (та же кнопка, что прыжок; во время повтора машина всё равно стоит)
const rl::RlDirectorFrame shot = director->Frame(deltaTime, skip, view->Sim(), before, now, alpha, &lastGameCamera);
const rl::RlWorldState& drawBefore = *shot.previous;      // дальше по функции вместо before / now / alpha:
const rl::RlWorldState& drawNow = *shot.current;          // живые миры, а в повторе миры клипа
const float drawAlpha = shot.alpha;
frozen = shot.freezeLive;  if (frozen) { accumulator = 0.0f; }
```

Пока играет повтор, цикл по машинам, мяч, пады, колёса и маркер берут `drawBefore`, `drawNow`, `drawAlpha` (они дают те же позы, что дали бы живые миры); поле `localSlot` остаётся тем же.

**6. Камера.** В `UpdateCamera` вычисление `rl::RlCameraUpdate(...)` оставить как есть каждый кадр (состояние камеры не должно остывать) и сохранить `lastGameCamera = cameraView;`. Затем применить либо камеру игры, либо камеру режиссёра:

```cpp
const rl::RlCameraView& use = shot.cinematicCamera ? shot.camera.view : cameraView;
const float horizontalFov = shot.cinematicCamera ? shot.camera.fovDegrees : cameraTuning.fov;
// basis из use.right / use.up / use.forward, cam->position = use.position, cam->fovYDeg из horizontalFov, как сейчас
```

В паузе `director->Frame` не вызывать (кадр идёт без режиссёра). Слушатель звука ставит `FxUpdateSystem` по основной камере, поэтому в повторе звук идёт из камеры повтора без отдельных вызовов.

**7. Звук и эффекты повтора.**

```cpp
if (shot.replayStarted) { feedback->BeginReplay(0.7f); }
if (shot.replay.active || shot.replayEnded)
{
    feedback->SetReplaySpeed(shot.replay.speed);
    for (const auto& tick : *shot.replayTicks) { feedback->OnTick(*tick.first, *tick.second); }   // события пройденных тиков
    feedback->Frame(deltaTime, *shot.previous, *shot.current, shot.alpha);                          // петли следуют машинам повтора
}
else { feedback->Frame(deltaTime, before, now, alpha); }                                           // как и раньше
if (shot.replayEnded) { feedback->EndReplay(); }
```

**8. HUD (UI-кит).** При каждом `hud.Update`: `state.replay.active = shot.replay.active; state.replay.author = <имя игрока shot.replay.scorerSlot или "">; state.replay.team = shot.replay.team; state.replay.goalSpeedKmh = shot.replay.goalSpeedKmh; state.replay.progress = shot.replay.progress; state.replay.speed = shot.replay.speed;`. `Hud::Draw` сам рисует REPLAY вместо баннеров, отсчёта, ленты и буст-кольца (табло и пинг остаются). Подсказку Skip показывает кит: «Space / A — Skip replay».

**9. Итоги.** Пока `shot.shot == RlShot::Results`, экран итогов G1 рисуется поверх; камеру даёт режиссёр (облёт машин победителей).

## Что нужно от `RlMatch` и данных

- **Офлайн ничего менять не нужно:** во время повтора матч просто не шагает (п. 4), фаза гола и её таймер стоят. Пока идёт камера на взрыв (1.8 с) матч живой, поэтому до конца фазы остаётся `goalSeconds − 1.8 = 1.2 с` (при `goalSeconds = 3`), их матч дожидается после повтора, затем кик-офф.
- **Онлайн повтор не может остановить матч.** Режиссёр обрывает его, когда живая фаза уходит из `GoalScored` (начался кик-офф): при `goalSeconds = 3` повтор успеет показать только последние ~1.2 с, что бесполезно. Чтобы онлайн-повтор был целиком, нужно `match.goalSeconds ≥ 10.5` (1.8 с камера + ~8 с повтор + запас) в `assets/data/rl_tuning.json` хоста (данные, не код; для офлайна оставить 3). Если такая пауза после гола не нужна, онлайн можно отключить: `RlReplayConfig::replayEnabled = false` (`director->SetConfig`), камеры облёта, взрыва и итогов работают и без повтора.
- Флаг «повтор идёт» для `RlMatch` не нужен: заморозка офлайн делается снаружи (п. 4); онлайн — тюнингом `goalSeconds`.
- Автор и команда гола берутся из `match.lastGoalScorer` / `lastGoalTeam` (есть), скорость мяча на голе режиссёр считает по записи (`goalSpeedKmh`), поле `lastGoalSpeed` из G1.0 ему не нужно.

## Тест `rl_replay` (`ctest -R rl_replay`, без окна)

- **кольцо:** границы после 1500 записей в кольце на 1200 тиков, откат на тик 1000 стирает последующие и пишет новый, откат старше кольца и разрыв начинают заново, поиск гола, размер кольца ≤ 2,25 МБ (было 2 МБ, пока имя стола было 24 байта: G1n подняла его до 33), запись тика < 0.02 мс (измерено 0.00004–0.0002 мс на мир 4v4);
- **матч ботов 2v2 на настоящей симуляции с голом на тике 2400:** сначала облёт стадиона, затем камера на взрыв, повтор, камера игры; клип ~6 с, повтор 8.0 с реального времени и совпадает с профилем скорости; каждый тик клипа пройден ровно один раз (709 тиков), показываются два соседних тика с долей 0..1, и **показанный тик побайтно равен записанному**; 2 тика за кадр на 1× и 1 тик за кадр в замедлении; матч заморожен весь повтор и после него стоит в фазе гола с запасом времени; камеры в каждом кадре конечные, с ортонормированными осями, внутри арены (с глубиной ворот);
- **план автора:** клип, где мяч в ворота забила машина 0: порядок планов Ball → Author → Goal (две смены), камеры допустимы в каждом кадре;
- **пропуск:** кнопка через секунду останавливает повтор в тот же кадр, матч размораживается;
- **онлайн:** `SetCanFreeze(false)`: матч никогда не заморожен, повтор обрывается кик-оффом (в тесте на 1.18 с из 8.03 с);
- **откат:** гол, найденный ещё раз на 3 тика позже после отката, даёт одну камеру на взрыв; кольцо хранит линию времени после отката;
- **камеры:** облёт непрерывен и не выходит за арену, начинается за воротами оранжевых и кончается за воротами синих лицом к полю; камера на взрыв смотрит на ворота (косинус > 0.97) со стороны поля, камера итогов крутится вокруг победителей, а не проигравших; смешение камер начинается на первой и кончается на второй;
- **`RlFeedback` в повторе:** события пройденных тиков играются снова (не подавляются живыми) и помечены `replay`, гол в повторе один, объявления (отсчёт, старт, вздох трибун, овертайм, конец) не повторяются; после `EndReplay` память живого матча вернулась (тот же гол не играется дважды).

## Ограничения

- Повтор не сохраняется на диск и не отправляется по сети: это 10 секунд памяти локального клиента.
- Камеры повтора простые (следящая, машина, сетка); подбор по траектории — по автору и положению в профиле, без анализа сцены.
- Звук в повторе: события тех же тиков, тише (`BeginReplay(gain)`), с питчем, зависящим от скорости воспроизведения; трибуны приглушены; зависимость громкости от замедления простая.
- Эффекты частиц идут в реальном времени, в замедлении их скорость не меняется.
- Онлайн без большого `goalSeconds` повтор обрывается кик-оффом (см. выше).
