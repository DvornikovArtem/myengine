# Rocket Arena: лобби (G6a)

Сервис лобби — то, что вызывает экран Private match (G1-flow): где игроки находят друг друга, видят состав, готовность и стартуют матч. Матч дальше идёт обычным `RlNetHost`/`RlNetClient` (`docs/game/rl-netcode.md`). Заголовки: `game/rl/include/rl/net/LobbyService.h` (интерфейс), `LobbyLan.h`, `LobbySteam.h`; код — `game/rl/src/net/LobbyLan.cpp`, `LobbySteamStub.cpp`, `steam/*`; тест — `rl_net` (`ctest -R rl_net`).

## Интерфейс (`rl::net::ILobbyService`)

Один интерфейс на LAN и Steam; вызывается раз в кадр `Update(now)` и читается `TakeEvents()`. Ничего не блокирует и не бросает исключений: ошибка — в `std::string error` или в событии `Error`.

| Что | Вызовы |
| --- | --- |
| Хост | `Create({hostName, mode, maxPlayers, lobbyPort, gamePort, friendsOnly})`, `InviteText()` (LAN: адрес `ip:порт` лобби, который друг вводит руками; IP — интерфейса, с которого уходит широковещательный маяк, `LocalIPv4Address()`), `InviteFriends()` (Steam: оверлей), `StartMatch(error)` — отказывает, пока кто-то не готов |
| Гость | `RefreshList()` → `Lobbies()` (id, имя хоста, режим, игроки/мест, ping, `joinable` + `note`: другая версия, лобби полное, матч уже идёт), `Join(id)` или `Join("192.168.1.5:47778")` вручную, `SetReady(bool)` |
| Состояние | `State()` (Idle, Creating, Hosting, Joining, Joined, Starting, Failed), `Members()`, `Current()`, `StartInfo()`, `LastError()`, `Leave()` |
| События | Created, Joined, MemberJoined, MemberLeft, MemberChanged, ListUpdated, MatchStarting, HostLeft, InviteReceived, Error |
| Матч | `CreateMatchTransport(sim)`: UDP в LAN, `SteamTransport` в Steam; `StartInfo()` = {isHost, hostAddress, gamePort, mode, members} |

Порядок на экране Private match: хост `Create` → показывает состав → когда все готовы `StartMatch` → на `MatchStarting` создаёт `RlNetHost` на `CreateMatchTransport`, `Listen(info.gamePort)`; гость на `MatchStarting` делает `RlNetClient` на своём `CreateMatchTransport` и `Connect(info.hostAddress)`. Гости входят в уже идущий матч (подключение посреди матча из G4f, слоты ботов), хост может подождать, пока `RlNetHost::ClientCount()` сравняется с числом членов лобби.

## LAN-лобби

- **Маяк.** Хост раз в 1 с рассылает датаграмму по `255.255.255.255:47779` (`'R' 'L' 1`, версия, режим, мест, игроков, флаг «матч идёт», порт лобби, имя). Гость (`RefreshList`) слушает этот порт (общий `SO_REUSEADDR`, поэтому два окна на одном ПК не мешают друг другу), собирает записи, через 4 с без маяка запись пропадает.
- **Ping.** На первый маяк и затем раз в 2 с гость шлёт хосту `Ping` (на адрес, откуда пришёл маяк), хост отвечает `Pong` с тем же числом; в списке — время круга. (Steam ping до входа в лобби не даёт: у записей Steam `pingMs = -1`.) Список Steam собирается из двух источников: публичный поиск `RequestLobbyList` (фильтр `rl_game=1`) и лобби друзей по присутствию (`GetFriendGamePlayed`): лобби «только для друзей» поиск не возвращает.
- **Лобби** — надёжное соединение (тот же `ReliableTransport`, что у матча) гостя к порту лобби хоста `47778`: `Hello` (версия, имя) → `Welcome` или `Reject` (другая версия, полное, матч идёт; соединение живёт ещё 0.6 с, чтобы отказ дошёл) → `Members` всем при любом изменении, `Ready`, `Rename`, `Start{gamePort}`. Ушедший гость (или потерявшийся по таймауту) пропадает из состава у всех; хост закрыл лобби — гости получают `HostLeft`.
- Порты: `47778` лобби, `47779` маяк, `47777` матч (`kDefaultLobbyPort`, `kLanBeaconPort`, `kDefaultGamePort`).
- Ручной вход по `ip[:порт]` остаётся (`Join("192.168.0.160")` добавит порт лобби).

## Steam

`SteamLobbyService` и `SteamTransport` под `MYENGINE_STEAM` (по умолчанию OFF; `docs/game/steam-setup.md`: как включить, что проверено на одном аккаунте и как проверить вдвоём). В сборке без SDK `MakeSteamLobbyService()` возвращает сервис, у которого `Available(whyNot)` говорит «в этой сборке нет Steam», поэтому экран может предлагать Steam без `#ifdef`. `FindConnectLobbyInCommandLine` разбирает `+connect_lobby <id>` и работает без SDK.

## Ник игрока (G1n)

Со Steam имя игрока везде — **имя профиля Steam** (`ISteamFriends::GetPersonaName`, функция `rl::net::SteamPersonaName` в `LobbySteam.h`), править его в игре нельзя. Без Steam (сборка без `MYENGINE_STEAM`, клиент не запущен, пустое имя) игрок вводит свой ник сам: Settings → PLAYER, поле «Player name» (2–16 символов: латиница, кириллица, цифры, пробел и `. _ -`; пробелы по краям обрезаются, пустой и из одной буквы не принимается; в слот матча влезает 32 байта: ровно 16 кириллических букв); ник сохраняется сразу в `game_settings.json` (`play.playerName`), по умолчанию — имя пользователя Windows, иначе «Player». Со Steam то же поле показывает ник профиля с подписью «FROM STEAM» и не редактируется. Источник один, `RlGameSettings::PlayerName()`, порядок: переменная окружения `MYENGINE_PLAYER_NAME` (тесты и две копии игры на одном ПК: у них один профиль Steam), имя Steam, введённый ник `play.playerName` из `game_settings.json`, пользователь Windows. Им пользуются все места: данные участника лобби LAN и Steam, `Join` сетевого матча (имя слота), главное меню (плашка справа вверху), таблица Tab, лента, GOAL!, итоги, MVP, тренировка.

Чистка имени — `rl::SanitizePlayerName` (`game/rl/include/rl/RlName.h`), одна на все пути: знак без глифа в атласе кита (эмодзи, CJK, не-UTF-8; диапазоны те же, что `kRangesFull` в `RlUiFonts.cpp`: латиница, кириллица, несколько знаков) становится «?», управляющие символы убираются, пробелы по краям обрезаются, длина — не больше 32 байт (слот матча `kNameBytes` = 33 с нулём; было 24), символ посередине не режется. Чистятся и имена, пришедшие по сети (маяк и состав LAN-лобби, участники Steam-лобби, слоты матча), поэтому чужой ник с эмодзи не рисуется «тофу». `Join` раньше нёс 15 байт и резал кириллицу посередине: теперь 32. `kNameBytes` поднят с 24 до 33, поэтому версия сетевого протокола 3 (`kNetProtocolVersion`) и версия протокола лобби LAN 2: клиент и хост с разными версиями друг друга отклоняют. Имя стола лежит в состоянии матча (откат, повтор — кольцо `RlWorldState` в памяти, поздний вход), снимки состояния имён не несут: имена идут отдельным сообщением `Names`, проверено тестом позднего входа с 16-буквенным ником.

## Экраны (G1-lobby)

Код: `engine/src/game/RlLobbyScreens.{h,cpp}` (экраны и выбор игрока), подключение — `RlGameFlow` (вкладка Private match экрана Play, экран Room, переход в лобби матча G5). Матч стартует на транспорте сервиса: `RlGameMatchSetup::transportFactory` (хост: `RlNetHost` + `Listen`, гость: `RlNetClient` + `Connect(info.hostAddress)`); система вызывает фабрику один раз и забывает её.

- **Переключатель LAN / Steam.** LAN работает всегда. Steam нужен собранный с `MYENGINE_STEAM` и запущенный клиент Steam: в такой сборке сервис Steam поднимается при запуске игры (чтобы приглашения друзей доходили в главном меню), иначе подпись красным объясняет причину (`Available(whyNot)`: «в этой сборке нет Steam» / «клиент Steam не запущен»).
- **Список.** LAN слушает маяки сам (после первого `RefreshList`), Steam опрашивается раз в 6 с и кнопкой Refresh. Строка: имя хоста, `2v2 · 2/4 · 12 ms`, пометка, если войти нельзя.
- **Создание.** Create lobby: размер команды, «Fill with bots», порт матча (LAN). Лобби Steam всегда «только для друзей».
- **Комната.** Состав и готовность; хост — приглашение и Start, гость — готовность. Старт: сервис шлёт `MatchStarting`, комната возвращает флоу `RlGameMatchSetup`, флоу запускает матч G5 и показывает его лобби; хост стартует сам, когда пришли все игроки комнаты (или через 12 с).
- **Приглашения.** `InviteReceived` (друг принял приглашение в запущенной игре) и `+connect_lobby <id>` (Steam запустил игру по приглашению) открывают комнату с `Join(id)`. При ошибке — панель с причиной. Разбор аргументов `app/src/main.cpp` пропускает `+connect_lobby <id>` (раньше любой неизвестный ключ показывал окно «Usage» и игра не стартовала).
- **Закрытие.** Пока идёт матч, лобби живёт в состоянии `Starting`; выход в меню (Leave, Results → Main menu) закрывает его (`Leave`). Выход на главное меню останавливает поиск LAN.

## Что проверено в G1-lobby

Живьём (два окна `myengine --game` на этом ПК, скрипты и скриншоты — `.team/tasks/g1l-evidence/`): LAN — хост создаёт лобби, гость видит его в списке (пинг ~30–45 мс), входит, жмёт «I am ready», хост жмёт Start match; оба окна уходят в лобби матча G5 и в матч (хост играет синей командой, гость оранжевой, на экране гостя пинг). Steam на одном аккаунте — Network → Steam, Create lobby, комната с Invite friends; во втором окне тот же аккаунт видит лобби в списке «Lobbies of your friends» (по присутствию). Ошибки панелью: «the host of the lobby does not answer» (вход на адрес, где нет хоста), «cannot enter the lobby» (`+connect_lobby` с несуществующим id). Не проверено: два разных аккаунта Steam, оверлей приглашений в окне, игра двух ПК по LAN.

## Что проверено

`rl_net` (778 проверок): параметры `--net-sim`; LAN-лобби на loopback-сети с виртуальным часом (маяк → список с ping → вход по записи → состав → готовность → старт → и сам матч на транспортах сервисов: 0 жёстких поправок), полное лобби, другая версия, ручной вход, уход гостя, исчезновение записи, уход хоста, молчащий хост (отказ с текстом); **то же по настоящему UDP на этом ПК** (маяк по broadcast дошёл, ping 3 мс); `FindConnectLobbyInCommandLine`; сервис Steam в сборке без SDK. Код Steam собирается против наброска `game/rl/steam_mock` (`-DMYENGINE_STEAM_CHECK=ON`, ни одной ошибки и предупреждения) и с настоящим SDK 1.65 (`MYENGINE_STEAM=ON`, без предупреждений); ручная проверка `myengine_rl_steam_smoke` на одном аккаунте прошла (steam-setup.md, раздел 6); игра двух аккаунтов **не проверялась**.

## Ограничения

- LAN: маяк идёт по IPv4-броадкасту стандартного интерфейса; в сети с изоляцией клиентов (гостевой Wi-Fi) или при брандмауэре, режущем UDP 47779, список пуст — тогда остаётся ввод адреса вручную.
- Состав лобби и готовность не защищены от подделки (LAN-доверие).
- В списке нет сортировки по версиям кроме «играбельные выше», нет пароля у лобби.
