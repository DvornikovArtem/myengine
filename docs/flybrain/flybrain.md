# Мозг мухи: коннектом MaleCNS v1.0 и LIF-симуляция (N0, N0b, FlyDoom)

Модуль `game/flybrain` загружает коннектом самца дрозофилы и симулирует его моделью leaky integrate-and-fire (LIF) из статьи Shiu et al. 2024 на CPU через job system движка или на GPU compute-шейдерами DX12 (раздел [GPU](#gpu-n0b)) — с одними и теми же спайками. От DOOM модуль не зависит: подключение мозга к игре (глаза → сенсорные нейроны, нисходящие нейроны → управление) — следующие задачи (N1, D1).

**Это не настоящая муха.** Это сеть точечных LIF-нейронов, связанная по карте синапсов: знак синапса взят из предсказанного медиатора, вес — число контактов, нет дендритов, рецепторов, нейромодуляции, тела и мышц. Так же честно пишут авторы DOOMFLY: «connectome-constrained LIF simulation drives an engineered interface».

## Формат `.fbrain` (версия 1)

Little-endian, один файл читается целиком одним `read` (≈ 160 МБ), массивы используются на месте, без копирования. Описание в коде: [`game/flybrain/src/FbrainFormat.h`](../../game/flybrain/src/FbrainFormat.h); конвертер пишет то же самое.

- `FileHeader` (40 байт): `"FLYBRAIN"`, версия, число секций, нейронов, строк, рёбер, типов.
- Таблица секций: 8-символьный тег, смещение, размер; каждая секция выровнена на 16 байт.

| Тег | Тип | Что |
| --- | --- | --- |
| `ATTRIB` | UTF-8 | датасет, цитата, лицензия, что изменено |
| `STROFFS`, `STRCHARS` | `uint32[S+1]`, байты | таблица строк (типы, классы, superclass); строка 0 — пустая |
| `BODYID` | `uint64[N]` | bodyId по возрастанию (`FindBodyId` — двоичный поиск) |
| `TYPE`, `CLASS`, `SUPERCLS` | `uint32[N]` | номера строк |
| `SIDE`, `NT` | `uint8[N]` | сторона (`somaSide`, иначе `rootSide`), медиатор |
| `HEX1`, `HEX2` | `int16[N]` | колонка оптической доли `assignedOlHex1/2`, `INT16_MIN` — нет |
| `POS` | `float[3N]` | позиция сомы (или другой точки тела), для 3D-облака |
| `ROWSTART` | `uint32[N+1]` | CSR по пресинаптическому нейрону |
| `TARGETS` | `uint32[E]` | постсинаптический нейрон, по возрастанию внутри строки |
| `WEIGHTS` | `int16[E]` | контакты × знак (обрезаются до ±32767; в MaleCNS обрезанных нет — проверяет тест) |
| `TYPENAME`, `TYPESTRT`, `TYPENEUR` | `uint32` | группы по типу: типы по алфавиту, нейроны каждого типа |

Загрузчик проверяет всё, что индексирует другие массивы (смещения CSR, цели рёбер, номера строк, группы типов); битый или обрезанный файл не читается.

## Модель

Нейрон (Shiu et al. 2024, `model.py`, `default_params`), `u = v − v_0`:

```
du/dt = (I − u + g) / t_mbr        (кроме рефрактерного периода)
dg/dt = −g / tau                   (кроме рефрактерного периода)
u > v_th − v_0  →  спайк; u = v_rst − v_0, g = 0; рефрактерность t_rfc
спайк нейрона j добавляет w_syn · weight(j→i) к g каждого i через t_dly
```

| Параметр | Значение | Откуда |
| --- | --- | --- |
| `v_0`, `v_rst` | −52 мВ | Kakaria & de Bivort 2017 (по Шиу) |
| `v_th` | −45 мВ | там же |
| `t_mbr` | 20 мс | там же |
| `tau` | 5 мс | Jürgensen et al. |
| `t_rfc` | 2,2 мс (22 шага) | Lazar et al. 2021 |
| `t_dly` | 1,8 мс (18 шагов) | Paul et al. 2015 |
| `w_syn` | 0,275 мВ на контакт | свободный параметр Шиу |
| Пуассоновский вход | событие добавляет `w_syn · 250 = 68,75` мВ к v; у стимулируемых нейронов `t_rfc = 0`; случайность — 32-битный хеш (нейрон, шаг, зерно), один и тот же на CPU и GPU | Шиу |
| `dt` | 0,1 мс | шаг Brian2 по умолчанию; так же у DOOMFLY |
| `I` | внешний ток (мВ), 0 по умолчанию | наше расширение: тонический ток в ламину, как в DOOMFLY |

Интегрирование точное: система линейная, решение на шаг — `u ← I + (u − I)·a + g·c`, `g ← g·b`, где `a = e^(−dt/t_mbr)`, `b = e^(−dt/tau)`, `c = tau/(tau − t_mbr)·(b − a)`. Порядок внутри шага как в Brian2: обновление состояния → порог → синаптический (и пуассоновский) вход → сброс. Отсюда два следствия, которые легко пропустить:

- вход, пришедший на шаге спайка, теряется (сброс идёт после входа);
- вход, пришедший в рефрактерный период, тоже теряется: Brian2 «замораживает» переменные рефрактерного нейрона.

Оба правила проверены на Brian2 2.11 с уравнениями Шиу (`method="linear"`): одиночный нейрон, цепочка, вход в рефрактерный период и случайные сети на 150 и 400 нейронов совпадают **спайк в спайк**. Тест `flybrain` сверяет нашу реализацию с записанными спайками Brian2 (`tests/flybrain/BrianGolden.h`, генератор `tools/flybrain/brian_golden.py`). Вариант «вход в рефрактерности копится в g» с Brian2 не совпадает (80 спайков против 63 в том же опыте).

Модель задаётся `flybrain::ModelParams`; значения по умолчанию — Шиу.

## Параллельная схема

Спайк нейрона на шаге `s` доходит до целей на шаге `s + 18`. Значит, внутри окна из 18 шагов (1,8 мс) нейроны друг от друга не зависят:

1. **Нейроны.** Нейроны делятся на куски по 4096, каждый кусок — задача job system (`jobs::Dispatch`). Внутри куска — блоки по 512: активные нейроны блока упаковываются в массивы (состояние ≈ 20 КБ, в L1), и окно идёт по времени снаружи, по нейронам внутри. Шаг считается по 4 нейрона одной инструкцией AVX2 (выбирается во время выполнения по `cpuid`; без AVX2 — скалярный код, результат бит в бит тот же, это проверяет тест). Вход нейрон читает из кольца `arrivals[шаг % 18][нейрон]` и обнуляет его. Спайки куска — в свой список.
2. **Доставка.** Спайки окна сортируются по слоту (шагу) и делятся на части по числу рёбер (≈ 4 части на поток), каждая часть — задача. Для каждого ребра — целочисленный атомик `_InterlockedExchangeAdd` числа контактов в `arrivals[s % 18][цель]` и флаг «есть вход». Слот уже прочитан в этом окне, поэтому запись не мешает чтению; один слот — это 4 байта × 164 789 = 0,66 МБ, так что запись спайков одного шага идёт в пределах L2. Множитель 0,275 мВ применяется, когда нейрон забирает вход.

Синхронизация — два `jobs::Wait` на окно (≈ 556 раз за секунду модели), а не на каждом шаге. Целые суммы не зависят от порядка, поэтому результат **бит в бит одинаков** при любом числе потоков (проверяет тест). Окно короче 18 шагов тоже допустимо (`AdvanceMs(28.57)` для тика DOOM — 285 или 286 шагов): вход его поздних шагов ждёт следующего окна.

**Спящие нейроны.** Без входа нейрон не может дойти до порога, если `u ≤ θ`, `I ≤ θ` и `I + g ≤ θ` (u стремится к `I + g(t)`, а `g(t)` монотонно уходит к 0) — граница точная, а не отсечение по активности. Такой нейрон «спит»: окно его пропускает, а когда приходит вход (или меняется ток), состояние догоняется аналитически за `k` шагов (`a^k`, `b^k` из таблицы до 4096 шагов, дальше — умножения на `a^4096`, `b^4096`, чтобы GPU получил те же биты). Так же делает DOOMFLY. Тест сравнивает эту схему с прямым пошаговым счётом всех нейронов.

Состояние нейрона — `double`, как в Brian2: во `float` спайк у самого порога сдвигался на шаг (на тестовой сети — 1 спайк из 459).

## GPU (N0b)

Тот же мозг считается на видеокарте compute-шейдерами DX12 (`game/flybrain/src/FlyBrainGpu.*`, шейдер [`assets/shaders/flybrain.hlsl`](../../assets/shaders/flybrain.hlsl)). CPU остаётся эталоном: **на GPU получаются те же спайки, бит в бит** — на синтетике, при переключении бэкендов посреди прогона и на настоящем MaleCNS (тест `flybrain_gpu`).

**Окно на GPU** (то же окно ≤ 18 шагов, что на CPU):

| Ядро | Потоки | Что делает |
| --- | --- | --- |
| `CSUpdate` | по изменению | стимулы и токи, изменившиеся с прошлого окна: догон нейрона под старым током, затем новые параметры (как `Wake` на CPU) |
| `CSCompact` | по нейрону | нейроны со входом или способные выстрелить — в плотный список (≈ 20 % мозга); один глобальный атомик на группу |
| `CSIntegrate` | по нейрону списка | шаги окна в `double`, вход из кольца `[шаг % 18][нейрон]`, Пуассон, спайки — в список окна, в кольцо спайков для визуализации и в счётчики наблюдений по шагам |
| `CSDeliver` | 512 групп × 64 | спайки окна по CSR: `InterlockedAdd` целых контактов в кольцо входа, флаг «есть вход» |
| `CSReset` | раз на отправку | обнуляет счётчики отправки (кольцо спайков продолжает счёт) |

Между ядрами — UAV-барьеры; `jobs::Wait` на CPU соответствует барьеру на GPU. Привязка — root-дескрипторы буферов (CBV модели, 8 констант окна, 6 SRV, 10 UAV), без куч дескрипторов. Шейдер компилирует наш `ShaderCompiler` из ЛР3 (fxc, `cs_5_0`, сообщения с файлом и строкой); root signature собрана вручную: `RootSignatureBuilder` ЛР3 знает только CBV и таблицы текстур, а здесь нужны UAV-буферы.

**Почему совпадает бит в бит.** Целые суммы контактов не зависят от порядка атомиков; всё остальное — те же операции в том же порядке:
- состояние и арифметика — `double`, как на CPU (буферы хранят `uint2`, `asdouble`/`asuint`; `precise` запрещает перестановки и FMA); нужна поддержка double в шейдерах (`DoublePrecisionFloatShaderOps`), иначе бэкенд не включается;
- константы модели (`a`, `b`, `c`, `K`, вес, порог) и таблицы степеней `a^k`, `b^k` считает CPU и передаёт битами; догон дальше 4096 шагов на обоих — умножения на `table[4096]`, а не `exp` (для этого CPU-код догона переписан так же);
- генератор Пуассона на обоих — 32-битный хеш (lowbias32): в SM 5.0 нет 64-битных целых. Шаги на GPU 32-битные — хватает на 119 часов модели;
- вход `int → float → double` точен для целых меньше 2²⁴, как `int → double` на CPU.

**Асинхронность.** У бэкенда своя compute-очередь. `Advance` / `AdvanceMs` только записывают окна в командный список и отправляют его — без ожидания (до 256 окон или 4096 шагов на отправку, 3 отправки в полёте). Счётчики наблюдений возвращаются через readback-буфер, когда GPU закончит: `CompletedStep()` — до какого шага они известны, `SpikeCount` / `RateHz` / `TotalSpikes` считают по этот шаг. Игра вызывает `AdvanceMs(28.57)` на тик и читает выходы предыдущего тика (задержка — одна отправка, то есть один тик DOOM, если вызывать по окну — одно окно); `Poll()` забирает готовое без ожидания, `Synchronize()` ждёт всё. Запросы отдельных нейронов (`VoltageMv`, `NeuronSpikeCount`, `AwakeCount`, `RecentSpikes`) на GPU синхронные: ждут GPU и читают состояние обратно — для тестов и отладки, не для кадра.

**Спайки для `BrainView` (V0).** `GetGpuSpikeRing()` отдаёт буфер `uint2 (нейрон, шаг) × capacity` (степень двойки, ≥ `SetSpikeRingCapacity`), счётчик записанных спайков `counters[0]` (следующий индекс — `counters[0] & (capacity − 1)`) и `lastSpikeStep` — `uint` на нейрон, шаг его последнего спайка (`0xFFFFFFFF` — не было; возраст = `(CompletedStep() − шаг) · dt`): его можно подключить к рендеру как `StructuredBuffer<uint>` на нейрон. Всё — на устройстве мозга. Между отправками буферы в состоянии `COMMON`; графическая очередь перед чтением ждёт `fence ≥ fenceValue`. Чтобы рисовать без копии на CPU, мозг должен считаться на устройстве рендера: `GpuOptions::device = adapter.GetDevice()`.

**Выбор бэкенда.**

```cpp
flybrain::BackendChoice choice = flybrain::BackendChoice::Auto;
flybrain::ParseBackendChoice(flagValue, choice);           // --flybrain auto|cpu|gpu
flybrain::GpuOptions options;
options.device = renderDevice;                             // null: свой device (самый быстрый адаптер с double)
std::string error;
if (brain.SetBackend(choice, options, &error) != flybrain::Backend::Gpu)
{
    log("fly brain on the CPU: " + error);                 // нет DX12, нет double, не прошла самопроверка
}
```

`Auto` берёт GPU, если устройство есть, double поддерживаются и проходит самопроверка (сеть из 300 нейронов с током и Пуассоном, 2000 шагов: спайки GPU = CPU), иначе остаётся на CPU. Бэкенд можно сменить на любом шаге: состояние целиком переезжает (выгрузка/загрузка буферов). На GPU счётчики ведут первые 32 наблюдения (`Watch`). Несколько мух на одном устройстве делят CSR коннектома (154 МБ), своё у каждой — ≈ 29 МБ.

## API

```cpp
#include <flybrain/FlyBrain.h>

std::string error;
auto connectome = flybrain::Connectome::Load(path, &error);       // nullptr + error, если файла нет или он битый
flybrain::FlyBrain brain(connectome);                               // ModelParams по умолчанию = Шиу
brain.SetParallel(true);                                            // окна — задачи job system (jobs::Initialize уже вызван)

flybrain::Group dnLeft = connectome->Find("DNa02", flybrain::Side::Left);
flybrain::Group retina = connectome->Find("R1-R6");
flybrain::Group r7 = connectome->FindPrefix("R7");                  // R7d, R7p, R7y, ...

brain.StimulateCurrent(connectome->Find("L1"), 12.0f);              // ток, мВ, бессрочно
auto id = brain.StimulateRate(retina, 30.0f, 200.0f);               // Пуассон 30 Гц на 200 мс
brain.SetDrive(neuron, mv);                                         // ток одного нейрона (фоторецептор каждый кадр)

auto watch = brain.Watch(dnLeft);                                   // счёт спайков группы по шагам
brain.AdvanceMs(1000.0 / 35.0);                                     // тик DOOM: 285 или 286 шагов
float hz = brain.RateHz(watch, 100.0f);                             // частота на нейрон за последние 100 мс
uint64_t n = brain.SpikeCount(watch, 28.57f);

std::vector<flybrain::SpikeEvent> spikes;
brain.RecentSpikes(spikes, 4096);                                   // последние спайки (кольцо) для растра и 3D
float v = brain.VoltageMv(neuron);
```

| Класс | Что |
| --- | --- |
| `Connectome` | неизменяемый граф и аннотации: `Load`, `FromImage`, `Find(type, side)`, `FindPrefix`, `FindSuperclass`, `FindBodyId`, `Info`, `Position`, `Hex1/2`, CSR (`RowStart`, `Targets`, `Weights`). Один коннектом на сколько угодно симуляций |
| `ConnectomeBuilder` | граф в коде (тесты, маленькие схемы для мух-врагов): `AddNeuron`, `AddEdge`, `Build` (образ файла), `Save` |
| `FlyBrain` | состояние и симуляция: стимулы (`StimulateRate`, `StimulateCurrent`, `StopStimulus`, `SetDrive`), `Advance(steps)` / `AdvanceMs`, выходы (`Watch`, `SpikeCount`, `RateHz`, `RecentSpikes`, `VoltageMv`), `Stats()`; бэкенд (`SetBackend`, `GetBackend`, `CompletedStep`, `Poll`, `Synchronize`, `GetGpuSpikeRing`, `GpuMemoryBytes`) — раздел [GPU](#gpu-n0b) |

Окно никогда не пересекает конец стимула, поэтому длительность стимула точна до шага.

## Проверки

| Тест | Что проверяет |
| --- | --- |
| `flybrain` (всегда, синтетические графы) | образ `.fbrain`: запись, чтение, поиск, битый файл; частота нейрона при постоянном токе против аналитической LIF `f = 1/(t_ref + t_mbr·ln(I/(I−θ)))` и против дискретной формулы; рефрактерность (22 шага); задержка 1,8 мс по цепочке и торможение; Пуассон 150 Гц → ~150 Гц; 459 спайков Brian2 один в один; событийная схема против пошагового эталона; бит в бит на 1 потоке и на job system; окна короче задержки |
| `flybrain_connectome` (код 77 без файла, ≈ 1 мин) | 164 789 нейронов / 25 563 197 рёбер / 124 025 046 контактов, ни один вес не обрезан; численности типов среди вычитанных (R1–R6 L 501 / R 893, DNa01/DNa02/DNp09/DNp01 по 1 на сторону, MDN 4, LPLC2 185, LC4 126, PPL101 2, MN9 2, L1 1776); известные bodyId (PPL101 11327/11900, MBON11 10704/11402); колонки у L1; тишина без входа; вкус → MN9 (хоботок, как у Шиу): каждый из 36 вкусовых типов на 150 Гц, LB3c (сахар у DOOMFLY) даёт MN9 > 20 Гц (78 Гц), а часть типов MN9 не трогает (LB2c, LB2d, PhG2, PhG3, PhG7, PhG8 — 0 Гц) |
| `flybrain_gpu` (код 77 без DX12-адаптера с double; WARP, если нет видеокарты; ≈ 5 с) | бэкенд создаётся, самопроверка `Auto` проходит, `--flybrain` разбирается; синтетика 40 000 нейронов с токами, Пуассоном, стимулом, который кончается посреди окна, сменой токов каждый тик и тиками DOOM 28,57 мс — **те же спайки, что на CPU (все 51 234, шаг в шаг)**, те же счётчики каждого нейрона, наблюдений и мембранные потенциалы бит в бит; CPU → GPU → CPU посреди прогона = прогон на CPU; `Advance` не ждёт GPU (`CompletedStep` отстаёт до `Synchronize`); на MaleCNS — 300 мс зрения, 85 073 спайка, те же, что на CPU |

Частота при постоянном токе (вывод теста `flybrain`):

| Ток I, мВ | Модель, Гц | Аналитическая LIF, Гц | Разница |
| --- | --- | --- | --- |
| 6 и 7 | 0 | 0 (I ≤ θ = 7 мВ) | — |
| 7,5 | 17,76 | 17,74 | +0,11 % |
| 8 | 22,88 | 22,84 | +0,20 % |
| 10 | 38,17 | 38,05 | +0,30 % |
| 15 | 68,03 | 67,69 | +0,49 % |
| 20 | 92,59 | 92,46 | +0,14 % |
| 30 | 133,33 | 133,08 | +0,19 % |
| 50 | 192,31 | 191,70 | +0,32 % |

Модель чуть быстрее непрерывной формулы, потому что порог проверяется раз в шаг, а рефрактерный период дискретный (21 замороженный шаг после спайка, правило Brian2): период короче аналитического не больше чем на `dt`. Период в шагах тест сверяет и с точной дискретной формулой `n + 21`, где `n` — первое целое с `I·(1 − a^n) > θ`.

## Скорость относительно реального времени

**Итог GPU (N0b):** одна муха — 6,1× реального времени, четыре одновременно — по 1,8–1,9×, худший случай («раскачка») — 1,4× для одной; таблица — [ниже](#gpu-против-cpu-n0b-malecns-v10).

**Итог CPU (N0):** MaleCNS целиком (164 789 нейронов) с тоническим током в ламину и пуассоновским входом в R1–R6 на 20–50 Гц идёт на 8 потоках со скоростью **0,92–0,96× реального времени**, на 4 потоках 0,66×, на одном 0,21–0,30×; память — 154 МБ образ + 21 МБ состояние. До реального времени не хватает нескольких процентов, поэтому режим «DOOM ждёт мозг» нужен (заложен в D0/N1); узкое место и что с ним делать — ниже.

Бенчмарк `myengine_flybrain_bench` (не в ctest, минуты), методика ЛР1: прогон для прогрева, затем 3 прогона, медиана; каждый прогон — новый мозг, 0,2 с модели на разгон и 1 с модели под замер. Скорость = секунды модели / секунды на стене (1,0 = реальное время).

```
build/tests/RelWithDebInfo/myengine_flybrain_bench.exe                 # настоящий коннектом (код 77, если файла нет)
build/tests/RelWithDebInfo/myengine_flybrain_bench.exe --synthetic     # случайный граф того же размера
    [--threads 1,2,4,8] [--scenarios silent,rest,vision20,vision50] [--repeats 3] [--seconds 1] [--warmup 0.2]
    [--probe <тип>|rest|vision20]                                        # спайки по суперклассам за 1 с
```

Сценарии (по базовой схеме DOOMFLY): `silent` — без входа; `rest` — тонический ток 12 мВ в L1/L2/L3/L5 (без него ламина молчит); `vision20` / `vision50` — плюс пуассоновский вход во все R1–R6 на 20 / 50 Гц. На синтетическом графе ток получают 5 % нейронов, пуассоновский вход — 2 %. Потоки: 1 — без job system, N — `jobs::Initialize(N − 1)` плюс главный поток, который тоже берёт задачи в `Wait`.

У Шиу на FlyWire (только мозг, другой отбор и знаки) активность остаётся разреженной. Для N1 это значит: вкусовые и другие сильные входы в центральный мозг нужно дозировать и проверять на «разгон»; кандидаты на причину — знак +1 у модуляторов и неясных медиаторов и рекуррентные петли VNC/центрального мозга, которых нет во FlyWire.

### GPU против CPU (N0b), MaleCNS v1.0

Пик рабочего набора бенчмарка 1,1 ГБ — это построение синтетического графа в памяти (`ConnectomeBuilder`), загрузка готового файла его не требует.

**Узкое место** (и на MaleCNS, и на синтетике) — шаги нейронов, а не синапсы: 80 % времени на MaleCNS, 75 % на синтетике. При зрительном входе за окно (1,8 мс) вход получают ≈ 35 тыс. нейронов MaleCNS (≈ 100 тыс. на синтетике), и каждый проходит все 18 шагов (≈ 3 нс на нейрон-шаг на одном ядре с AVX2), хотя почти никто из них до порога не дойдёт. Доставка — около пятой части (≈ 30 млн синапсов/с на MaleCNS). Что дальше:
- вариант на compute shader — сделан (N0b, раздел [GPU](#gpu-n0b)): 6× реального времени, спайки те же;
- на CPU — обрабатывать нейрон, который получил вход, но заведомо не дойдёт до порога (та же граница `I + g ≤ θ` с учётом входа окна), аналитически по моментам прихода входа, а не 18 шагами;
- для игры уже заложен режим «DOOM ждёт мозг» (D0/N1), как у DOOMFLY: детерминированно, но медленнее реального времени, если мозг не успевает.

Как оптимизировалась схема (vision20, 8 потоков, та же нагрузка машины): первая версия 0,23× → раскладка кольца `[слот][нейрон]` и доставка по слотам → блоки по 512 нейронов «время снаружи» → AVX2 → 0,37–0,49×. Доставка подешевела с ≈ 70 нс до ≈ 10 нс на синапс (запись в пределах слота 0,7 МБ вместо случайной по 12 МБ).

## Ограничения

- Это LIF по карте связей, а не муха (см. начало). Знаки по предсказанному медиатору; модуляторы (дофамин, октопамин, серотонин) считаются возбуждающими, как у DOOMFLY.
- У мухи фоторецепторы и ламина градуальные, а не спайковые; в LIF их приходится «подкармливать» тоническим током (12 мВ в L1/L2/L3/L5 у DOOMFLY), без него ламина молчит.
- Догон спящего нейрона в замкнутой форме округляется иначе, чем пошаговый счёт Brian2; спайк, попавший в пределы ошибки округления (~1e-15 мВ) от порога, может сдвинуться на шаг. На тестовых сетях расхождений нет.
- MaleCNS не говорит, какие вкусовые нейроны сладкие, а какие горькие: тест проверяет «LB3c → MN9» (сахар у DOOMFLY) и избирательность, а не «сахар против горького».
- Вкусовой вход раскачивает центральный мозг в самоподдерживающийся режим (см. замеры) — это свойство модели на этом графе, а не ошибка счёта (модель совпадает с Brian2), но для игры его придётся учитывать.
- Пластичности (обучения) нет; подкрепление из DOOMFLY (ток в PPL101) — задача N1.
- GPU-бэкенду нужны double в compute-шейдерах (есть у видеокарт NVIDIA/AMD/Intel с DX12, WARP тоже умеет); на GPU счётчики ведут первые 32 наблюдения, шаги 32-битные (119 часов модели).
