# Мозг мухи: коннектом MaleCNS v1.0 и LIF-симуляция (N0, N0b, N2, N3, N3b, FlyDoom)

Модуль `game/flybrain` загружает коннектом самца дрозофилы и симулирует его моделью leaky integrate-and-fire (LIF) из статьи Shiu et al. 2024 на CPU через job system движка или на GPU compute-шейдерами DX12 (раздел [GPU](#gpu-n0b)) — с одними и теми же спайками. От DOOM модуль не зависит: подключение мозга к игре (глаза → сенсорные нейроны, нисходящие нейроны → управление) — следующие задачи (N1, D1).

**Это не настоящая муха.** Это сеть точечных LIF-нейронов, связанная по карте синапсов: знак синапса взят из предсказанного медиатора, вес — число контактов, нет дендритов, рецепторов, нейромодуляции, тела и мышц. Так же честно пишут авторы DOOMFLY: «connectome-constrained LIF simulation drives an engineered interface».

## Формат `.fbrain` (версия 1)

Little-endian, один файл читается целиком одним `read` (≈ 160 МБ), массивы используются на месте, без копирования. Описание в коде: [`game/flybrain/src/FbrainFormat.h`](../../game/flybrain/src/FbrainFormat.h); конвертер пишет то же самое.

- `FileHeader` (40 байт): `"FLYBRAIN"`, версия, число секций, нейронов, строк, рёбер, типов.
- Таблица секций: 8-символьный тег, смещение, размер; каждая секция выровнена на 16 байт.

| Тег | Тип | Что |
| --- | --- | --- |
| `ATTRIB` | UTF-8 | датасет, цитата, лицензия, что изменено |
| `STROFFS`, `STRCHARS` | `uint32[S+1]`, байты | таблица строк (типы, классы, superclass); строка 0 — пустая |
| `BODYID` | `uint64[N]` | bodyId по возрастанию (`FindBodyId` — двоичный поиск) |
| `TYPE`, `CLASS`, `SUPERCLS` | `uint32[N]` | номера строк |
| `SIDE`, `NT` | `uint8[N]` | сторона (`somaSide`, иначе `rootSide`), медиатор |
| `HEX1`, `HEX2` | `int16[N]` | колонка оптической доли `assignedOlHex1/2`, `INT16_MIN` — нет |
| `POS` | `float[3N]` | позиция сомы (или другой точки тела), для 3D-облака |
| `ROWSTART` | `uint32[N+1]` | CSR по пресинаптическому нейрону |
| `TARGETS` | `uint32[E]` | постсинаптический нейрон, по возрастанию внутри строки |
| `WEIGHTS` | `int16[E]` | контакты × знак (обрезаются до ±32767; в MaleCNS обрезанных нет — проверяет тест) |
| `TYPENAME`, `TYPESTRT`, `TYPENEUR` | `uint32` | группы по типу: типы по алфавиту, нейроны каждого типа |

Загрузчик проверяет всё, что индексирует другие массивы (смещения CSR, цели рёбер, номера строк, группы типов); битый или обрезанный файл не читается.

## Модель

Нейрон (Shiu et al. 2024, `model.py`, `default_params`), `u = v − v_0`:

```
du/dt = (I − u + g) / t_mbr        (кроме рефрактерного периода)
dg/dt = −g / tau                   (кроме рефрактерного периода)
u > v_th − v_0  →  спайк; u = v_rst − v_0, g = 0; рефрактерность t_rfc
спайк нейрона j добавляет w_syn · weight(j→i) к g каждого i через t_dly
```

| Параметр | Значение | Откуда |
| --- | --- | --- |
| `v_0`, `v_rst` | −52 мВ | Kakaria & de Bivort 2017 (по Шиу) |
| `v_th` | −45 мВ | там же |
| `t_mbr` | 20 мс | там же |
| `tau` | 5 мс | Jürgensen et al. |
| `t_rfc` | 2,2 мс (22 шага) | Lazar et al. 2021 |
| `t_dly` | 1,8 мс (18 шагов) | Paul et al. 2015 |
| `w_syn` | 0,275 мВ на контакт | свободный параметр Шиу |
| Пуассоновский вход | событие добавляет `w_syn · 250 = 68,75` мВ к v; у стимулируемых нейронов `t_rfc = 0`; случайность — 32-битный хеш (нейрон, шаг, зерно), один и тот же на CPU и GPU | Шиу |
| `dt` | 0,1 мс | шаг Brian2 по умолчанию; так же у DOOMFLY |
| `I` | внешний ток (мВ), 0 по умолчанию | наше расширение: тонический ток в ламину, как в DOOMFLY |

Интегрирование точное: система линейная, решение на шаг — `u ← I + (u − I)·a + g·c`, `g ← g·b`, где `a = e^(−dt/t_mbr)`, `b = e^(−dt/tau)`, `c = tau/(tau − t_mbr)·(b − a)`. Порядок внутри шага как в Brian2: обновление состояния → порог → синаптический (и пуассоновский) вход → сброс. Отсюда два следствия, которые легко пропустить:

- вход, пришедший на шаге спайка, теряется (сброс идёт после входа);
- вход, пришедший в рефрактерный период, тоже теряется: Brian2 «замораживает» переменные рефрактерного нейрона.

Оба правила проверены на Brian2 2.11 с уравнениями Шиу (`method="linear"`): одиночный нейрон, цепочка, вход в рефрактерный период и случайные сети на 150 и 400 нейронов совпадают **спайк в спайк**. Тест `flybrain` сверяет нашу реализацию с записанными спайками Brian2 (`tests/flybrain/BrianGolden.h`, генератор `tools/flybrain/brian_golden.py`). Вариант «вход в рефрактерности копится в g» с Brian2 не совпадает (80 спайков против 63 в том же опыте).

Модель задаётся `flybrain::ModelParams`; значения по умолчанию — Шиу.

## Параллельная схема

Спайк нейрона на шаге `s` доходит до целей на шаге `s + 18`. Значит, внутри окна из 18 шагов (1,8 мс) нейроны друг от друга не зависят:

1. **Нейроны.** Нейроны делятся на куски по 4096, каждый кусок — задача job system (`jobs::Dispatch`). Внутри куска — блоки по 512: активные нейроны блока упаковываются в массивы (состояние ≈ 20 КБ, в L1), и окно идёт по времени снаружи, по нейронам внутри. Шаг считается по 4 нейрона одной инструкцией AVX2 (выбирается во время выполнения по `cpuid`; без AVX2 — скалярный код, результат бит в бит тот же, это проверяет тест). Вход нейрон читает из кольца `arrivals[шаг % 18][нейрон]` и обнуляет его. Спайки куска — в свой список.
2. **Доставка.** Спайки окна сортируются по слоту (шагу) и делятся на части по числу рёбер (≈ 4 части на поток), каждая часть — задача. Для каждого ребра — целочисленный атомик `_InterlockedExchangeAdd` числа контактов в `arrivals[s % 18][цель]` и флаг «есть вход». Слот уже прочитан в этом окне, поэтому запись не мешает чтению; один слот — это 4 байта × 164 789 = 0,66 МБ, так что запись спайков одного шага идёт в пределах L2. Множитель 0,275 мВ применяется, когда нейрон забирает вход.

Синхронизация — два `jobs::Wait` на окно (≈ 556 раз за секунду модели), а не на каждом шаге. Целые суммы не зависят от порядка, поэтому результат **бит в бит одинаков** при любом числе потоков (проверяет тест). Окно короче 18 шагов тоже допустимо (`AdvanceMs(28.57)` для тика DOOM — 285 или 286 шагов): вход его поздних шагов ждёт следующего окна.

**Спящие нейроны.** Без входа нейрон не может дойти до порога, если `u ≤ θ`, `I ≤ θ` и `I + g ≤ θ` (u стремится к `I + g(t)`, а `g(t)` монотонно уходит к 0) — граница точная, а не отсечение по активности. Такой нейрон «спит»: окно его пропускает, а когда приходит вход (или меняется ток), состояние догоняется аналитически за `k` шагов (`a^k`, `b^k` из таблицы до 4096 шагов, дальше — умножения на `a^4096`, `b^4096`, чтобы GPU получил те же биты). Так же делает DOOMFLY. Тест сравнивает эту схему с прямым пошаговым счётом всех нейронов.

Состояние нейрона — `double`, как в Brian2: во `float` спайк у самого порога сдвигался на шаг (на тестовой сети — 1 спайк из 459).

## GPU (N0b)

Тот же мозг считается на видеокарте compute-шейдерами DX12 (`game/flybrain/src/FlyBrainGpu.*`, шейдер [`assets/shaders/flybrain.hlsl`](../../assets/shaders/flybrain.hlsl)). CPU остаётся эталоном: **на GPU получаются те же спайки, бит в бит** — на синтетике, при переключении бэкендов посреди прогона и на настоящем MaleCNS (тест `flybrain_gpu`).

**Окно на GPU** (то же окно ≤ 18 шагов, что на CPU):

| Ядро | Потоки | Что делает |
| --- | --- | --- |
| `CSUpdate` | по изменению | стимулы и токи, изменившиеся с прошлого окна: догон нейрона под старым током, затем новые параметры (как `Wake` на CPU) |
| `CSCompact` | по нейрону | нейроны со входом или способные выстрелить — в плотный список (≈ 20 % мозга); один глобальный атомик на группу |
| `CSIntegrate` | по нейрону списка | шаги окна в `double`, вход из кольца `[шаг % 18][нейрон]`, Пуассон, спайки — в список окна, в кольцо спайков для визуализации и в счётчики наблюдений по шагам |
| `CSDeliver` | 512 групп × 64 | спайки окна по CSR: `InterlockedAdd` целых контактов в кольцо входа, флаг «есть вход» |
| `CSReset` | раз на отправку | обнуляет счётчики отправки (кольцо спайков продолжает счёт) |

Между ядрами — UAV-барьеры; `jobs::Wait` на CPU соответствует барьеру на GPU. Привязка — root-дескрипторы буферов (CBV модели, 8 констант окна, 6 SRV, 10 UAV), без куч дескрипторов. Шейдер компилирует наш `ShaderCompiler` из ЛР3 (fxc, `cs_5_0`, сообщения с файлом и строкой); root signature собрана вручную: `RootSignatureBuilder` ЛР3 знает только CBV и таблицы текстур, а здесь нужны UAV-буферы.

**Почему совпадает бит в бит.** Целые суммы контактов не зависят от порядка атомиков; всё остальное — те же операции в том же порядке:
- состояние и арифметика — `double`, как на CPU (буферы хранят `uint2`, `asdouble`/`asuint`; `precise` запрещает перестановки и FMA); нужна поддержка double в шейдерах (`DoublePrecisionFloatShaderOps`), иначе бэкенд не включается;
- константы модели (`a`, `b`, `c`, `K`, вес, порог) и таблицы степеней `a^k`, `b^k` считает CPU и передаёт битами; догон дальше 4096 шагов на обоих — умножения на `table[4096]`, а не `exp` (для этого CPU-код догона переписан так же);
- генератор Пуассона на обоих — 32-битный хеш (lowbias32): в SM 5.0 нет 64-битных целых. Шаги на GPU 32-битные — хватает на 119 часов модели;
- вход `int → float → double` точен для целых меньше 2²⁴, как `int → double` на CPU.

**Асинхронность.** У бэкенда своя compute-очередь. `Advance` / `AdvanceMs` только записывают окна в командный список и отправляют его — без ожидания (до 256 окон или 4096 шагов на отправку, 3 отправки в полёте). Счётчики наблюдений возвращаются через readback-буфер, когда GPU закончит: `CompletedStep()` — до какого шага они известны, `SpikeCount` / `RateHz` / `TotalSpikes` считают по этот шаг. Игра вызывает `AdvanceMs(28.57)` на тик и читает выходы предыдущего тика (задержка — одна отправка, то есть один тик DOOM, если вызывать по окну — одно окно); `Poll()` забирает готовое без ожидания, `Synchronize()` ждёт всё. Запросы отдельных нейронов (`VoltageMv`, `NeuronSpikeCount`, `AwakeCount`, `RecentSpikes`) на GPU синхронные: ждут GPU и читают состояние обратно — для тестов и отладки, не для кадра.

**Спайки для `BrainView` (V0).** `GetGpuSpikeRing()` отдаёт буфер `uint2 (нейрон, шаг) × capacity` (степень двойки, ≥ `SetSpikeRingCapacity`), счётчик записанных спайков `counters[0]` (следующий индекс — `counters[0] & (capacity − 1)`) и `lastSpikeStep` — `uint` на нейрон, шаг его последнего спайка (`0xFFFFFFFF` — не было; возраст = `(CompletedStep() − шаг) · dt`): его можно подключить к рендеру как `StructuredBuffer<uint>` на нейрон. Всё — на устройстве мозга. Между отправками буферы в состоянии `COMMON`; графическая очередь перед чтением ждёт `fence ≥ fenceValue`. Чтобы рисовать без копии на CPU, мозг должен считаться на устройстве рендера: `GpuOptions::device = adapter.GetDevice()`.

**Выбор бэкенда.**

```cpp
flybrain::BackendChoice choice = flybrain::BackendChoice::Auto;
flybrain::ParseBackendChoice(flagValue, choice);           // --flybrain auto|cpu|gpu
flybrain::GpuOptions options;
options.device = renderDevice;                             // null: свой device (самый быстрый адаптер с double)
std::string error;
if (brain.SetBackend(choice, options, &error) != flybrain::Backend::Gpu)
{
    log("fly brain on the CPU: " + error);                 // нет DX12, нет double, не прошла самопроверка
}
```

`Auto` берёт GPU, если устройство есть, double поддерживаются и проходит самопроверка (сеть из 300 нейронов с током и Пуассоном, 2000 шагов: спайки GPU = CPU), иначе остаётся на CPU. Бэкенд можно сменить на любом шаге: состояние целиком переезжает (выгрузка/загрузка буферов). На GPU счётчики ведут первые 32 наблюдения (`Watch`). Несколько мух на одном устройстве делят CSR коннектома (154 МБ), своё у каждой — ≈ 29 МБ.

## Рой мух-врагов (N2)

В режиме «Рой» у каждой мухи-врага свой маленький мозг: схема из 1–5 тыс. нейронов, вырезанная из MaleCNS вокруг пути «лупинг → поворот, ход, бросок». Все мухи считаются одним батчем.

**Вырезка** (`flybrain::ExtractCircuit`, [`game/flybrain/include/flybrain/Circuit.h`](../../game/flybrain/include/flybrain/Circuit.h)):
- входы: LPLC2 и LC4 (детекторы лупинга, 311 нейронов); выходы: DNp01 (гигантское волокно, бросок), DNa01/DNa02 (повороты), DNp09 (ход вперёд), MDN (назад) — 12 нейронов;
- вверх от выходов на 3 шага: пресинаптический партнёр остаётся, если даёт ≥ 1,25 % всех контактов на нейрон-цель; вниз от входов на 3 шага: цель остаётся, если получает ≥ 1,25 % всех контактов нейрона-источника;
- схема = нейроны, достигнутые в обе стороны (лежат на путях вход → выход), плюс входы, выходы и сильные прямые входы выходов (торможение вокруг них); синапсы между ними — все, как в полном коннектоме, со своими знаками.

Результат: **1 660 нейронов, 155 694 синапса, 1,9 млн контактов, 796 типов** (больше всего — LPLC2 185, LC4 126, LC9 19, LT51 13; остальное — по нескольку нейронов центрального мозга, нисходящих и восходящих). Подбор порога: 2 % дают 448 нейронов, 1,5 % — 923, **1,25 % — 1 660**, 1 % — 4 008 нейронов.

Файл `assets/flybrain/swarm_circuit.fbrain` (1 МБ, тот же формат, в атрибуции дописаны параметры вырезки) делает утилита:

```
build/tests/RelWithDebInfo/myengine_flybrain_circuit.exe [--up-hops 3] [--up-share 0.0125] [--down-hops 3] [--down-share 0.0125] [--dry-run]
```

Как и `malecns_v1.fbrain`, файл в git не попадает (`*.fbrain`). Он производный от данных CC BY 4.0 и маленький, так что его можно положить в пакет игры с той же атрибуцией.

**Батч: реплики `FlyBrain`.** Отдельного движка для роя нет. `FlyBrain(circuit, params, flies)` держит `flies` независимых мозгов на одном CSR: состояние разложено как `[нейрон][муха]` («юниты», `unit = neuron · flies + fly`), спайк юнита доставляется только в юниты той же мухи. Отсюда:
- CPU: блоки по 512 юнитов — это мухи соседних нейронов, AVX2 считает 4 мухи одного нейрона одной инструкцией; окно по 18 шагов — одно на весь рой, как на job system;
- GPU: те же ядра; в `CSDeliver` цель = `post · flies + fly`, остальное без изменений; одно окно — один набор диспетчей на всех мух;
- у одной мухи (`flies = 1`) юнит и нейрон совпадают, всё прежнее работает как было.

Для выходов роя на GPU есть `FlyBrain::Track(units)`: каждая отправка копирует назад суммы спайков этих юнитов (подряд идущие мухи нейрона — одна копия), и `TrackedSpikes(unit)` читает их без синхронизации. Счётчики `Watch` для этого не годятся: их на GPU 32, а у роя 7 групп × 32 мухи. Вход по юниту, меняющийся каждый кадр, — `SetPoissonRate(unit, Hz)`, рядом с `SetDrive`.

**`FlySwarmBrain`** ([`FlySwarmBrain.h`](../../game/flybrain/include/flybrain/FlySwarmBrain.h)):

```cpp
auto circuit = flybrain::Connectome::Load("assets/flybrain/swarm_circuit.fbrain");
flybrain::SwarmOptions options;
options.backend = flybrain::BackendChoice::Auto;           // GPU, если есть; иначе CPU
auto swarm = flybrain::FlySwarmBrain::Create(circuit, 32, options);

flybrain::SwarmInput input;                                // всё 0..1
input.loomLeft = 0.8f;                                     // что-то приближается слева (угловой размер и скорость)
input.loomRight = 0.0f;
input.brightness = 0.5f;
swarm->SetInput(fly, input);
swarm->AdvanceMs(1000.0 / 35.0);                           // тик DOOM, все мухи сразу
const flybrain::SwarmOutput& out = swarm->Output(fly);     // turn −1..+1 (+ вправо), forward −1..+1, escape 0..1, escapeSpikes
```

Вход: `loom` стороны → пуассоновский вход в LPLC2 и LC4 этой стороны с частотой `loom · 200 Гц`; `brightness` → ток `brightness · 5 мВ` во все входные нейроны (ниже порога). Выход: частоты нисходящих нейронов, сглаженные экспонентой со 100 мс (как у DOOMFLY): `turn = tanh((DNa02_R + ½DNa01_R − DNa02_L − ½DNa01_L) / 50 Гц)`, `forward = tanh((DNp09 − MDN) / 50 Гц)`, `escape = tanh(DNp01 / 50 Гц)`; каждый новый спайк гигантского волокна (`escapeSpikes`) — бросок. На GPU выходы отстают на одну отправку (тик).

**Поведение на вырезанной схеме** (тест `flybrain_swarm`, одинаково на CPU и GPU):

| Опыт | Результат |
| --- | --- |
| нет входа 300 мс | ни одного спайка |
| только яркость 1 (5 мВ во все входы) 300 мс | ни одного спайка |
| лупинг слева 300 мс | DNa02_R 33 Гц, DNa02_L 0: **поворот вправо, от угрозы** (`turn +0,58`); гигантское волокно — 113 спайков (`escape 1`) |
| лупинг справа 300 мс | DNa02_L 1,6 Гц, DNa02_R 0: поворот влево, но слабый (`turn −0,03`); гигантское волокно — 135 спайков |
| муха без входа рядом с этими | ничего не делает |
| 300 + 400 мс после конца лупинга | выходы в покое (`turn`, `forward`, `escape` < 0,05, новых бросков нет) |

Знак поворота документирован: **лупинг с одной стороны поворачивает муху в другую** (уход от угрозы), бросок — с обеих сторон. Найдены две особенности графа (модель совпадает с Brian2, это не ошибка счёта):
- **асимметрия:** лупинг справа поворачивает в 20 раз слабее, чем слева. Вероятно, сказываются разные численности LC4 (71 слева, 55 справа) и неполнота правой половины в вырезке. Если для игры нужна симметрия, D1 может зеркалить `turn` мухи по более сильной стороне или поднять `commandScaleHz`;
- **петля после сильного лупинга:** 9 нейронов (CL213 L/R, ацетилхолин ↔ тормозные GNG581, GNG584, GNG306, DNg74_a) продолжают стрелять (≈ 520 спайков за 400 мс у двух мух против 45 тыс. во время лупинга). Ни один выход роя от этого не зависит.

**Скорость, 32 мухи** (53 120 юнитов, вход меняется каждый тик у каждой мухи, 1,77 млн спайков в секунду на рой; медиана трёх прогонов теста):

| Бэкенд | × реального времени |
| --- | --- |
| GPU (RTX 3050 Laptop) | **3,80** (3,72..3,89) |
| CPU (job system, AVX2) | **1,10** (0,79..1,12; машина была нагружена сборками других кодеров) |

Обе цифры не ниже реального времени. Схема и состояние роя занимают немного: CSR схемы ≈ 1 МБ на всех, состояние ≈ 7 МБ на 32 мухи (130 Б на юнит, из них 72 Б — кольцо входа).

## Обучение (N3)

Муха может учиться так, как это устроено в грибовидном теле: синапс клетки Кеньона (KC) на выходной нейрон (MBON) ослабевает, если KC была активна (след), пока стреляют дофаминовые нейроны (DAN) компартмента этого MBON. Наказание — PPL1, награда — PAM. Сделано в `FlyBrain` (`EnablePlasticity`), на CPU и GPU одинаково.

**Что пластично** (`PlasticityRule`, всё из аннотаций и связей MaleCNS):
- рёбра «тип KC* → тип MBON*»: в MaleCNS это **61 210 синапсов** от 4 063 KC на 97 MBON;
- компартмент MBON — DAN типов PPL1* (16 нейронов, наказание) и PAM* (316, награда), которые делают на этот MBON ≥ 10 контактов; вклад DAN — его доля этих контактов. На MBON с компартментом приходятся 56 171 пластичный синапс. Пример: PPL101 (γ1pedc) попадает в компартменты 10 MBON, среди них MBON11 — как в литературе. Порог в 10 контактов отсекает случайные единичные синапсы: без него PPL101 «доставал» 35 MBON.

**Правило**, раз за вызов `Advance` (тик DOOM — 28,57 мс; DOOMFLY обновляет веса так же, бинами ≤ 10 мс):

```
trace_KC   = trace_KC · e^(−Δt/τ) + спайки KC за вызов           τ = 2 с (след)
DA_MBON    = Σ доля_DAN · спайки DAN за вызов                     дофамин компартмента
scale      = 1 + (scale − 1) · e^(−Δt/τ_f)                        забывание, τ_f = 30 мин (как у DOOMFLY)
scale     −= η · trace_KC · DA_MBON                               η = 5·10⁻⁴; депрессия
scale      = clamp(scale, 0,1, 2)                                 от исходного веса синапса
вес        = round(контакты · 256 · scale)                        в 1/256 контакта
```

**Целые веса и совпадение CPU = GPU.** Вход синапсов теперь копится в 1/256 контакта (`kFixedScale`): обычный синапс даёт `контакты · 256`, пластичный — свой округлённый вес. Это не меняет ни одного спайка: `w_syn/256 · 256c` округляется так же, как `w_syn · c` (умножение на степень двойки точное). Тест против Brian2 по-прежнему проходит, 459 из 459 спайков. Шаг обучения считает CPU по суммам спайков KC и DAN, одинаково для обоих бэкендов. На GPU суммы приходят через `Track`, изменившиеся веса уходят в буфер `PlasticWeights` ядром `CSPlastic` до следующего окна. Чтобы веса вызова попали в следующий вызов, как на CPU, `Advance` на GPU с обучением ждёт предыдущую отправку. При скорости GPU 6× это почти не стоит времени. Итог: те же веса и те же спайки бит в бит (тест).

**Дофамин — модулятор (`ModelParams::fastModulatorySynapses`).** У Шиу и DOOMFLY синапсы с непонятным или модуляторным медиатором (дофамин, октопамин, серотонин) — быстрые возбуждающие (+1). На MaleCNS это ломает обучение: **двух PPL101 на 150 Гц достаточно**, чтобы центральный мозг ушёл в самоподдерживающийся режим (1,2 млн спайков/с). Тогда стреляют почти все KC и все DAN, и ослабевают все 61 тыс. синапсов. С `fastModulatorySynapses = false` спайки DAN никуда не доставляются как ток (нейроны сами стреляют, дофамин работает только как сигнал обучения), и PPL101 больше не раскачивает мозг (≈ 300 спайков/с, после стимула тишина). По умолчанию опция включена (`true`, совместимость с N0 и Brian2); для режима обучения её нужно выключать — и в ветке «без обучения» тоже, чтобы сравнение было честным. Массовый вход (все ~2 000 KCg-m, вкусовые LB3c на 150 Гц) раскачивает мозг и с тихими модуляторами: это свойство графа, оно описано выше.

**API:**

```cpp
flybrain::ModelParams params;
params.fastModulatorySynapses = false;                     // дофамин — модулятор
flybrain::FlyBrain brain(connectome, params);
brain.EnablePlasticity();                                  // до SetBackend(Gpu)
brain.LoadMemory(flybrain::FlyBrain::DefaultMemoryPath()); // %LOCALAPPDATA%\FlyDoom\fly_memory.bin, если есть
// урон:
brain.StimulateCurrent(brain.PunishmentNeurons(), 15.0f, 200.0f);   // PPL1; 4 мВ — ниже порога, DAN не стреляют
// награда (подбор, убийство):
brain.StimulateCurrent(brain.RewardNeurons(), 15.0f, 200.0f);       // PAM
// перед тем как мозг делается заново (смерть, уровень): выученное сохранить и вернуть
std::vector<double> memory = brain.GetPlasticScales();
newBrain.EnablePlasticity(); newBrain.SetPlasticScales(memory);
brain.SaveMemory(flybrain::FlyBrain::DefaultMemoryPath());
brain.SetLearning(false);                                  // веса заморожены (контроль)
brain.ResetPlasticity();                                   // всё к 1
```

Файл памяти: `FLYMEM01`, отпечаток пластичных синапсов (bodyId пре и пост), число синапсов и мух, затем `double` масштабы `[синапс][муха]`. Память другого коннектома или другого числа мух не читается.

**Проверки** (тест `flybrain_plasticity`, ≈ 4 с):

| Опыт | Результат |
| --- | --- |
| синтетическое грибовидное тело: 20 KC «запаха» A, 20 KC «запаха» B, MBON01 в компартменте PPL101, MBON02 — PAM | 60 пластичных синапсов, у каждого MBON есть компартмент |
| 10 пар «A + PPL1», затем ответы за 1 с | MBON01 на A: **35 → 0 спайков**; на B: 31 → 33; MBON02 на A: 28 → 33; масштаб A→MBON01 0,131, B→MBON01 1,000, A→MBON02 1,000 |
| то же с `SetLearning(false)` | веса не меняются, ответ на A 35 → 30 (шум Пуассона) |
| файл памяти | восстанавливает все веса; сброс — все 1; память другого коннектома отвергается |
| то же на GPU | **те же 6 828 спайков и те же 60 весов бит в бит** |
| MaleCNS, `fastModulatorySynapses = false`: 5 пар «102 KC (каждая 40-я) на 20 Гц + PPL101 15 мВ» | 2 485 спайков на весь мозг за 3 с, ни одна посторонняя KC не стреляла; **ослабли все 258 синапсов этих KC на MBON компартментов PPL101** (MBON11 116, MBON20 42, MBON30 44, MBON35 33, MBON25 23; минимум 0,646); **из 59 685 синапсов остальных KC — ни один**; на GPU — те же числа |

**Замер в игре: эффекта нет, и понятно почему.** Временная сборка «N3 + N1» (`FlyPlayer` coder-1 с локальной правкой: пластичность, дофамин как модулятор, урон → все PPL1 на 15 мВ, память между жизнями; в репозиторий правка не входит, дифф отдан coder-1). Муха играет E1M1 на skill 4 по 10 минут игры в каждой ветке, мозг на CPU, контроллер `controls_doomfly.json`:

| Ветка | Смертей за 10 мин | Жизни, с | Средняя жизнь, с | Урон, HP/с | Путь, ед./с | Спайков KC за игру | Средний масштаб весов |
| --- | --- | --- | --- | --- | --- | --- | --- |
| с обучением | 3 | 41,1 · 24,0 · 30,6 | 31,9 | 0,68 | 82,5 | **0** | 1,0000 |
| без обучения | 3 | 41,1 · 24,0 · 30,6 | 31,9 | 0,68 | 79,2 | **0** | 1,0000 |

Первые три жизни совпадают до тика (время, урон, убийства). Разница в пути — из четвёртой жизни, которую оборвал лимит времени: в обеих ветках муха прожила её до конца замера, ≈ 8 минут. **Обучения не было, потому что за всю игру клетки Кеньона не дали ни одного спайка**: зрительный вход DOOMFLY (фоторецепторы → ламина → оптическая доля) не доходит до грибовидного тела. Без активности KC нет следа, урон даёт дофамин, но ослаблять нечего, и мозг в обеих ветках один и тот же. Это совпадает с честным выводом DOOMFLY («обучение не показано»). Чтобы обучение имело шанс:
- KC нужен вход, связанный с игрой: в мозге мухи они получают в основном запах (проекционные нейроны антеннальной доли) и немного зрения (KCg-d, KCab-p от зрительных проекционных нейронов). Инженерный вариант для N1/D1 — «запах уровня» или «запах монстра»: редкий набор KC (≈ 2–5 %), который включается, когда в кадре есть угроза. Массовый вход в KC (все KCg-m) раскачивает мозг — дозировать;
- выходы MBON должны влиять на управление. В контроллере `controls_doomfly.json` их нет: даже выученный MBON сейчас не меняет команду игрока.

Повторить замер: правка `FlyPlayer` и харнесс `FlyLearnMeasure` (жизнь за жизнью, возрождение по «use», итоги по жизням) лежат в заметках сессии (`n3-flyplayer-learning.diff`). После того как N1 подключит вход в KC, их можно запускать снова.

## Муха учится в игре (N3b)

Чтобы муха училась в DOOM, нужно три вещи: KC должны видеть игру, урон должен включать PPL1, а MBON должны менять команду. Сначала разобрано, что об этом говорит коннектом (инструмент `myengine_flybrain_mb_probe`, ниже); потом сделан вход и проверено обучение на всём MaleCNS.

**Что видят клетки Кеньона.** В MaleCNS 4 064 KC (15 типов). Снаружи на них приходит 928 421 контакт, из них зрительных (нейроны оптических долей) — **11 439, то есть 1,2 %**. Зрение получают почти только **KCg-d (206 клеток) и KCab-p (129)**, это вспомогательная чашечка, как в литературе. Остальное — запах (проекционные нейроны антеннальной доли), DAN, APL и DPM. Главные зрительные входы:

| Тип | Нейронов | Контактов на KC | KC | Куда |
| --- | --- | --- | --- | --- |
| aMe12 | 6 | 1 785 | 96 | KCg-d 87 |
| aMe26 | 6 | 1 127 | 90 | KCab-p 77 |
| MeVP41 | 2 | 1 013 | 62 | KCg-d 56 |
| LoVP42 | 2 | 923 | 61 | KCg-d 58 |
| MeVP36 | 2 | 659 | 47 | KCg-d 46 |
| MeVP45 | 2 | 265 | 64 | KCab-p 62 |

Всего у KC 290 зрительных пресинаптических нейронов, из них 108 дают ≥ 10 контактов. Отдельно: половина выходов KC (1 153 845 из 2 246 664 контактов) идёт на другие KC — это аксо-аксональные синапсы в долях.

**Почему в N3 KC молчали.** Свой вход эти зрительные нейроны получают из цветового пути R7/R8: через гистамин фоторецепторов и глутамат Dm8/Dm9. В точечной LIF это только торможение. У мухи фоторецепторы и ламина градуальные (раздел «Ограничения»), и путь работает через снятие торможения, которого в модели нет. Проверка: Пуассон в R1–R6 на 0/20/80 Гц и 12 мВ в ламину зажигают 10–13 из 290 зрительных входов KC, а сами KC — **0**. Поэтому вход сделан мостом: **`KcVision` подаёт картинку прямо в зрительные входы KC**, а «куда смотрит» каждый из них берётся из коннектома. Это колонки (`assignedOlHex1/2`) его пресинаптических нейронов на 1 и 2 синапса выше (синапсы ≥ 5 контактов). Через второй шаг колонка получает вес «контакты первого синапса × доля второго во входе среднего нейрона». Поле есть у всех 108 входов (1 769 колонок обеих сторон). Мост наш, а не биология: оптическую долю он обходит.

**Разгон мозга и тихие lLN (`ModelParams::silentTypePrefixes`).** Пуассон в 66 зрительных входов KC на 20 Гц уводит MaleCNS в самоподдерживающийся режим (0,5 млн спайков/с, горят 76 % KC), и случается это не каждый раз (на 80 Гц может не случиться). Очаг — **lLN1_bc**, 30 локальных нейронов антеннальной доли (медиатор по предсказанию — ацетилхолин). На себя они делают **86 864 контакта**, то есть один спайк даёт соседям ≈ 27 мВ при пороге 7 мВ: бистабильный аттрактор, который дальше через PN зажигает KCg-m. Убрать KC→KC и «сенсорный → сенсорный» недостаточно. Если выключить выходы одного lLN1_bc, срыв уходит на 1 с, но возвращается за 3 с с тоническим током ламины. **Если выключить выходы всех lLN\***, разгона нет, и отклик KC растёт с частотой монотонно. `silentTypePrefixes = {"lLN"}` делает именно это: нейроны этих типов стреляют, но их синапсы ничего не несут (тот же механизм, что у `fastModulatorySynapses`, CPU и GPU одинаково). Запаха в DOOM нет, поэтому для игры это честная цена.

**Цена для лупинга (D1a).** Единственная работающая реакция мухи из D1a — отворот от растущего объекта справа или спереди. Её выход — DNa02 противоположной стороны, и сопровождается она бурей центрального мозга ([flydoom-fly.md](../game/flydoom-fly.md), раздел «Лупинг»). Сцены инструмента `myengine_doomfly_vision` (GPU, колонки 12/12 мВ, средние за 1,5 с, яркий растущий круг справа / в центре) в четырёх режимах модели:

| Режим | DNa02 L, Гц | Центральный мозг, тыс. спайков/с | KC на зрительный вход | Обучение |
| --- | --- | --- | --- | --- |
| D1a: дофамин быстрый, lLN работают | 2,0 / 2,0 | 706 / 745 | разгон (76 % KC) | нет: быстрый дофамин раскачивает мозг (N3) |
| дофамин быстрый, lLN тихие | 7,3 / 4,0 | 189 / 193 | — | нет (быстрый дофамин) |
| дофамин — модулятор, lLN работают | 4,0 / 1,3 | 306 / 35 | разгон | нет (разгон) |
| **дофамин — модулятор, lLN тихие** (режим «муха учится») | 2,0 / 1,3 | 36 / 37 | 11,6 % зрительных KC, без разгона | MBON на X −35 % к ветке без обучения |

Тёмный растущий круг, неподвижная картинка и объект слева во всех режимах дают 0, как в D1a. Очаг бури — не только lLN1_bc: без lLN она слабее в 4–20 раз, но остаётся. Выход «DNa02 L при объекте справа» есть во всех режимах. Поэтому `silentTypePrefixes` и `fastModulatorySynapses = false` включаются только в режиме обучения, остальные режимы работают как в D1a.

**Разреженность KC** (без lLN, 12 мВ в ламину, 3 с, часть зрительных входов KC на Пуассоне):

| Часть 290 входов | 40 Гц | 80 Гц | 150 Гц |
| --- | --- | --- | --- |
| 10 % | 7 KC | 3 | 9 |
| 20 % | 7 | 22 (6,6 % зрительных KC) | 56 |
| 40 % | 8 | 43 | 107 |

Мозг при этом держится на ≈ 0,35 млн спайков/с: это фон ламины и центрального комплекса, а не разгон.

**Порог наказания.** PPL1 под постоянным током (дофамин — модулятор): 4 мВ дают 0 Гц, 7,5 → 16 Гц, 10 → 38, **15 → 68**, 20 → 92. Порог 7 мВ (`v_th − v_0`). Урон FlyPlayer в 4 мВ PPL1 не включает, для обучения нужно 15 мВ.

**MBON и управление.** На картинку (20 % входов на 80 Гц) отвечают MBON30 (110 Гц), MBON32 (32), MBON20 (18), MBON21 (8); без картинки MBON молчат. Это γ-доля, где лежат компартменты PPL1. Прямой путь MBON → нисходящие нейроны управления (DNa01/02, DNp09, MDN, DNp01, DNp20, DNpe017) в коннектоме слабый. Прямые синапсы есть у MBON32 (−1,3 % входа этих DN), MBON27 (+0,7 %), MBON31 (−0,6 %); у остальных ≤ 0,8 % через один промежуточный нейрон. Поэтому «MBON → действие» в игре задаётся нашим весом в контроллере, и это так и помечено.

**Проверка на коннектоме** (тест `flybrain_kc_vision`, ≈ 70 с; дофамин — модулятор, lLN тихие, 12 мВ в ламину). Картинка X — половина колонок левого глаза (меньшие `hex1`), Y — такая же половина правого:

| Опыт | Результат |
| --- | --- |
| `KcVision` | 108 зрительных входов KC (≥ 10 контактов), у всех поле ≥ 3 колонок |
| X на 1 с | горят **39 из 335 зрительных KC (11,6 %)**, без картинки — 0. Через 0,5 с после X: 60 спайков KC (без картинки 0), мозг 357 тыс. спайков/с против 276 тыс. без картинки. Остаток — кольцевой аттрактор центрального комплекса (PEN, EPG, FR1, Delta7): он остаётся в другом состоянии, и это его устойчивость, а не разгон |
| KC картинок | X: 89 KC, из них 72 слева; Y: 123, из них 4 слева; общих 15 |
| «вид X + урон»: 12 раз X 0,6 с + PPL1 15 мВ; ответы мерятся при замороженном обучении | масштаб синапсов KC картинки X на MBON компартментов PPL1 — **0,53**, KC картинки Y — 0,74, остальных KC — 0,9999 |
| ответ MBON, до которых доходят KC картинки (≥ 2 % их возбуждающих контактов: для X MBON35, 11, 21, 20, 32, 33, 19) | **на X: 64 спайка против 99 без обучения (−35 %)**, на Y: 271 против 382 (−29 %) |
| то же без обучения | веса ровно 1, ответы до сочетаний те же, что с обучением |

Почему считываются не все MBON компартментов PPL1. Самый громкий из них, MBON30, получает вход и от центрального комплекса (FR1, CRE067, LAL155). Состояние CX между замерами дрейфует, и ответ MBON30 на X вырос в обеих ветках с 126 до ≈ 270 спайков. Поэтому сравнение идёт с веткой без обучения на тех же тиках: модель детерминирована, и разница между ветками — только обучение. Почему Y тоже теряет часть ответа: зрительные входы левого глаза доходят и до правой чашечки, часть правых KC стреляет и на X, и на 12 сочетаниях их тоже наказывают. Обобщение между X и Y — свойство этого графа. X теряет больше.

**Детерминированность (разбор 4-й жизни N3).** Режим `determinism` пробника гоняет 10 с «как в игре»: ток в зрительные нейроны меняется каждый тик, каждые 2 с урон в PPL1, обучение включено. Повтор, job system против одного потока и AVX2 против скалярного кода дают **одинаковые спайки у всех 164 789 нейронов**. Если KC молчат (вход только в R1–R6, как в N3), обучение вкл/выкл тоже ничего не меняет. Полная цепочка «DOOM + FlyPlayer + мозг» (временный стенд с трассой каждого тика: позиция, команда, хэш кадра, шаг мозга) за 3 минуты игры, 6 300 тиков и четыре жизни дважды дала один и тот же след. DOOM идёт по виртуальным часам (`PlatformSleepMs`/`StepTic`), экранный wipe тоже.

**Но детерминизм не полный.** След режима «Fly learns» (`myengine_fly_learn_measure --trace`) с одним зерном в двух процессах совпадает 1 576 тиков, а на 1 576-м различается **один пиксель кадра** (строка 105, столбец 77). На 2 370-м различаются 10 пикселей одной строки 3D-вида (белый отрезок против коричневого). Позиция, команда и спайки до этого одинаковы. Мозг видит разный кадр, и через 1–2 тика его спайки расходятся, а дальше муха играет по-другому. То же в сборке Debug: стек там заполнен 0xCC, куча 0xCD, значит, это не мусор неинициализированной памяти. Обнулённая зона DOOM (`I_ZoneBase`) тоже не помогла. Источник — программный рендер DOOM, но какой именно участок, не найдено. Вывод для замеров: два процесса с одним зерном совпадают первые ≈ 45 с игры, потом расходятся. Расхождение похоже на редкий шум картинки, одинаковый для обеих веток, и не смещает сравнение. Ветки «с обучением / без» расходятся гораздо раньше, на 13-м тике, из-за самих весов (раздел «В игре»). Скорее всего, этим же объясняется и разница путей 82,5 / 79,2 в 4-й жизни N3. Тест `doom_fly` (`play`) сравнивает 140 тактов — в них след совпадает.

flybrain::ModelParams params;
params.fastModulatorySynapses = false;          // дофамин — модулятор
params.silentTypePrefixes = { "lLN" };          // антеннальная доля молчит: без этого зрительный вход разгоняет мозг
flybrain::FlyBrain brain(connectome, params);
brain.EnablePlasticity();

flybrain::KcVision vision;
vision.Build(*connectome);                      // KcVisionConfig: minContactsOntoKcs 10, minSynapseContacts 5, maxRateHz 120, gain 1
std::vector<float> feature(vision.Columns().size(), 0.0f);   // 0..1 в каждой колонке (side, hex1, hex2)
// ... каждый тик: признак колонок из картинки (FlyEyes::Columns() даёт те же колонки с местом на экране)
vision.Apply(brain, feature);                   // Пуассон каждого входа = maxRateHz · clamp(gain · Σ вес_колонки · признак)

### В игре: режим «Fly learns»

`FlyPlayerConfig::learning.enabled` (пункт меню **Fly learns**, `--fly-mode fly-learn`; остальные режимы не меняются) включает в FlyPlayer:
- дофамин как модулятор и тихие lLN;
- пластичность (`EnablePlasticity` до GPU);
- урон 15 мВ во все PPL1;
- вход в KC через `KcVision`. Признак колонки — смена её света против медленного среднего, `|L − L_медл| / (L_медл + 0,05)`, тот же медленный канал, что у движения D1a, до 120 Гц на вход;
- перенос весов из жизни в жизнь и файл памяти `%LOCALAPPDATA%\FlyDoom\fly_memory.bin`; `--fly-forget` стирает его при первом запуске режима.

В статусе — `kcSpikesPerSecond` и `learnedScale` (средний вес KC→MBON раз в секунду), в панели — группа LEARNING с подписью «наш мост: картинка → зрительные входы KC; MBON в повороте — наш вес».

**Управление `controls_learn.json`** — DOOMFLY плюс MBON32 и MBON20 в повороте с весом ±0,5 (справа минус слева). Это MBON компартментов PPL1, до которых доходят KC зрительной картинки: муха поворачивает к стороне, чьи MBON отвечают сильнее, а наказанный вид ослабляет MBON своей стороны. Это наш вес, а не биология. Смещение и усиления **откалиброваны под этот мозг** (стенд `myengine_fly_learn_measure`, E1M1). На ровной картинке он такой же, как мозг D1a. Но в игре вход в KC переводит центральный мозг в другое состояние (≈ 55 тыс. спайков/с против 0): `DNp20 R − L` в среднем 0,5 Гц (у D1a 10,8), DNpe017 3,7 Гц (23,4). Без калибровки муха кружила на месте со смещением −1°/такт и почти не шла. Поэтому смещение поворота 0,5 Гц, усиление хода 6, порог огня DNpe017 4 Гц. При этом ход и стрельба такие же, как у DOOMFLY (огонь почти всегда, как у мухи D1a в игре).

**Лупинг в этом режиме** (`doom_fly`, сценарий `loom_learn`). Сбросов мозга нет. Отворот от растущего круга справа и в центре слабее, чем в D1a: средний поворот на 0,5–0,7°/такт ниже, чем у стоящего круга (в D1a −1,24°/такт); минимум −4,6°. На объект слева муха теперь поворачивает к нему (−1,26°/такт): MBON левой стороны отвечают на движение (MBON32 40–70 Гц), а MBON-поворот ведёт к новому, ещё не наказанному.

**«Вид X + урон» через всю цепочку** (`doom_fly`, сценарий `learn_shift`). Мерцающий узор на левой половине кадра (X), 8 сочетаний X с уроном, потом X и такой же узор справа (Y). Две ветки с одним зерном:

| | С обучением | Без обучения |
| --- | --- | --- |
| левые MBON (32 + 20) на X после сочетаний, Гц | **34,0** | 55,4 |
| поворот на X, °/такт (минус — к X) | **−1,89** | −3,25 |
| поворот на Y, °/такт | 0,36 | 0,27 |
| правые MBON на Y, Гц | 30,0 | 40,6 |
| средний вес KC→MBON | 0,9954 | 1 |

После урона муха поворачивает к X на 1,4°/такт меньше, и это сдвиг действия из-за ослабленных KC→MBON. Y тоже немного теряет, как в тесте на коннектоме: коды картинок пересекаются.

| --- | --- | --- | --- | --- | --- | --- |

(p — критерий Манна–Уитни по жизням.) Среднее время жизни без обучения тянут вверх две жизни в 553 и 286 с: муха застряла там, где её не достают. Честный итог: в игре синапсы KC→MBON учатся (средний вес 0,984 за 25 жизней), а в синтетике сдвиг ответа MBON и поворота есть (выше). Но заметного изменения поведения за 25 жизней на ветку **не видно**. Причины видны в числах:
- обучение медленное: вес падает в среднем на 1,6 % за ≈ 20 минут игры, а наказываются только те KC, что горели в момент урона;
- поворот MBON (вес 0,5 на ≈ 30–50 Гц) меньше шума DN;
- ветки расходятся уже на 13-м тике (0,4 с). DAN немного горят на любую картинку, веса чуть отличаются с первых кадров, и хаос мозга превращает это в разные траектории. Сравнивать можно только статистически, а для эффекта ~15 % нужно заметно больше жизней.

Повторить: `myengine_fly_learn_measure --learning 1|0 --lives 25 --skill 5 --seed 1 [--trace след.txt]`; калибровка контроллера — `--calibrate`.

## API

```cpp
#include <flybrain/FlyBrain.h>

std::string error;
auto connectome = flybrain::Connectome::Load(path, &error);       // nullptr + error, если файла нет или он битый
flybrain::FlyBrain brain(connectome);                               // ModelParams по умолчанию = Шиу
brain.SetParallel(true);                                            // окна — задачи job system (jobs::Initialize уже вызван)

flybrain::Group dnLeft = connectome->Find("DNa02", flybrain::Side::Left);
flybrain::Group retina = connectome->Find("R1-R6");
flybrain::Group r7 = connectome->FindPrefix("R7");                  // R7d, R7p, R7y, ...

brain.StimulateCurrent(connectome->Find("L1"), 12.0f);              // ток, мВ, бессрочно
auto id = brain.StimulateRate(retina, 30.0f, 200.0f);               // Пуассон 30 Гц на 200 мс
brain.SetDrive(neuron, mv);                                         // ток одного нейрона (фоторецептор каждый кадр)

auto watch = brain.Watch(dnLeft);                                   // счёт спайков группы по шагам
brain.AdvanceMs(1000.0 / 35.0);                                     // тик DOOM: 285 или 286 шагов
float hz = brain.RateHz(watch, 100.0f);                             // частота на нейрон за последние 100 мс
uint64_t n = brain.SpikeCount(watch, 28.57f);

std::vector<flybrain::SpikeEvent> spikes;
brain.RecentSpikes(spikes, 4096);                                   // последние спайки (кольцо) для растра и 3D
float v = brain.VoltageMv(neuron);
```

| --- | --- |
| `Connectome` | неизменяемый граф и аннотации: `Load`, `FromImage`, `Find(type, side)`, `FindPrefix`, `FindSuperclass`, `FindBodyId`, `Info`, `Position`, `Hex1/2`, CSR (`RowStart`, `Targets`, `Weights`). Один коннектом на сколько угодно симуляций |
| `ExtractCircuit`, `CircuitSpec`, `CircuitReport` | вырезка маленькой схемы из коннектома (раздел [Рой](#рой-мух-врагов-n2)) |
| `KcVision`, `KcVisionConfig` | зрительные входы клеток Кеньона и их поля из колонок коннектома; `Build`, `Columns`, `Inputs`, `RateHz`, `Apply` (Пуассон входов по признаку колонок) — раздел [Муха учится в игре](#муха-учится-в-игре-n3b) |
| `FlySwarmBrain` | рой мух: схема, муха = реплика `FlyBrain`; `SetInput` (лупинг слева/справа, яркость), `AdvanceMs`, `Output` (поворот, ход, бросок) |
| `ConnectomeBuilder` | граф в коде (тесты, маленькие схемы для мух-врагов): `AddNeuron`, `AddEdge`, `Build` (образ файла), `Save` |
| `FlyBrain` | состояние и симуляция: стимулы (`StimulateRate`, `StimulateCurrent`, `StopStimulus`, `SetDrive`), `Advance(steps)` / `AdvanceMs`, выходы (`Watch`, `SpikeCount`, `RateHz`, `RecentSpikes`, `VoltageMv`), `Stats()`; бэкенд (`SetBackend`, `GetBackend`, `CompletedStep`, `Poll`, `Synchronize`, `GetGpuSpikeRing`, `GpuMemoryBytes`) — раздел [GPU](#gpu-n0b); реплики (`FlyBrain(connectome, params, replicas)`, `Unit`, `ForReplica`), `SetPoissonRate`, `Track` / `TrackedSpikes` — раздел [Рой](#рой-мух-врагов-n2) |

Окно никогда не пересекает конец стимула, поэтому длительность стимула точна до шага.

Модель чуть быстрее непрерывной формулы, потому что порог проверяется раз в шаг, а рефрактерный период дискретный (21 замороженный шаг после спайка, правило Brian2): период короче аналитического не больше чем на `dt`. Период в шагах тест сверяет и с точной дискретной формулой `n + 21`, где `n` — первое целое с `I·(1 − a^n) > θ`.

## Скорость относительно реального времени

**Итог GPU (N0b):** одна муха — 6,1× реального времени, четыре одновременно — по 1,8–1,9×, худший случай («раскачка») — 1,4× для одной; таблица — [ниже](#gpu-против-cpu-n0b-malecns-v10).

**Итог CPU (N0):** MaleCNS целиком (164 789 нейронов) с тоническим током в ламину и пуассоновским входом в R1–R6 на 20–50 Гц идёт на 8 потоках со скоростью **0,92–0,96× реального времени**, на 4 потоках 0,66×, на одном 0,21–0,30×; память — 154 МБ образ + 21 МБ состояние. До реального времени не хватает нескольких процентов, поэтому режим «DOOM ждёт мозг» нужен (заложен в D0/N1); узкое место и что с ним делать — ниже.

Бенчмарк `myengine_flybrain_bench` (не в ctest, минуты), методика ЛР1: прогон для прогрева, затем 3 прогона, медиана; каждый прогон — новый мозг, 0,2 с модели на разгон и 1 с модели под замер. Скорость = секунды модели / секунды на стене (1,0 = реальное время).

```
build/tests/RelWithDebInfo/myengine_flybrain_bench.exe                 # настоящий коннектом (код 77, если файла нет)
build/tests/RelWithDebInfo/myengine_flybrain_bench.exe --synthetic     # случайный граф того же размера
    [--threads 1,2,4,8] [--scenarios silent,rest,vision20,vision50] [--repeats 3] [--seconds 1] [--warmup 0.2]
    [--probe <тип>|rest|vision20]                                        # спайки по суперклассам за 1 с
```

Сценарии (по базовой схеме DOOMFLY): `silent` — без входа; `rest` — тонический ток 12 мВ в L1/L2/L3/L5 (без него ламина молчит); `vision20` / `vision50` — плюс пуассоновский вход во все R1–R6 на 20 / 50 Гц. На синтетическом графе ток получают 5 % нейронов, пуассоновский вход — 2 %. Потоки: 1 — без job system, N — `jobs::Initialize(N − 1)` плюс главный поток, который тоже берёт задачи в `Wait`.

- вариант на compute shader — сделан (N0b, раздел [GPU](#gpu-n0b)): 6× реального времени, спайки те же;
- на CPU — обрабатывать нейрон, который получил вход, но заведомо не дойдёт до порога (та же граница `I + g ≤ θ` с учётом входа окна), аналитически по моментам прихода входа, а не 18 шагами;
- для игры уже заложен режим «DOOM ждёт мозг» (D0/N1), как у DOOMFLY: детерминированно, но медленнее реального времени, если мозг не успевает.

Как оптимизировалась схема (vision20, 8 потоков, та же нагрузка машины): первая версия 0,23× → раскладка кольца `[слот][нейрон]` и доставка по слотам → блоки по 512 нейронов «время снаружи» → AVX2 → 0,37–0,49×. Доставка подешевела с ≈ 70 нс до ≈ 10 нс на синапс (запись в пределах слота 0,7 МБ вместо случайной по 12 МБ).

## Ограничения

- Это LIF по карте связей, а не муха (см. начало). Знаки по предсказанному медиатору; модуляторы (дофамин, октопамин, серотонин) считаются возбуждающими, как у DOOMFLY.
- У мухи фоторецепторы и ламина градуальные, а не спайковые; в LIF их приходится «подкармливать» тоническим током (12 мВ в L1/L2/L3/L5 у DOOMFLY), без него ламина молчит.
- Догон спящего нейрона в замкнутой форме округляется иначе, чем пошаговый счёт Brian2; спайк, попавший в пределы ошибки округления (~1e-15 мВ) от порога, может сдвинуться на шаг. На тестовых сетях расхождений нет.
- MaleCNS не говорит, какие вкусовые нейроны сладкие, а какие горькие: тест проверяет «LB3c → MN9» (сахар у DOOMFLY) и избирательность, а не «сахар против горького».
- Вкусовой вход раскачивает центральный мозг в самоподдерживающийся режим (см. замеры) — это свойство модели на этом графе, а не ошибка счёта (модель совпадает с Brian2), но для игры его придётся учитывать.
- Обучение (N3) есть, но от фоторецепторов до клеток Кеньона картинка в точечной LIF не доходит (цветовой путь R7/R8 только тормозит). Вход в KC — наш мост `KcVision`: признак колонок прямо в зрительные входы KC, поля из коннектома (раздел «Муха учится в игре»).
- Локальные нейроны антеннальной доли (lLN) как точечные нейроны — очаг разгона мозга; в режиме обучения их выходы выключены (`silentTypePrefixes`), обоняние в нём не работает.
- GPU-бэкенду нужны double в compute-шейдерах (есть у видеокарт NVIDIA/AMD/Intel с DX12, WARP тоже умеет); на GPU счётчики ведут первые 32 наблюдения, шаги 32-битные (119 часов модели).
