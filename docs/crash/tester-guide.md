# Инструкция для тестировщика (ЛР5)

Как скачать сборку Rocket Arena из GitHub Releases, запустить её в чистой папке, вызвать тестовый сбой и какие файлы отчёта передать разработчику. Как разработчик читает отчёт — [dump-analysis.md](dump-analysis.md), обзор работы — [README.md](README.md).

## Релизы

Страница: <https://github.com/DvornikovArtem/myengine/releases>

| Тег | Что в сборке | Тестовые сбои |
| --- | --- | --- |
| `v0.1.0-lr5.1` | ранний релиз | INTEGER DIVIDE BY ZERO, ACCESS VIOLATION |
| `v0.1.0-lr5.2` | новый релиз (следующий коммит) | те же две и ASSERTION FAILURE |

В описании каждого релиза — его `buildId`, SHA коммита и ссылка на прогон GitHub Actions, который его собрал. В разделе **Assets** два архива одной сборки:

- `RocketArena-0.1.0-build<buildId>-win64.zip` — **пакет для запуска** (нужен тестировщику);
- `RocketArena-0.1.0-build<buildId>-symbols.zip` — отладочные символы `RocketArena.pdb` (нужны только разработчику).

В обоих архивах лежит `build-info.txt` с одним и тем же `buildId` и SHA.

## Системные требования

- Windows 10 или 11, 64 бита.
- Видеокарта с DirectX 12 (уровень функций 11_0 и выше) и свежий драйвер. Без такой видеокарты игра запускается на программном рендерере WARP, но медленно.
- Около 60 МБ на диске для распакованной папки (архив весит около 22 МБ).
- **Ничего устанавливать не нужно.** Visual C++ runtime (`vcruntime140.dll`, `msvcp140.dll` и др.) и Python 3.14 (`python314.dll`, `python314.zip`) лежат рядом с exe. DirectX 12, XAudio2 и XInput входят в Windows. Steam не нужен: сборка релиза собрана без Steam и без Wwise (звук идёт через XAudio2).

## Запуск

1. Откройте релиз, в **Assets** скачайте `RocketArena-0.1.0-build<buildId>-win64.zip`.
2. Распакуйте его в **пустую папку вне репозитория и каталогов сборки**, например `C:\Temp\ra-test\`. Внутри появится папка `RocketArena`.
3. Запустите `RocketArena\RocketArena.exe`. Если SmartScreen предупредит о неизвестном издателе: «Подробнее» → «Выполнить в любом случае» (exe не подписан).
4. Загрузится сцена `rocket_league.json`: стадион, машина на подиуме, главное меню **ROCKET ARENA**.

**Сцена реагирует на ввод:**

- в меню — мышь (наведение и клик), стрелки и Enter, Esc;
- `TRAINING` → любая тренировка или `PLAY` → матч с ботами: `W` / `S` — газ и задний ход, `A` / `D` — руль, левая кнопка мыши — буст, правая — прыжок, `Space` — камера на мяч, `Esc` — пауза.

**Штатный выход:** в главном меню `EXIT` → `Quit` (или в паузе матча выйти в меню и затем `EXIT`). После штатного выхода новых файлов в папке отчётов не появляется.

## Тестовые сбои

В главном меню справа сверху, под именем игрока, — панель **CRASH TEST**. В её заголовке написан `BUILD <buildId>` — тот же, что в описании релиза. Каждая кнопка роняет игру нарочно. Сначала появляется вопрос **CRASH THE GAME?**: **Crash** — уронить, **Cancel** или Esc — отказаться. Подтверждение нужно, чтобы случайный клик не ронял игру при обычном запуске.

| Кнопка | Исключение | Где в коде (стек дампа) | Релизы |
| --- | --- | --- | --- |
| INTEGER DIVIDE BY ZERO | `0xC0000094` integer division by zero | `myengine::core::crash::test::DivideByZero`, `engine/src/core/CrashTests.cpp` | lr5.1, lr5.2 |
| ACCESS VIOLATION | `0xC0000005` access violation (запись по адресу 0) | `myengine::core::crash::test::AccessViolation`, `engine/src/core/CrashTests.cpp` | lr5.1, lr5.2 |
| ASSERTION FAILURE | `0xE0000003` assertion failure | `myengine::core::crash::test::AssertionFailure`, `engine/src/core/CrashTests.cpp` | только lr5.2 |

Ниже функции сбоя в стеке — `DrawCrashTest` (`engine/src/game/RlGameFlow.cpp`), обработчик нажатия кнопки.

## Что происходит при сбое

1. Игра пишет отчёт и показывает окно **«Rocket Arena has stopped working»** с `reportId`, `buildId` и путём отчёта. Нажмите OK — процесс завершится.
2. Отчёт лежит в папке `%LOCALAPPDATA%\RocketArena\crashes\` (вставьте этот путь в адресную строку Проводника). Один отчёт — три файла с общим именем `crash-<дата>-<время>-<reportId>`:

| Файл | Что в нём |
| --- | --- |
| `.dmp` | minidump: исключение и его контекст, аварийный поток, стеки всех потоков, список модулей |
| `.txt` | метаданные без отладчика: `reportId`, время сбоя (местное и UTC), `buildId`, версия, SHA коммита, сцена, последнее действие, исключение и адрес `RocketArena.exe+0x…`, поток; в конце — последние 40 строк лога |
| `.log` | весь лог упавшего запуска; последняя строка — `[CRASH] reportId=… buildId=…` |

3. **Передайте разработчику все три файла** этого отчёта (или всю папку `crashes`). Каждый сбой — новый `reportId` и новые три файла, старые отчёты не перезаписываются.
4. При следующем запуске игра один раз показывает красную плашку «The game crashed last time…» с именем отчёта.

Лог текущего запуска — `%LOCALAPPDATA%\RocketArena\logs\myengine.log`. Он перезаписывается при каждом запуске, поэтому для упавшего запуска берите `.log` из отчёта. В логе есть строки `Build: version 0.1.0, buildId …, commit …` и `Crash handler: reportId …, reports go to …`, а перед сбоем — `Game UI: crash test: …` (последнее действие).

## Сценарий приёмки (три запуска)

1. **Новый релиз (`v0.1.0-lr5.2`), штатно:** запустить, подвигать машину в `TRAINING`, выйти через `EXIT`. Папка `crashes` не пополняется.
2. **Ранний релиз (`v0.1.0-lr5.1`), сбой:** нажать любую кнопку CRASH TEST, передать три файла отчёта. Разработчик по `buildId` из `.txt` находит релиз `v0.1.0-lr5.1`, скачивает его символы и показывает место сбоя.
3. **Тот же ранний релиз, повтор:** по «last action» из отчёта нажать ту же кнопку. Появляется второй отчёт с другим `reportId`; тип исключения и место в коде совпадают с первым. Оба отчёта остаются в папке.
