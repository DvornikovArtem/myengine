# Рендер в текстуру и миниатюры ассетов (R2)

Фундамент превью: движок умеет рисовать во внеэкранные цели, а `ThumbnailService` строит из них миниатюры мешей, материалов и префабов и кеширует их на диске. Интерфейсы для панелей (Content Browser, пикеры, просмотрщики) подключаются поверх этого сервиса.

## Рендер в текстуру: `IRenderAdapter`

Цель — RGBA8 цвет и собственная глубина `D32_FLOAT`. Её текстура — обычная `TextureHandle`, поэтому `ImGui::Image` и `DrawItem::texture` принимают её так же, как любую загруженную текстуру.

| Вызов | Что делает |
| --- | --- |
| `CreateRenderTarget(w, h)` | Создаёт цель (до 4096 px, до 64 штук). 0, если лимит исчерпан |
| `DestroyRenderTarget(rt)` | Освобождает цель; GPU видит её, пока не закончит работу кадра, поэтому ресурс и дескриптор возвращаются по забору (fence) |
| `GetRenderTargetTexture(rt)` | Текстура цели; содержимое не определено, пока цель не нарисована хотя бы раз |
| `BeginRenderTarget(rt, clear)` | Внутри кадра (после `BeginFrame`): переход в `RENDER_TARGET`, очистка цвета и глубины, вывод идёт в цель |
| `SetViewProjection` / `Draw` / `DrawDebugLines` | Между `Begin` и `End` работают как обычно, но пишут в цель, со своим view-projection |
| `EndRenderTarget(rt)` | Переход в `PIXEL_SHADER_RESOURCE`, вывод возвращается на поверхность кадра (viewport и scissor восстановлены) |
| `ReadRenderTargetPixels(rt, out)` | Синхронное чтение RGBA8 на CPU; вне кадра, редко (кеш на диске) |

Ограничения внутри прохода: `SetRenderRegion` и `DrawUiGeometry` игнорируются; режим Wireframe выключается на время прохода и возвращается после. Создавать и уничтожать цели нужно между кадрами.

`RenderTargetPool` (`render/RenderTargetPool.h`) — пул целей одного размера: `Acquire(w, h)` берёт свободную или создаёт новую, пока не достигнут предел; `Release` возвращает.

Заодно исправлено повторное использование дескрипторов текстур: `DestroyTexture` отдаёт слот в кучу SRV (с отсрочкой до конца работы GPU), куча увеличена с 512 до 2048.

## `editor::ThumbnailService`

```cpp
auto thumbnail = service.Request("assets/models/crate.obj", 128); // 64 / 128 / 256
if (thumbnail.ready)
{
    ImGui::Image(static_cast<ImTextureID>(thumbnail.ImGuiTextureId()), size);
}
else
{
    // иконка типа: thumbnail.kind
}
```

Порядок кадра (Application это делает сам): `Update()` между кадрами — чтение и запись кеша на диске, проверка устаревших, вытеснение; `Render(surface)` сразу после `BeginFrame`, до сцены и UI — рисует до `budgetPerFrame` (2) миниатюр; `Request()` — в любой момент, например при построении UI.

| Тип | Что рисуется |
| --- | --- |
| Текстура (`.png`, `.jpg`, `.bmp`, `.tga`) | сама текстура, без цели; `sourceWidth/Height` для пропорций |
| Материал (`*.material.json`) | сфера `assets/models/sphere.obj` с материалом |
| Меш (`.obj`) | меш с предложенным материалом (`SetMaterialSuggestion`, по умолчанию `default.material.json`), кадрирование по границам, вид 3/4 сверху |
| Префаб (`*.prefab.json`) | все меши шаблона с учётом иерархии, кадрирование по общим границам |
| Остальное | нет превью: `kind == Other`, рисуется иконка |

Пока меш или текстура догружаются (ResourceManager грузит в фоне), миниатюра остаётся заглушкой; через 1200 кадров ожидания — `Failed`.

### Кеш

- В памяти: до `maxRenderTargets` (48) целей; когда они заняты, вытесняется неиспользуемая дольше всех миниатюра (на экране — не трогается); картинки, прочитанные с диска, — до `maxCachedTextures` (192) обычных текстур.
- На диске: `<проект>/Saved/Thumbnails/<подпись>_<размер>.tga`. Подпись — хеш времён изменения и размеров файла ассета и всего, на что он ссылается (шейдер и текстура материала, меши и материалы префаба). Любое изменение даёт другое имя файла, поэтому устаревшая картинка не читается. Файлы старше 30 дней удаляются при старте. `Saved/` в `.gitignore`.
- Изменённые файлы замечаются сами (каждые 30 кадров проверяется часть миниатюр); `Invalidate(path)` / `InvalidateAll()` — принудительно.

## Проверка

- `ctest`: `thumbnail_service` — заглушка, затем картинка, бюджет, пул и вытеснение, кеш на диске (второй сервис не рисует), инвалидация по времени файла. Работает на записывающем адаптере, без GPU.
- Вручную (DX12, окно): `myengine_render_target_smoke` — треугольник в цель, текстура цели в UI-проходе, чтение пикселей, 300 созданий и уничтожений целей (слоты и дескрипторы возвращаются), пул.
- В редакторе: Help → Developer → Thumbnails — окно со счётчиками сервиса и миниатюрами ассетов проекта (или `MYENGINE_THUMBNAILS_WINDOW=1` для открытия при старте).
