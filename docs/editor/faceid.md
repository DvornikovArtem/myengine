# Вход в редактор по лицу (Face ID, F0)

При запуске редактор может попросить посмотреть в камеру: лицо узнаётся — редактор открывается, нет — остаётся пароль. Это учебная защита от случайного человека за ноутбуком, а не замок против атакующего; ограничения описаны в конце.

Всё работает локально: камера, нейросети и профили не выходят за пределы компьютера, ни одна картинка не сохраняется.

## Как это выглядит

| Ситуация | Что видно |
| --- | --- |
| Профилей нет (первый запуск) | Предложение: «Set up Face ID» (запись лица) или «Not now» (вход отключается; включить заново — `Window > Face ID`) |
| Есть профили | Экран входа: изображение камеры (зеркальное), рамка вокруг лица, строка статуса. Лицо узнано пять кадров подряд → просьба повернуть голову → редактор открывается |
| Нет камеры, камера занята, нет доступа | Дружелюбное сообщение (см. «Ошибки камеры») и кнопка «Use the password» |
| Три неудачи подряд (чужое лицо, таймаут) | Блокировка попыток на 30 с, обратный отсчёт; пароль работает всегда |
| Запись профиля | Окно с текстом согласия → имя и пароль → «Start the camera» → восемь хороших кадров с поворотами головы → «Saved» |

Игры (`--game`), автоматические прогоны (`--exit-after-frames`, `MYENGINE_UI_SCRIPT`, `MYENGINE_UI_GALLERY`) и сборка без ONNX Runtime экран входа не показывают — тесты, CI и скрытый рабочий стол работают как раньше.

Отключение: флаг `--no-faceid` или переменная окружения `MYENGINE_NO_FACEID=1`.

## Окно настроек: `Window > Face ID`

- «Ask for Face ID when the editor starts» — вход при запуске.
- «Ask to turn the head» — проверка живости (см. ниже).
- «Ask in the games too» — настройка записывается в `settings.json`, но игры её пока не читают: сам вход сделан только для редактора. Флаг подготовлен для задач FlyDoom.
- Camera — выбор камеры из списка Media Foundation.
- Threshold — порог косинусного сходства, по умолчанию 0.363 (значение из документации OpenCV для SFace).
- Faces (до трёх) — список профилей с удалением (данные стираются из файла сразу).
- Повреждённый файл профилей показывается красным сообщением и кнопкой «Erase the damaged file and start again».

## Что и где хранится

`%LOCALAPPDATA%\myengine\faceid\`:

| Файл | Содержимое |
| --- | --- |
| `profiles.bin` | до 3 профилей: имя (до 32 байт UTF-8) и 5–10 эмбеддингов по 128 чисел; хеш пароля. Весь файл зашифрован DPAPI (`CryptProtectData`, привязка к учётной записи Windows, дополнительный секрет приложения) |
| `settings.json` | настройки окна выше (без личных данных) |

- Пароль: не короче 6 символов, хранится как PBKDF2-HMAC-SHA256 (120 000 итераций, соль 16 байт, BCrypt Windows), сравнение за постоянное время.
- Эмбеддинг — 128 чисел, по которым лицо восстановить нельзя; кадры камеры живут только в памяти и пропадают при остановке камеры.
- Удаление последнего профиля перезаписывает файл нулями и удаляет его вместе с паролем.
- Файл, который не расшифровывается (другая учётная запись Windows), — это сообщение об ошибке, файл не удаляется и не перезаписывается до явного действия пользователя.
- В репозитории нет ни лиц, ни эмбеддингов, ни моделей: всё скачанное в `.gitignore`.

## Как устроено

```
FaceCamera (Media Foundation, поток) → кадр RGB
   → FaceModels::Detect  (YuNet, ONNX Runtime) → рамка + 5 точек
   → AlignFace           (подобие по 5 точкам → 112×112)
   → FaceModels::Embed   (SFace, ONNX Runtime) → 128 чисел
   → BestMatch (косинус) → RecognitionDecider (5 кадров подряд) → LivenessChallenge → вход
```

| Часть | Файлы | Что делает |
| --- | --- | --- |
| Камера | `engine/src/faceid/FaceCamera.cpp` | `IMFSourceReader`, 640×480 при 30 к/с, RGB32 через видеопроцессор ридера; свой поток; учитывает pitch и отрицательный stride (`IMF2DBuffer::Lock2D`) |
| Модели | `FaceModels.cpp` / `FaceModelsStub.cpp` | ONNX Runtime 1.20.1, CPU. YuNet 2023mar: декодирование шагов 8/16/32, NMS 0.3, вход BGR 0–255, полотно 640×640 с чёрным краем. SFace 2021dec: RGB 0–255, 112×112 → 128 чисел. Без `MYENGINE_FACEID` — заглушка |
| Выравнивание | `FaceAlign.cpp` | OpenCV не используется: подобие (поворот, один масштаб, сдвиг) методом наименьших квадратов по пяти точкам (формула Умеямы), шаблон ArcFace, билинейная выборка. Также `Sharpness` — дисперсия лапласиана, отсев смазанных кадров |
| Решения | `FaceMatcher.cpp` | `Cosine`, `BestMatch`, `RecognitionDecider`, `AttemptLimiter`, `LivenessChallenge` — чистая логика без камеры и моделей, время приходит аргументом |
| Профили | `FaceProfileStore.cpp` | файл, DPAPI, пароль, лимиты, стирание |
| Сервис | `FaceIdService.cpp` | владеет камерой, моделями, профилями; свой поток распознавания/записи; экраны берут снимок состояния `View()` |
| Экраны | `FaceIdGate.cpp` | ImGui-экраны; подключены к `UiManager` через `SetEditorGate` (до редактора, может его закрыть) и `SetEditorOverlay` (после) |

Картинка камеры показывается текстурой, которую `UiManager` пересоздаёт на каждое обновление кадра (на окно — одна текстура).

### Распознавание

- Лицо считается узнанным, когда пять кадров подряд лучшее совпадение — один и тот же профиль с косинусом не ниже порога. Один слабый кадр сбрасывает серию. Двенадцать кадров подряд без совпадения — «чужое лицо».
- Чужим считается и лицо без совпадений, и узнанное, но не прошедшее проверку поворота.

### Запись профиля

Согласие (флажок), имя, пароль (дважды), затем восемь кадров. Кадр берётся, когда в картинке ровно одно лицо шириной не меньше 120 px, голова в нужной позе (по очереди прямо и с поворотами в обе стороны; подсказка под картинкой говорит, что делать), лицо резкое (дисперсия лапласиана выровненного лица не ниже 30) и держится три кадра подряд; между кадрами не меньше 0.6 с. Запись возможна только с живой камеры — загрузить фотографию вместо камеры нельзя.

### Проверка «поверни голову» (liveness)

Просьба повернуть голову в случайную сторону; по точкам YuNet смещение носа относительно середины между глазами (`FaceDetection::Yaw`, в долях расстояния между глазами) должно измениться на 0.25, за 8 секунд. Фотография, поднесённая к камере, голову не поворачивает.

**Честно о ней:** это защита от самого простого случая — фото или экран с неподвижным снимком. Видео с поворотом, маска, 3D-модель и специальные атаки её обходят; настоящую защиту дают инфракрасные/глубинные камеры (Windows Hello). Face ID этого движка — учебная демонстрация, и пароль из профиля в любом случае остаётся запасным входом.

## Установка зависимостей

ONNX Runtime и модели в репозиторий не входят (лицензии: ONNX Runtime — MIT, YuNet — MIT, SFace — Apache 2.0; тексты кладутся в `assets/faceid/licenses/`).

```powershell
tools\faceid\fetch_models.ps1                 # ONNX Runtime 1.20.1 + YuNet + SFace, SHA-256 проверяется
tools\faceid\fetch_models.ps1 -WithTestImage  # плюс две портретные фотографии NASA (общественное достояние) для теста
```

Скрипт кладёт `external/onnxruntime/` и `assets/faceid/models/` (всё в `.gitignore`). Уже скачанный файл с правильным хешем повторно не качается.

CMake: опция `MYENGINE_FACEID` включается сама, если `external/onnxruntime/lib/onnxruntime.lib` найден; иначе сборка идёт с заглушкой моделей, а редактор запускается как раньше. В shipping-сборке Face ID нет. `onnxruntime.dll` копируется рядом с исполняемыми файлами вместе с ассетами; модели ищутся в `<папка exe>/assets/faceid/models`. Нет моделей — экран входа не показывается, причина записывается в лог (`Face ID is off: …`) и видна в `Window > Face ID`.

## Ошибки камеры

| Сообщение (начало) | Причина | Что делать |
| --- | --- | --- |
| Media Foundation did not start | не запустилась подсистема Media Foundation | перезапустить редактор; войти паролем |
| no camera found: connect one (or use the password) | камеры нет | подключить камеру, нажать Refresh в `Window > Face ID`; войти паролем |
| access to the camera is denied: … | Параметры Windows → Конфиденциальность → Камера | включить «Let desktop apps access your camera» |
| the camera cannot be opened (0x…): another program may be using it | камеру держит другая программа (Teams, браузер) | закрыть программу и повторить |
| the camera cannot be read (0x…) | драйвер открылся, но поток не читается | выбрать другую камеру; войти паролем |

При любой из ошибок экран входа сразу переходит на ввод пароля.

## Тест `faceid`

```
ctest --test-dir build -C RelWithDebInfo -R faceid
```

Без камеры и окна. Проверяет: косинус и нормализацию, `BestMatch`, `RecognitionDecider` (пять кадров, сброс серией, отказ после двенадцати, порог), `AttemptLimiter` (три неудачи → блокировка 30 с), `LivenessChallenge` (верная сторона, неверная, таймаут), выравнивание (известное преобразование восстанавливается, тождество сохраняет картинку), `Sharpness`, файл профилей (шифрование, лимиты, пароль, удаление последнего профиля, повреждённый файл, чужая защита, стирание), хеш пароля, DPAPI. Затем, если есть ONNX Runtime, модели и портреты (`-WithTestImage`), — настоящие YuNet и SFace на двух фотографиях: лицо находится, тот же человек при другом свете и размере выше порога, другой человек ниже, владелец проходит решение, чужой нет. Нет моделей или портретов — выход с кодом 77, CTest показывает тест как пропущенный.

## Что не сделано / границы

- Вход есть только в редакторе; настройка «Ask in the games too» пока ничего не включает в играх.
- Профили привязаны к учётной записи Windows (DPAPI): под другой учётной записью файл не открывается, останется стереть его и записать лицо заново.
- Порог 0.363 взят из документации OpenCV; на очках, плохом свете и маленьком лице сходство падает — тогда помогает перезапись профиля в нужных условиях или вход паролем.
- Живая проверка с камерой и запись реальных профилей — на стороне владельца компьютера: автоматические прогоны камеру не включают.
