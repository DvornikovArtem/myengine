# Вход в редактор по лицу (Face ID, F0, F1)

При запуске редактор может попросить посмотреть в камеру: лицо узнаётся — редактор открывается, нет — остаётся пароль. Это учебная защита от случайного человека за ноутбуком, а не замок против атакующего; ограничения описаны в конце.

Лица бывают **локальные** (запись на этом компьютере, F0) и **общие** (одна подписанная база для всех копий движка, F1 — раздел «Общая база лиц» ниже). Всё работает локально: камера, нейросети и профили не выходят за пределы компьютера, ни одна картинка не сохраняется.

## Как это выглядит

| Ситуация | Что видно |
| --- | --- |
| Нет ни общей базы, ни профилей (первый запуск) | Предложение: «Set up Face ID» (запись лица) или «Not now» (вход отключается; включить заново — `Window > Face ID`) |
| Есть профили | Экран входа: изображение камеры (зеркальное), рамка вокруг лица, строка статуса. Лицо узнано пять кадров подряд → просьба повернуть голову → редактор открывается |
| Нет камеры, камера занята, нет доступа | Дружелюбное сообщение (см. «Ошибки камеры») и кнопка «Use the password» |
| Три неудачи подряд (чужое лицо, таймаут) | Блокировка попыток на 30 с, обратный отсчёт; пароль работает всегда |
| Запись профиля | Окно с текстом согласия → имя и пароль → восемь кадров с поворотами головы с камеры («Start the camera») и/или лица из фотографий («Add from photos…», раздел «Лица из фотографий») → «Saved» |

Игры (`--game`), автоматические прогоны (`--exit-after-frames`, `MYENGINE_UI_SCRIPT`, `MYENGINE_UI_GALLERY`) и сборка без ONNX Runtime экран входа не показывают — тесты, CI и скрытый рабочий стол работают как раньше.

Отключение: флаг `--no-faceid` или переменная окружения `MYENGINE_NO_FACEID=1`. Файл общей базы: `--faceid-db <файл>` (переменная `MYENGINE_FACEID_DB`).

## Окно настроек: `Window > Face ID`

- Вверху — режим (Local или Shared), в Shared — путь к базе, число лиц, дата подписи, есть ли пароль; ниже — раздел «Publisher» (ключ и действия издателя, см. «Общая база лиц»).
- «Ask for Face ID when the editor starts» — вход при запуске.
- «Ask to turn the head» — проверка живости (см. ниже).
- «Ask in the games too» — настройка записывается в `settings.json`, но игры её пока не читают: сам вход сделан только для редактора. Флаг подготовлен для задач FlyDoom.
- Camera — выбор камеры из списка Media Foundation.
- Threshold — порог косинусного сходства, по умолчанию 0.363 (значение из документации OpenCV для SFace).
- Faces (до трёх) — список профилей с удалением (данные стираются из файла сразу).
- Повреждённый файл профилей показывается красным сообщением и кнопкой «Erase the damaged file and start again».

## Что и где хранится

`%LOCALAPPDATA%\myengine\faceid\`:

| Файл | Содержимое |
| --- | --- |
| `profiles.bin` | до 3 профилей: имя (до 32 байт UTF-8) и 5–10 эмбеддингов по 128 чисел; хеш пароля. Весь файл зашифрован DPAPI (`CryptProtectData`, привязка к учётной записи Windows, дополнительный секрет приложения) |
| `settings.json` | настройки окна выше (без личных данных) |
| `signing.key` | только на компьютере издателя: приватный ключ подписи общей базы под DPAPI (см. «Общая база лиц») |

- Пароль: не короче 6 символов, хранится как PBKDF2-HMAC-SHA256 (120 000 итераций, соль 16 байт, BCrypt Windows), сравнение за постоянное время.
- Эмбеддинг — 128 чисел, по которым лицо восстановить нельзя; кадры камеры живут только в памяти и пропадают при остановке камеры.
- Удаление последнего профиля перезаписывает файл нулями и удаляет его вместе с паролем.
- Файл, который не расшифровывается (другая учётная запись Windows), — это сообщение об ошибке, файл не удаляется и не перезаписывается до явного действия пользователя.
- В репозитории нет ни лиц, ни эмбеддингов, ни моделей: всё скачанное в `.gitignore`.

## Как устроено

```
FaceCamera (Media Foundation, поток) → кадр RGB
   → FaceModels::Detect  (YuNet, ONNX Runtime) → рамка + 5 точек
   → AlignFace           (подобие по 5 точкам → 112×112)
   → FaceModels::Embed   (SFace, ONNX Runtime) → 128 чисел
   → BestMatch (косинус) → RecognitionDecider (5 кадров подряд) → LivenessChallenge → вход
```

| Часть | Файлы | Что делает |
| --- | --- | --- |
| Камера | `engine/src/faceid/FaceCamera.cpp` | `IMFSourceReader`, 640×480 при 30 к/с, RGB32 через видеопроцессор ридера; свой поток; учитывает pitch и отрицательный stride (`IMF2DBuffer::Lock2D`) |
| Модели | `FaceModels.cpp` / `FaceModelsStub.cpp` | ONNX Runtime 1.20.1, CPU. YuNet 2023mar: декодирование шагов 8/16/32, NMS 0.3, вход BGR 0–255, полотно 640×640 с чёрным краем. SFace 2021dec: RGB 0–255, 112×112 → 128 чисел. Без `MYENGINE_FACEID` — заглушка |
| Выравнивание | `FaceAlign.cpp` | OpenCV не используется: подобие (поворот, один масштаб, сдвиг) методом наименьших квадратов по пяти точкам (формула Умеямы), шаблон ArcFace, билинейная выборка. Также `Sharpness` — дисперсия лапласиана, отсев смазанных кадров |
| Решения | `FaceMatcher.cpp` | `Cosine`, `BestMatch`, `RecognitionDecider`, `AttemptLimiter`, `LivenessChallenge` — чистая логика без камеры и моделей, время приходит аргументом |
| Фотографии | `FacePhotos.cpp` | файл jpg/png → одно лицо → эмбеддинг (проверки и причины отказа, раздел «Лица из фотографий»), диалог выбора файлов |
| Профили | `FaceProfileStore.cpp` | файл, DPAPI, пароль, лимиты, стирание |
| Сервис | `FaceIdService.cpp` | владеет камерой, моделями, профилями; свой поток распознавания/записи; экраны берут снимок состояния `View()` |
| Экраны | `FaceIdGate.cpp` | ImGui-экраны; подключены к `UiManager` через `SetEditorGate` (до редактора, может его закрыть) и `SetEditorOverlay` (после) |

Картинка камеры показывается текстурой, которую `UiManager` пересоздаёт на каждое обновление кадра (на окно — одна текстура).

### Распознавание

- Лицо считается узнанным, когда пять кадров подряд лучшее совпадение — один и тот же профиль с косинусом не ниже порога. Один слабый кадр сбрасывает серию. Двенадцать кадров подряд без совпадения — «чужое лицо».
- Чужим считается и лицо без совпадений, и узнанное, но не прошедшее проверку поворота.

### Запись профиля

Согласие (флажок), имя, пароль (дважды), затем восемь кадров. Кадр берётся, когда в картинке ровно одно лицо шириной не меньше 120 px, голова в нужной позе (по очереди прямо и с поворотами в обе стороны; подсказка под картинкой говорит, что делать), лицо резкое (дисперсия лапласиана выровненного лица не ниже 30) и держится три кадра подряд; между кадрами не меньше 0.6 с. Вместо камеры (или вместе с ней) лица можно взять из фотографий — раздел «Лица из фотографий» ниже.

### Проверка «поверни голову» (liveness)

Просьба повернуть голову в случайную сторону; по точкам YuNet смещение носа относительно середины между глазами (`FaceDetection::Yaw`, в долях расстояния между глазами) должно измениться на 0.25, за 8 секунд. Фотография, поднесённая к камере, голову не поворачивает.

**Честно о ней:** это защита от самого простого случая — фото или экран с неподвижным снимком. Видео с поворотом, маска, 3D-модель и специальные атаки её обходят; настоящую защиту дают инфракрасные/глубинные камеры (Windows Hello). Face ID этого движка — учебная демонстрация, и пароль из профиля в любом случае остаётся запасным входом.

### Лица из фотографий (F2)

Когда человека нет рядом с компьютером (друг, преподаватель), его лицо можно записать по фотографиям. Кнопка **Add from photos…** есть на экране «Add a face: who is this» — и при записи локального профиля (`Window > Face ID > Add a face…`), и при записи в общую базу издателя (`Record a face into the shared database…`). Согласие и имя те же, что при записи с камеры: человек на фотографиях должен быть согласен, чтобы его лицо записали.

**Как это делается.** «Add from photos…» открывает обычное окно выбора файлов (можно выбрать несколько jpg/png сразу). Каждая фотография проходит тот же путь, что и кадр камеры: YuNet ищет лицо, SFace делает эмбеддинг из 128 чисел. Фотография не копируется и нигде не сохраняется: она живёт в памяти, пока строится эмбеддинг, остаются только числа. Под кнопкой для каждого файла (по имени) написано, принят он или отклонён и почему:

| Причина отказа | Условие |
| --- | --- |
| it is not a jpg or png picture / the file cannot be read | не картинка, пустой или недоступный файл; больше 64 МБ или 120 мегапикселей |
| no face found | YuNet лица не нашёл (если фото лежит на боку — снято телефоном без учёта поворота — снимок поворачивается на 90°, 180°, 270°, и побеждает поворот с самым уверенным лицом, у которого глаза выше носа, а нос выше рта; флаг ориентации EXIF не читается) |
| N faces found | другое лицо больше четверти площади главного: на фото должен быть один человек (маленькие лица на заднем плане не мешают) |
| the face is too small | ширина лица на оригинале меньше 120 px, как и на кадре камеры |
| the head is turned too far | смещение носа (`FaceDetection::Yaw`) больше 0.55 расстояния между глазами: анфас и лёгкие повороты подходят, профиль нет |
| the face is blurred | дисперсия лапласиана выровненного лица ниже 30, как и на кадре камеры |
| the same picture as … | тот же снимок выбран дважды (косинус эмбеддингов выше 0.995) |
| this does not look like the person in the other photos | лицо не похоже на остальные (косинус ниже 0.30 с каждым; цепочка «похоже на похожее» считается): в набор попал чужой человек или лицо за стеклом шлема. Если фотографий не было раньше, человеком считается самая большая группа похожих из выбранных (при равенстве — первая), и чужой отклоняется на любом месте списка; позже выбранные фотографии сравниваются с уже принятыми |

Больше 10 фотографий в одном лице не берётся; из слишком больших снимков (длинная сторона больше 1280 px) перед поиском лица усреднением делается копия поменьше, ширина лица для проверки считается по оригиналу.

**Сколько нужно.** Профилю и лицу в базе нужно 5–10 эмбеддингов. Три-четыре принятые фотографии добираются до пяти **зеркальными** копиями: эмбеддинг считается ещё раз по отражённому слева направо снимку (то же лицо, только в зеркале; это добавляет немного разнообразия, но новых данных о человеке не даёт, поэтому лучше сразу выбрать пять фотографий и больше). Пять и больше фотографий берутся как есть. Кнопка **Save from photos** включается с трёх фотографий. Фотографии можно смешать с камерой: **Add the rest by camera** снимает недостающие лица (восемь минус число фотографий, но не меньше одного, и всего не больше десяти), сначала с поворотами головы в обе стороны, потом анфас; фотографии, добавленные до этого, входят в тот же профиль.

**Какие фотографии подходят.** Один человек, лицо шириной от 120 px, анфас или с лёгким поворотом головы (лучше две-три фотографии с поворотом и несколько прямых), хороший ровный свет, без очков с бликами, без сильных фильтров, раскрашивания и ретуши, фотографии из разных дней и разного света лучше пяти одинаковых кадров подряд. Фотографии на документы и яркие селфи с широкоугольным искажением хуже обычных портретов.

**Честно о границах.**

- По фотографии лицо в базу **запишется**, и камера потом узнает этого человека, когда он сам сядет перед ней. Но **живую проверку при входе фотография не пройдёт**: просьба повернуть голову (`LivenessChallenge`) остаётся такой же, и фото или экран с неподвижным снимком, поднесённые к камере, её по-прежнему не проходят — так что войти «по фотографии человека» нельзя, даже если его лицо записано по фото. Запись из файла и вход перед камерой — разные вещи: первая не требует человека рядом, второй требует его живого.
- Распознавание по эмбеддингам из фото чуть слабее, чем по кадрам с камеры того же человека: другая камера, свет, возраст снимка. Порог 0.363 остаётся прежним; если человека не узнают, лучше добавить кадры камеры («Add the rest by camera») или заменить фото более свежими.
- Проверка «тот же человек» в списке фотографий — защита от случайной ошибки (в папке оказался чужой снимок), не от обмана: порог мягкий (0.30): на портретах NASA разные люди набирают до 0.25, один человек в разные годы — от 0.42 и выше, и только лицо за стеклом шлема дало 0.11–0.22. Такая фотография отклоняется, и это нормально: она плохой образец.
- Человек на фотографиях должен быть согласен: чужое лицо без согласия записывать нельзя; текст согласия при записи тот же.

## Общая база лиц (F1)

Артём записывает три лица (себя, друга, преподавателя) один раз — и любой, кто получил собранный пакет движка с файлом базы, пускается в редактор теми же тремя лицами. Для этого лица лежат в одном подписанном файле `allowed_faces.fdb`; движок принимает его только если подпись сделана ключом издателя, чей публичный ключ встроен в exe.

### Два режима

| Режим | Когда | Что пускает | Запись лиц |
| --- | --- | --- | --- |
| **Shared** | `allowed_faces.fdb` найден | только лица из этой базы (локальные профили игнорируются) | на этом компьютере нельзя; только издатель, ключом |
| **Local** | базы нет | лица этого компьютера (F0, DPAPI) | как в F0 |

Режим определяется сам: есть база — Shared. База найдена, но не прошла проверку — это всё равно Shared, и вход закрыт (см. «Что проверяется»): подменой файла Local не включить. Издатель может в окне Face ID включить Local (галка «Use the local faces…», только при ключе издателя), чтобы проверить F0-поведение.

### Где ищется база

1. `--faceid-db <файл>` (или `MYENGINE_FACEID_DB`) — названный файл. Нет такого файла — Shared и ошибка «database that was named is not there», другой файл вместо него не ищется.
2. `faceid\allowed_faces.fdb` рядом с exe — так лежит в пакете.
3. `assets\faceid\allowed_faces.fdb` рядом с exe — запасное место для работы на своём компьютере (файл в `.gitignore`, в репозиторий не попадает).

### Формат и подпись

```
u32 "MEFD"  u32 версия  u32 длина тела  тело  u32 длина подписи  подпись (64 байта)
тело: число лиц; на лицо — имя (UTF-8, до 32 байт), дата YYYY-MM-DD, 5–10 эмбеддингов SFace (128 float32);
      пароль издателя (необязательно): итерации, соль, хеш PBKDF2-HMAC-SHA256; дата подписи
```

- Подпись — **ECDSA P-256 / SHA-256 через Windows CNG** (`BCrypt*`), сторонних библиотек нет. Ed25519 не выбран: готовой подписи Ed25519 в CNG нет (есть только ECDH на Curve25519), а ECDSA P-256 есть во всех Windows 10 и 11 и для этой задачи ничем не хуже. Подписываются заголовок и тело целиком, так что нельзя поменять ни версию, ни длину.
- Публичный ключ (128 hex-цифр: X и Y точки) — в `engine/include/myengine/faceid/FaceIdTrustedKey.h`. Пока там пусто, ни одна база не принимается (сообщение «This build has no key…»); на компьютере издателя до этого принимается его собственный ключ — чтобы работать до пересборки.
- Лица разбираются **только после** успешной проверки подписи; разбор проверяет каждую длину (обрезанный или лживый файл не читает за границей — проверено перебором).
- Эмбеддинги в файле **не зашифрованы**: ключ шифрования всё равно лежал бы в exe, это была бы видимость защиты. Файл защищён от **подмены**, не от **чтения**: у кого есть файл, у того есть эти 128 чисел. Восстановить по ним картинку лица на практике нельзя, но это биометрический шаблон — поэтому при записи лица в общую базу показывается согласие, и записывать можно только человека, который согласился.

### Ключ издателя

- Приватный ключ создаётся один раз кнопкой **Create the publisher key** (`Window > Face ID > Publisher`) и лежит в `%LOCALAPPDATA%\myengine\faceid\signing.key` под DPAPI. Он никогда не попадает в репозиторий, пакет и лог; второй ключ поверх первого не создаётся (всё подписанное старым ключом стало бы бесполезным).
- **Export the key** — резервная копия: файл с приватным ключом, зашифрованный AES-256-GCM под ключ из пароля (PBKDF2-HMAC-SHA256, 200 000 итераций, соль 16 байт; пароль от 8 символов; существующий файл не перезаписывается). **Import the key** — обратно (на другом компьютере или после переустановки Windows). Неверный пароль и изменённый файл дают одну и ту же ошибку (тег GCM не сошёлся); ключ в файле держите и храните пароль вне репозитория.
- Файл `signing.key` привязан к учётной записи Windows. Под другой он не открывается — тогда импорт из резервной копии.

### Как Артёму записать троих и раздать базу

1. Собрать движок (RelWithDebInfo), запустить редактор, `Window > Face ID > Publisher > Create the publisher key`.
2. **Export the key** — резервная копия в безопасное место, пароль не терять.
3. **Copy the public key**, затем в консоли: `tools\faceid\set_trusted_key.ps1 -Key <скопированное>` и пересобрать движок. Публичный ключ не секрет, заголовок можно коммитить; без этого шага чужие копии базу не примут.
4. `Record a face into the shared database …` — для каждого из троих: текст согласия (человек согласен), имя, затем камера (8 кадров, человек рядом) и/или фотографии («Add from photos…», раздел «Лица из фотографий»). Лица сначала попадают в черновик.
5. Галка «Put my password in the database» и пароль — тогда у всех один запасной вход (хеш лежит в той же подписанной базе); без галки при неработающей камере войти нельзя.
6. **Sign and save the database** — путь по умолчанию: найденная база или `faceid\allowed_faces.fdb` рядом с exe. Копия движка сразу работает в Shared.
7. Отдать файл остальным — только в пакете сборки: рядом с exe в `faceid\allowed_faces.fdb` (чтобы `package_game.ps1` брал файл, нужна правка в файлах B0, см. отчёт задачи F1; до этого — копированием вручную в папку пакета). Копия с уже выданной старой базой не узнает о новой, пока ей не отдали файл: удаление лица из базы никого не «отзывает» задним числом.

### Что в репозитории

Файл базы в git не кладётся никогда (решение Артёма: репозиторий публичный, а это биометрия друга и преподавателя): `assets/faceid/allowed_faces.fdb` и `faceid/allowed_faces.fdb` в `.gitignore`. База попадает только в пакет сборки, рядом с exe в `faceid/allowed_faces.fdb`. Сборка из исходников без файла работает в режиме Local. В git идёт публичный ключ (`FaceIdTrustedKey.h`) — он не секрет.

### Что проверяется и что видно

| Что с файлом | Результат |
| --- | --- |
| подписан ключом издателя | Shared, пускает его лица |
| изменён один байт (заголовок, лица, подпись), добавлено лицо, обрезан, мусор | «The face database is damaged or forged: …», вход закрыт |
| подписан чужим ключом | то же («signed by somebody else») |
| в сборке нет встроенного ключа | «This build has no key to check the face database with…» |
| назван `--faceid-db`, но его нет | «The face database that was named is not there», вход закрыт |

При закрытом входе экран показывает причину; пароль и камера не принимаются. На компьютере с ключом издателя на экране есть кнопка «I am the publisher: open the editor» — чтобы открыть редактор и починить базу.

### Честные границы

- Подпись защищает от «дописать своё лицо в файл» и от чужой базы, но не от того, кто правит exe (заменит встроенный ключ или условие), удалит файл базы (тогда Local, и любой запишет своё лицо), запустит `--no-faceid` или удалит модели. Это демонстрация, а не замок.
- Лицо в базе — биометрический шаблон реального человека; поэтому база не в git, поэтому согласие, поэтому удалять лицо по просьбе человека нужно из черновика и перевыпустить файл.
- Проверка поворота головы и остальные ограничения F0 остаются теми же.

## Установка зависимостей

ONNX Runtime и модели в репозиторий не входят (лицензии: ONNX Runtime — MIT, YuNet — MIT, SFace — Apache 2.0; тексты кладутся в `assets/faceid/licenses/`).

```powershell
tools\faceid\fetch_models.ps1                 # ONNX Runtime 1.20.1 + YuNet + SFace, SHA-256 проверяется
tools\faceid\fetch_models.ps1 -WithTestImage  # плюс портреты двух астронавтов NASA (общественное достояние) для тестов: assets\faceid\test\ и \photos\
```

Скрипт кладёт `external/onnxruntime/` и `assets/faceid/models/` (всё в `.gitignore`). Уже скачанный файл с правильным хешем повторно не качается.

CMake: опция `MYENGINE_FACEID` включается сама, если `external/onnxruntime/lib/onnxruntime.lib` найден; иначе сборка идёт с заглушкой моделей, а редактор запускается как раньше. В shipping-сборке Face ID нет. `onnxruntime.dll` копируется рядом с исполняемыми файлами вместе с ассетами; модели ищутся в `<папка exe>/assets/faceid/models`. Нет моделей — экран входа не показывается, причина записывается в лог (`Face ID is off: …`) и видна в `Window > Face ID`.

## Ошибки камеры

| Сообщение (начало) | Причина | Что делать |
| --- | --- | --- |
| Media Foundation did not start | не запустилась подсистема Media Foundation | перезапустить редактор; войти паролем |
| no camera found: connect one (or use the password) | камеры нет | подключить камеру, нажать Refresh в `Window > Face ID`; войти паролем |
| access to the camera is denied: … | Параметры Windows → Конфиденциальность → Камера | включить «Let desktop apps access your camera» |
| the camera cannot be opened (0x…): another program may be using it | камеру держит другая программа (Teams, браузер) | закрыть программу и повторить |
| the camera cannot be read (0x…) | драйвер открылся, но поток не читается | выбрать другую камеру; войти паролем |

При любой из ошибок экран входа сразу переходит на ввод пароля.

## Тест `faceid`

```
ctest --test-dir build -C RelWithDebInfo -R faceid
```

Без камеры и окна. Проверяет (F0): косинус и нормализацию, `BestMatch`, `RecognitionDecider` (пять кадров, сброс серией, отказ после двенадцати, порог), `AttemptLimiter` (три неудачи → блокировка 30 с), `LivenessChallenge` (верная сторона, неверная, таймаут), выравнивание (известное преобразование восстанавливается, тождество сохраняет картинку), `Sharpness`, файл профилей (шифрование, лимиты, пароль, удаление последнего профиля, повреждённый файл, чужая защита, стирание), хеш пароля, DPAPI. Затем, если есть ONNX Runtime, модели и портреты (`-WithTestImage`), — настоящие YuNet и SFace на двух фотографиях: лицо находится, тот же человек при другом свете и размере выше порога, другой человек ниже, владелец проходит решение, чужой нет. Нет моделей или портретов — выход с кодом 77, CTest показывает тест как пропущенный.

Дополнение F2 (тот же тест, нужны `-WithTestImage`): `LoadPhoto` (не картинка, нет файла, jpg читается); `ExaminePhoto` на шести портретах Армстронга (1958–1969) и пяти Олдрина — принято или отказано и почему; тот же человек на разных снимках выше порога и выше порога «чужого», разные люди ниже порога; профиль из фотографий узнаёт ещё один снимок того же человека и не узнаёт другого; зеркальное лицо — тот же человек; отказы (серая картинка, уменьшенный в 4 раза снимок, размытый, два портрета в одном кадре, снимок, лежащий на боку, увеличенный в 4 раза снимок принимается); сервис: `AddPhotos` (три снимка принято, чужой человек, тот же снимок дважды, не картинка отклонены с причинами; в пачке лицо за стеклом шлема и чужой отклоняются на любом месте списка, позже выбранные фотографии сравниваются с уже принятыми, из двух разных людей остаётся первый), `CameraFacesAfter`, `TakePhotoFaces` (три фотографии → пять лиц), профиль из фотографий записывается и узнаёт, лицо из фотографий попадает в черновик общей базы, предел в десять фотографий.

## Что не сделано / границы

- Вход есть только в редакторе; настройка «Ask in the games too» пока ничего не включает в играх. Общая база и её ключи работают так же в играх, когда они начнут читать эту настройку.
- Профили привязаны к учётной записи Windows (DPAPI): под другой учётной записью файл не открывается, останется стереть его и записать лицо заново.
- Порог 0.363 взят из документации OpenCV; на очках, плохом свете и маленьком лице сходство падает — тогда помогает перезапись профиля в нужных условиях или вход паролем.
- Живая проверка с камерой и запись реальных профилей — на стороне владельца компьютера: автоматические прогоны камеру не включают.
- Лица из фотографий проверены на портретах NASA; окно выбора файлов и экран записи с фотографиями автоматические прогоны не открывают (их проверяет владелец компьютера вместе с камерой).
